# 회사 디자인 기준 (kit-design-system)

## 0. 기준 문서부터
1. 저장소 루트의 `DESIGN.md` 또는 `docs/DESIGN_SYSTEM.md`를 먼저 읽습니다.
2. 없으면 만들고 시작합니다. 형식은 아래 1절을 따르고, 값은 지금 코드(테일윈드 설정, CSS 변수)에서 **측정**해 적습니다. 남의 브랜드 디자인 문서를 통째로 가져오지 않습니다(형식만 참고: awesome-design-md).
3. 화면 코드는 토큰 이름(`bg-surface`, `text-ink-2`)을 쓰고, 색 값(#hex)을 직접 쓰지 않습니다.

## 1. 디자인 문서에 들어갈 것
- **색 역할**: 바탕, 면, 선, 입력 선, 본문, 흐린 글자, 강조, 강조 위 글자, 위험·성공·경고. 회색은 5~7단계면 충분합니다.
- **글자**: 글꼴(한국어는 Pretendard 등), 크기 단계(예: 12·13·14·16·20·28·40), 줄 높이, 굵기.
- **간격**: 4 또는 8 기준 단계.
- **모서리·그림자·움직임**: 각각 2~3가지. 움직임은 대부분 0.3초 이내, 들어오고 나갈 때 ease-out.
- **부품**: 버튼·입력·선택·표·모달·알림 띠·빈 화면. 각 부품의 상태(기본·마우스 올림·누름·포커스·비활성·불러오는 중·오류).
- **대비**: 본문 4.5:1, 큰 글자·입력 선·포커스 링 3:1 이상. `kit-reference-match/scripts/contrast.py`로 검사할 수 있습니다.
- **브랜드별 차이**: 다짐·하이링크·워크인은 로고·대표색·말투가 다릅니다. 브랜드마다 문서를 따로 둡니다.

## 2. "AI 티" 점검표 — 하나라도 걸리면 고친다
| 걸리는 것 | 왜 문제인가 | 고치는 방향 |
|---|---|---|
| 의미 없는 보라·파랑 그라데이션 배경, 빛나는 구슬 | 생성형 기본값처럼 보임 | 브랜드 색 1개 + 중립색, 실제 사진·실제 화면 |
| 같은 모양 카드 3~4개가 한 줄로 반복 | 정보 위계가 없음 | 가장 중요한 1개를 크게, 나머지는 목록·표로 |
| 아이콘 대신 이모지, 아이콘마다 다른 굵기 | 조잡해 보임 | 한 아이콘 세트(Lucide 등), 같은 굵기 |
| 화면 가운데 정렬된 큰 제목 + 버튼 2개만 있는 첫 화면 | 어디서 본 듯함 | 실제 제품 화면·현장 사진과 구체적 문장 |
| "혁신적인", "차세대", "올인원 솔루션" 같은 빈 말 | 신뢰를 깎음 | 고객 상황 + 숫자 + 할 수 있는 일 |
| 확인 안 된 숫자·가짜 고객 로고·가짜 후기 | 법·신뢰 문제 | 실제 실적만, 없으면 빼기 |
| 영어 더미 문구, 번역투 한국어 | 한국 고객에게 어색 | 쉬운 한국어로 다시 쓰기(`kit-ko-copy`) |
| 과한 그림자·유리 효과·둥근 모서리 남발 | 싸 보임 | 문서의 2~3단계만 |
| 모든 요소에 움직임 | 산만함 | 필요한 곳에만 짧게(`emil-design-eng`) |
| 빈 화면·오류·불러오는 중 화면 없음 | 실제 사용에서 깨짐 | 상태별 화면을 만든다(`break-ui`로 극단값 시험) |

## 3. 만들고 나서 확인
1. 화면폭 3개(390·768·1440)로 실제 화면을 찍어 봅니다(노트북은 Playwright, 클라우드는 저장소 E2E 도구).
2. 빈 목록, 아주 긴 이름, 오류 응답, 느린 응답 상태를 확인합니다(`break-ui`).
3. 키보드만으로 이동해 포커스가 보이는지, 움직임 줄이기 설정을 존중하는지 확인합니다.
4. 결과는 '고친 전/후/이유' 표로 남기고, 확인 못한 것은 '확인 못함'으로 씁니다.

## 4. 레퍼런스가 있을 때
- 대표가 레퍼런스를 줬다면 `kit-reference-match`로 실제 화면을 먼저 보고 기능표를 만든 뒤, 우리 토큰으로 만듭니다.
- 레퍼런스의 로고·색·문구·이미지는 쓰지 않습니다.
