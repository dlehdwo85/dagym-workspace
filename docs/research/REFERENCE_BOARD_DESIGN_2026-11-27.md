# 레퍼런스 보드 설계 한 장 (#1178 · 대표 결정 D-25 '개발' · 2026-11-27 클라우드)

대표 요청(#1174, 11/26): 고객사별 디자인 요청 — 레퍼런스를 올리면 분석해서 비슷한 느낌으로 만든다.
대표 결정(D-25, 11/25): 개발한다. 스타일 카드 · 템플릿 합성 · 나란히 비교 · 베끼기 경고. 설계 한 장을 먼저 만든다.

이 문서는 설계입니다. 아직 만든 코드는 없습니다. 원가는 코드에 있는 단가표(`src/lib/ai/provider.ts`, 환율 1,400원)로 계산한 **어림값**입니다.

## 1. 한 줄 흐름

**올리기 → 스타일 카드(AI 분석 1회) → 우리 자산으로 만들기(템플릿 합성) → 나란히 다듬기 → 베끼기 검사 → 승인함**

| 단계 | 사람이 하는 일 | 시스템이 하는 일 | AI 원가 |
|---|---|---|---|
| ① 올리기 | 마음에 드는 게시물 사진 1~3장을 보드에 올림. 출처 메모(선택). '참고용·게시 안 함'에 체크 | 회사 자료실의 비공개 폴더 '마케팅/레퍼런스'에 저장. 공개·게시 경로에는 나가지 않음 | 0원 |
| ② 스타일 카드 | [분석] 한 번 누름 | 표준 모델이 그림을 보고 '구조·분위기'만 뽑아 카드로 저장(아래 3절) | 1장 약 27원 · 3장 약 37원 |
| ③ 만들기 | 글(주제·초안)을 고르고 [이 스타일로 만들기] | 카드 → 우리 틀(FEED_TEMPLATES 13종)과 설정값으로 바꿈. 색은 **우리 브랜드 키트 색**, 사진은 **우리 자료실 사진**으로 서버가 그림(mktCarouselDraw) | 0원(그리기) |
| ④ 나란히 다듬기 | 왼쪽 레퍼런스 · 오른쪽 우리 시안을 보며 조절 칩을 누름(글자 크게·바탕 진하게·사진 비중·목록↔제목) | 칩 = 틀 설정값 바꾸고 다시 그림. 글을 고칠 때만 글 모델 | 칩 0원 · 글 고치기 약 13원 |
| ⑤ 베끼기 검사 | 경고를 읽고 고침 | 그림·글·로고·색 네 가지 검사(아래 4절). 막힘이면 승인함에 못 올림 | 0원 |
| ⑥ 승인함 | 지금 시안 승인 흐름 그대로 | — | — |

사진이 모자라면 지금처럼 '사진 필요' 안내를 띄웁니다. AI 사진 생성은 관리자 승인과 크레딧 차감을 거칠 때만 합니다(1장 6.5크레딧 ≈ 280~455원, F4 이후 요금제 미정 회사는 생성 안 함).

## 2. 왜 '템플릿 합성'인가

- 이미지 생성 AI는 한글 글자를 자주 깨뜨립니다. 그래서 **글자가 들어가는 디자인은 우리 서버가 틀로 그립니다.**
- 레퍼런스 그림 자체는 생성 AI에 **보내지 않습니다**(그림→그림 변환을 하지 않음). 보내면 남의 그림을 그대로 닮게 만들 위험이 큽니다.
- 레퍼런스에서 가져오는 것은 **구조와 분위기**뿐입니다. 회사 공통 원칙 그대로: 남의 로고·브랜드색·문구·이미지는 쓰지 않습니다.

## 3. 스타일 카드(분석 결과, 저장되는 값)

| 항목 | 예 | 만들 때 쓰임 |
|---|---|---|
| 배치 | 큰 제목 위 + 사진 아래 2/3 · 4분할 · 번호 목록 | 가장 가까운 우리 틀 1~2개(title·list·photo_fade·grid4·statement·poster 등) |
| 글자 양 | 적음 / 보통 / 많음 | 제목 길이·목록 개수 제한 |
| 글자 크기 단계 | 제목 : 본문 = 3 : 1 | 틀 글자 크기 설정 |
| 분위기 | 어두운 바탕·고대비 / 밝은 파스텔 / 강한 원색 | **우리 브랜드 색** 안에서 진하기·대비만 맞춤 |
| 사진 쓰임 | 꽉 채움 / 일부 / 없음 · 피사체(사람·공간·화면) | 자료실 사진 고르기 조건 |
| 꾸밈 | 둥근 띠·밑줄·동그라미 강조 | 틀이 가진 꾸밈만 켬(새 꾸밈은 만들지 않음) |
| 말투 | 질문형 첫 줄 · 숫자 강조 | 글 모델에 주는 지시(사실·숫자는 브랜드 키트 재료만) |
| 보이는 글자(OCR) | 레퍼런스 속 문구 | **베끼기 검사에만** 씀. 만들기에는 넘기지 않음 |
| 로고·얼굴 있음 | 예/아니요 | 베끼기 검사·경고 |

## 4. 베끼기 검사(경고 · 막힘)

| 검사 | 방법(돈 안 듦) | 결과 |
|---|---|---|
| 그림이 너무 비슷함 | 레퍼런스와 우리 시안의 축소 그림 지문(dHash) 거리 | 거리가 아주 가까우면 **막힘** — 틀·사진을 바꿔야 올라감 |
| 문구 베낌 | 레퍼런스 보이는 글자와 우리 글의 세 글자 묶음 겹침률 · 12자 이상 같은 구간 | 겹침률이 높거나 같은 구간이 있으면 **막힘** |
| 남의 로고·이름 | 스타일 카드의 로고 있음 + 레퍼런스 속 상호가 우리 글에 나옴 | **막힘** |
| 남의 브랜드색 | 우리 시안의 주 색이 레퍼런스 주 색과 같고 우리 브랜드 키트 색이 아님 | **경고**(관리자가 이유를 적고 넘길 수 있음) |

## 5. 안전장치

- 레퍼런스는 회사 비공개 자료실에만 둡니다. 게시·공유 링크·소개 화면에는 나가지 않습니다. 기본 90일 뒤 자동 삭제(스타일 카드는 남김).
- 올릴 때 '참고용·게시 안 함' 확인을 받습니다. 사람 얼굴이 보이는 레퍼런스는 분석은 하되 그림을 시안 화면에서 흐리게 보여 줍니다.
- 분석 AI 호출은 회사 월 AI 예산과 AI 동의(사람이 누른 요청)를 그대로 따릅니다. 회사별 월 분석 횟수 상한을 둡니다(아래 결정 2).
- 다른 회사의 보드·카드는 404(다른 회사 데이터 숨김 규칙 그대로). 감사 기록: 올리기·분석·경고 넘기기.

## 6. 데이터·화면(1단계 범위)

- DB(추가형 마이그레이션 1개): `mkt_references`(회사·브랜드·자료실 파일·출처 메모·스타일 카드 jsonb·분석 시각·원가·만든 사람·지울 날), `mkt_contents.quality.reference`(어느 카드로 만들었는지·검사 결과).
- 화면: 마케팅 › 브랜드 키트 옆 **레퍼런스 보드** 탭(카드 목록) → 카드 상세(분석 결과 표 + [이 스타일로 만들기]) → 나란히 다듬기 화면(휴대폰에서는 위·아래).
- 1단계: 올리기·분석·카드·틀 합성·나란히 보기·칩 4개·베끼기 검사. 2단계: 사진 생성 연결(승인·크레딧) · 카드뉴스 여러 장 · 릴스 표지. 3단계: 영상 스타일.
- 시험: 가짜 AI 응답으로 카드 저장 · 같은 그림을 그대로 올리면 막힘 · 문구를 그대로 쓰면 막힘 · 다른 회사 404 · 요금제 미정이면 사진 생성 안 함 · 원가가 AI 사용 기록에 남음.

## 7. 원가 계산 근거(어림)

- 그림 1장(1080×1350) ≈ 입력 1,950토큰. 지시문 ≈ 1,500토큰. 카드 출력 ≈ 1,200토큰.
- 표준 모델(입력 100만 토큰당 $2 · 출력 $10): 1장 ≈ $0.019 ≈ **27원**, 3장 ≈ $0.027 ≈ **37원**.
- 최상 모델(입력 $4 · 출력 $20)이면 약 2배(1장 ≈ 53원, 3장 ≈ 75원). 빠른 모델이면 2원 안팎이지만 배치·분위기 판단이 약해 권하지 않습니다.
- 글 고치기 1회(입력 2,000 · 출력 500, 표준 모델) ≈ 13원. 틀 그리기·베끼기 검사는 AI를 쓰지 않아 0원.
- 실제 원가는 1단계를 만든 뒤 시험 10건의 AI 사용 기록으로 다시 확인합니다(지금 숫자는 확인 전).

## 8. 대표 결정 요청(만들기 전에)

1. 분석 모델: **표준(1장 약 27원, 권장)** / 최상(약 53원)
2. 회사별 월 분석 상한: 베이직 10회 · 스탠다드 30회 · 프로 100회(권장안) / 다른 숫자
3. 레퍼런스 보관: **90일 뒤 자동 삭제(권장)** / 계속 보관
4. 남의 브랜드색 경고: **경고만(관리자가 이유 적고 넘김, 권장)** / 막힘
