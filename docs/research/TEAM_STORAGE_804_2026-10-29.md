# 팀별 저장소 설계안 (#804, 2026-10-29)

대표 요청: 자료실을 '회사 전체 · 우리 팀 · 내 파일'로 나눈다. 올리면 기본은 내 팀, 업무 첨부는 그 업무의 팀으로. 기존 기밀 등급은 그대로 두고 추가 잠금으로만 쓴다.
상태: **설계안(구현 전)**. 대표가 승인하면 아래 순서로 만든다.

## 1. 지금 구조(코드 기준)

| 무엇 | 어디 | 뜻 |
|---|---|---|
| 파일 | `library_files` | 회사(tenant)·공간(space: work·sales·marketing)·폴더(글자 경로)·보안 등급(security)·업무(task_id) |
| 폴더 권한 | `library_folder_perms` | 폴더마다 역할(대표·관리자·부서장·현장 관리자·직원)별 보기·고치기·없음 |
| 폴더 보안 | `library_folder_security` | 폴더 등급 일반·내부·기밀(아래로 물려받음) |
| 조직 | `teams`(parent_id·kind) | 본사 › 사업부 › 부서 › 팀 4단(210 migration, 10/26 대표 확정) |
| 구성원 | `team_members`(is_lead) | 한 사람이 여러 팀 가능 |
| 업무의 팀 | `tasks.team_id` + `task_teams`(함께하는 부서) | |

지금은 파일이 '누구 팀 것'인지 칸이 없다. 폴더 이름과 역할 권한으로만 나눈다.

## 2. 바꿀 것

### 2-1. 칸 하나 추가(추가형 migration)
- `library_files.team_id uuid null` — 비어 있으면 **회사 전체**.
- `library_files.scope text` — `company`(회사 전체) · `team`(팀) · `mine`(내 파일). 기본 `company`(기존 파일은 그대로 보임).

### 2-2. 누가 보나(서버 `access.ts` 한 곳에서)
| 구분 | 보는 사람 |
|---|---|
| 회사 전체 | 지금과 같음(메뉴 권한·폴더 권한·보안 등급) |
| 우리 팀 | 그 팀 구성원 + 그 팀의 위 단위(부서·사업부·본사) 구성원 중 장(is_lead) + 대표·관리자 |
| 내 파일 | 올린 사람만(대표·관리자도 기본은 안 봄. 퇴사 처리 때만 대표가 넘겨받기) |
| 기밀 | 위 조건 + 기밀 열람 권한(지금 규칙 그대로, 추가 잠금) |

- 다른 팀 파일은 목록에 안 나오고, 주소로 열어도 404(다른 조직 데이터 규칙과 같게).
- AI 비서 자료 찾기(#753)·자료실 검색·업무 첨부 고르기도 같은 검사를 쓴다.

### 2-3. 올릴 때 기본값
- 자료실에서 올리기: **내 팀**(팀이 여럿이면 '주 팀' = 처음 들어간 팀, 올리기 창에서 바꿀 수 있음). 팀이 없으면 회사 전체.
- 업무 첨부 → 자료실에 남길 때: 그 업무의 `team_id`(없으면 담당자의 주 팀).
- 영업·마케팅 공간 파일: 공간 담당 팀이 정해져 있지 않으면 회사 전체(지금처럼).

### 2-4. 화면
- 자료실 왼쪽 맨 위에 탭 3개: `회사 전체` · `우리 팀`(팀이 여럿이면 고르기) · `내 파일`. 그 아래 폴더 탐색기는 지금 그대로.
- 파일 줄에 작은 표시: 팀 이름 또는 '내 파일'. 파일 메뉴에 [옮기기: 회사 전체 / 팀 / 내 파일].
- 휴대폰도 같은 탭(가로로 밀기).

## 3. 기존 파일 옮기기(대표 승인 표)
1. 클라우드가 **폴더 → 팀 대응표**를 만든다: 맨 위 폴더마다 파일 수, 올린 사람들의 팀(많은 순), 제안 팀. 예) `영업/입찰` 312개 → 제안 '영업팀'.
2. 대표(또는 관리자)가 화면에서 표를 보고 칸마다 [회사 전체로 둠 / 이 팀으로]를 고른다.
3. [적용]을 누르면 그 폴더 파일의 `scope·team_id`만 바뀐다(파일·폴더 이름은 그대로, 되돌리기 가능).
- 표에 없는(정하지 않은) 폴더는 회사 전체로 남는다. 아무것도 숨지 않는다.

## 4. 순서와 걸리는 시간(어림)
| 단계 | 내용 | 어림 |
|---|---|---|
| 1 | 칸 추가 · 서버 권한 검사(목록·열기·검색·AI 찾기·첨부 고르기) · 시험 | 1일 |
| 2 | 자료실 탭 3개 · 올리기 기본값 · 옮기기 메뉴 · 휴대폰 | 1일 |
| 3 | 폴더 → 팀 대응표 화면 · 적용·되돌리기 | 0.5일 |
| 4 | 운영 확인(로컬) · 대응표 대표 결정 · 적용 | 대표 일정에 맞춤 |

## 5. 대표가 정할 것
1. '우리 팀' 파일을 위 단위 **장만** 볼지, 위 단위 **구성원 모두** 볼지(제안: 장만).
2. '내 파일'을 대표·관리자도 볼 수 있게 할지(제안: 기본은 못 봄, 퇴사 처리 때만 넘겨받기).
3. 한 사람이 여러 팀일 때 '주 팀'을 처음 들어간 팀으로 할지, 사람마다 고르게 할지(제안: 사람마다 설정 › 내 정보에서 고름, 기본은 처음 팀).
4. 영업·마케팅 공간 파일도 팀으로 나눌지(제안: 이번에는 업무 공간만, 영업·마케팅은 회사 전체 유지).

## 6. 대표 결정(10/29 23:55, 로컬이 전달) — 구현 진행
1. '우리 팀' 파일은 **위 단위 구성원 모두**가 본다(장만이 아님). 같은 팀 구성원 + 그 팀 위 부서·사업부·본사 구성원 + 대표·관리자.
2. '내 파일' = 올린 사람만(대표·관리자도 기본은 못 봄, 퇴사 처리 때만 넘겨받기) — 설계안대로(대표 추가 답이 오면 바꿈).
3. 여러 팀이면 **주 팀 = 소속 팀 가운데 조직도에서 가장 위 단위**(사람마다 고르는 칸 없음). 같은 높이가 둘이면 먼저 들어간 팀.
4. 영업·마케팅은 나누지 않고, 업무 파일·업무 보기 규칙도 지금 그대로.

**해석(구현 범위)**: 팀 저장소는 **업무 공간 자료실에 사람이 직접 올리는 파일에만** 적용한다. 영업·마케팅 공간 파일, 업무 첨부에서 자료실로 자동 등록되는 파일(V38 4), 제작의뢰실·AI 가 만든 파일은 지금처럼 회사 전체(업무 첨부 파일은 업무를 볼 수 있는 사람). 기존 파일은 모두 회사 전체로 남고, 3절 폴더 → 팀 대응표로 옮길 때만 바뀐다.

## 7. 구현 상태(292차, 2026-10-31)
- migration `230_library_scope.sql`(추가형): `library_files.scope`(company·team·mine, 기본 company) · `team_id` · 팀·내 파일 빈 폴더 표 `library_scope_folders`. 기존 파일은 모두 company 그대로.
- 서버(`src/lib/library.ts`): 목록·열기·내려받기·검색·AI 찾기·문서 열기가 모두 같은 검사 — 팀 자료 = 그 팀과 아래 단위의 파일을 위 단위 구성원이 봄(내가 속한 팀 + 그 아래 팀), 대표·관리자는 모든 팀 · 내 파일 = 올린 사람만(대표·관리자도 404) · 기밀 등급은 그 위에 그대로. 마케팅 사진 후보(poolCond)는 회사 전체만.
- 올리기·새 문서·새 폴더·옮기기·폴더 이름 바꾸기/지우기에 범위(scope·teamId). 팀 자료는 업무 공간만, 업무 첨부 파일은 회사 전체 고정, 내 파일로는 올린 사람만 옮김, 팀 폴더 이름 바꾸기는 팀장·관리자만. 범위를 바꾸면 감사 기록(library.scope_set).
- 화면: 업무 공간 자료실에 탭 '전체 · 회사 전체 · 우리 팀 · 내 파일'(팀이 여럿이면 팀 고르기) · 파일 줄 표시(팀 이름 / 내 파일) · '올릴 곳' 고르기(탭 따라 기본) · 자료 고치기 창 '보관 범위'.
- ~~해석(292차)~~: '올리면 기본은 내 팀'을 직원에게 적용하고, 대표·관리자가 '전체' 탭에서 올릴 때는 회사 전체를 기본으로 둠(회사 양식·로고가 직원에게 안 보이는 일을 막으려고). 대표가 '대표도 팀 기본'을 원하면 한 줄로 바꿈.
- **293차 #837(대표 원문 "대표자가 올리는 자료가 기밀자료가 많을 수 있음")**: 대표·관리자도 '전체' 탭에서 올리면 기본 = 우리 팀(주 팀). 팀이 없으면 회사 전체. '회사 전체' 탭에서 올리면 회사 전체.
