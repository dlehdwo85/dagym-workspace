# 카드 등록 무료 체험 → 체험 끝나면 자동 구독 — 설계안과 작업량 (2026-10-24, 대표 질문 ④)

대표 질문: "카드 등록 무료 체험 → 체험이 끝나면 자동 구독 결제, 구현할 수 있는가?"

## 0. 결론

- **구현할 수 있다.** 이미 있는 카드 등록(빌키, 0원)·월 자동 결제·실패 재시도·읽기 전용 흐름을 그대로 쓰고,
  '체험 끝나는 날 = 첫 결제일'과 '유료 전환 동의' 단계만 더하면 된다. **작업량 약 4일**(시험 포함, 실결제 확인 별도).
- **법 때문에 결정할 것이 하나 있다.** 가입할 때 받은 동의만으로는 부족하고, 응답이 없는 것을 동의로 보면 안 된다(공정위 가이드라인 2026-10-06).
  안전하게 가려면 체험 중(전환 7일 전 ~ 1일 전)에 '유료 전환 동의'를 한 번 더 받고,
  **동의하지 않으면(응답 없음 포함) 결제하지 않고 지금처럼 읽기 전용**으로 둔다 → 아래 6번 A안·B안 중 대표 결정.
- **나이스페이 실상점**: 결제창 상점(walkin001m) 실결제는 10/23 100원 시험으로 확인됨.
  **빌링 상점(walkin002m)의 카드 등록·자동 승인은 실운영에서 확인 못함.** 운영 서버의 실결제 전환 값(NICEPAY_MODE)도 확인 못함(값은 Vercel 에만 있음).

## 1. 법 조문 확인 (원문 대조 결과)

| 항목 | 확인한 내용 | 출처 |
|---|---|---|
| 근거 | 전자상거래법 제13조 제6항 + 시행령 제20조의2, 2025.2.14 시행 | 정책브리핑(공정위 발표 기사) |
| 무엇을 | 정기결제 금액이 오르거나 **무료 → 유료로 바뀔 때 소비자 동의**를 받고, **취소·해지 조건·방법**을 알려야 함 | 정책브리핑 "증액·유료 전환 전 30일 이내에 소비자의 동의를 받고 … 취소하거나 해지하기 위한 조건·방법 등을 소비자에게 고지해야 한다" |
| 언제 | **전환 전 30일 이내** | 같은 기사 · 김앤장 해설(시행령 제20조의2 = 전환 전 30일 내) |
| 기산 예 | 5/1 한 달 무료 → 6/1 유료 전환이면 **5/2 ~ 5/31 사이**에 동의 | 법률신문(법무법인 화우 해설) |
| 가입 때 동의 | 가입 약관에 유료 전환을 넣어 둔 것만으로는 부족, **별도의 명시적 동의** 필요. "거부 의사를 밝히지 않았다는 이유만으로 동의한 것으로 간주해서도 안 된다". 별도 동의가 없으면 오른 금액이 결제되지 않게 해야 함 | 공정위 다크패턴 가이드라인(2026-10-06 배포) 보도 — ZDNet·뉴데일리 (가이드라인은 법적 구속력 없음, 법·시행령이 우선) |
| 짧은 체험 | "할인·무료체험 기간이 30일 이내인 경우에도 법정 기간 내 별도 동의가 요구됨" | 김앤장 문답서 정리(검색 요약 — **문답서 원문은 확인 못함**) |
| 제재 | 과태료 1차 100만·2차 200만·3차 이상 500만 원(법상 상한 500만 원), 영업정지 1차 3개월·2차 6개월·3차 12개월 | 정책브리핑 · 김앤장 |

해석: 우리 체험은 14일이라 **가입한 날도 '전환 전 30일 이내'**에 들어간다. 그래서 가입 때 별도 동의 한 번(B안)도
기간 조건은 맞지만, "가입 때 받은 동의는 별도 동의로 인정되기 어렵다"는 해설이 있어 다툼 소지가 있다.
가장 안전한 것은 체험 중에 '전환 확인'을 따로 한 번 더 받는 A안. **원문 문답서·법무 확인은 대표 쪽에서 한 번 해 주시길 권함.**

## 2. 흐름 (A안 기준)

1. **가입 단계에 '카드 등록' 추가** (지금 가입 4단계 중 회사 정보 다음)
   - 기존 `/api/billing/card` 그대로: 나이스페이 빌키 발급(0원), 카드번호는 저장하지 않고 끝 4자리만.
   - 가입 약관과 **따로** 체크하는 동의 문구(예시):
     > 체험이 끝나는 **{11/7}**에 **{비즈니스}** 요금제로 유료 전환됩니다.
     > 금액: **{5}명 × {6,900}원 = {34,500}원 + 부가세 = 월 {37,950}원** (인원이 바뀌면 바뀐 인원 기준).
     > 결제 수단: **{카드사} \*\*\*\*{1234}**. 전환 전에 설정 › 사용량·요금제의 **[자동 전환 끄기]**로 언제든 해지할 수 있고,
     > 체험 중에 해지하면 **0원**입니다. 전환 7일 전에 한 번 더 동의를 받으며, 동의하지 않으면 결제하지 않습니다.
   - 기록: `billing_consents` 에 kind = `trial_signup` (문구 원문·금액·전환일·카드 끝 4자리·IP·시각·약관 버전).
2. **체험 중**: 상태는 지금처럼 'trial', 고른 요금제 = `chosen_plan`, **첫 결제일 `next_billing_on` = 체험 종료일(`trial_ends_at`)**.
3. **전환 7일 전**(14일 체험이면 가입 7일째): 앱 알림 + 메일 '유료 전환 확인' → 확인 화면에서 **[전환 동의]** / **[자동 전환 끄기]**.
   - [전환 동의] = `billing_consents` kind = `trial_conversion` (전환일·전후 가격·결제 수단·해지 방법 문구 원문).
4. **3일 전·1일 전 알림**(앱 + 메일, 해지 버튼 한 번):
   - 동의한 회사: "{11/7} {37,950}원 결제 예정 — [자동 전환 끄기]"
   - 동의 안 한 회사: "동의하지 않으면 {11/7}부터 읽기 전용이 됩니다(결제 없음) — [전환 동의]"
5. **전환일**: 정기 실행이 '체험 끝 + 30일 이내 전환 동의 있음 + 동의 금액 이상 오르지 않음'이면 결제 → 유료 활성 → 다음 달부터 기존 월 자동 결제.
   - 동의가 없으면 결제 시도 안 함 → 지금처럼 읽기 전용.
   - 인원이 늘어 금액이 동의 때보다 커지면 결제하지 않고 **새 금액으로 다시 동의** 요청.
   - 플랫폼 운영에서 체험을 연장해 전환일이 동의일로부터 30일을 넘기면 **다시 동의** 요청.
6. **결제 실패**: 기존 흐름 그대로 — 지금 코드는 **첫 실패 뒤 3일·7일 재시도, 7일 미납 = 읽기 전용, 30일 = 이용 중지**.
   로컬 요청에 적힌 '1·3·5일 재시도'와 다르므로, 바꿀지 결정 필요(바꾸는 데 반나절 이하).
7. **해지**: [자동 전환 끄기] 한 번. 체험 중이면 0원, 원하면 나이스페이 빌키도 삭제.

## 3. 데이터 (DB 1개, 칸 추가만)

- `billing_consents` 에 칸 추가: `kind`(auto_renew / trial_signup / trial_conversion), `convert_on`(전환일), `seats`, `unit_krw`, `card_last4`, `cancel_text`(해지 방법 문구), `user_agent`. 기존 행은 `auto_renew`.
- `tenant_subscriptions` 는 그대로(체험 중에도 `next_billing_on`·`billing_cycle`·`chosen_plan` 을 채워 둠).

## 5. 나이스페이 실상점 상태

| 항목 | 상태 | 근거 |
|---|---|---|
| 결제창 상점 walkin001m(인증 결제·연간·추가 팩) | **실결제 확인됨** — 10/23 09:02 100원 승인, 1시간 뒤 자동 취소 | docs/handoff/LOCAL_LOG.md 10/23 |
| 빌링 상점 walkin002m(카드 등록·월 자동 결제) | **확인 못함** — 코드·환경변수 이름(NICEPAY_BILL_MID/KEY)은 준비됨, 실제 빌키 발급·승인 시험 기록 없음 | 코드 `src/lib/billing/nicepay.ts`, LOCAL_LOG |
| 운영 실결제 전환 값 NICEPAY_MODE=live | **확인 못함** — live 가 아니면 일반 회사 결제는 공개 시험 상점으로 감(실제 청구 안 됨) | Vercel 환경변수(대표만 볼 수 있음) |

- 확인 방법 제안: 플랫폼 운영 '결제 시험'에 **[실 빌링 시험]**(시험 회사에 카드 등록 0원 → 100원 승인 → 즉시 취소 → 빌키 삭제) 버튼을 추가(반나절) → 대표 카드로 1회.
- 참고: 지금 카드 등록은 카드번호·유효기간·생년월일(또는 사업자번호)·비밀번호 앞 2자리를 우리 화면에서 받아 나이스페이로 보내는 방식(우리는 저장하지 않음).
  나이스페이 쪽 화면에서 카드 인증까지 하는 '빌키 발급 결제창' 방식이 있으면 카드번호가 우리 서버를 거치지 않아 더 안전하다 — **나이스페이에 문의 필요(확인 못함)**.

## 6. 대표 결정이 필요한 것

1. **A안**(가입 때 별도 동의 + 체험 중 전환 확인 동의, 응답 없으면 결제 안 함 — 법적으로 안전, 전환율은 낮을 수 있음)
   / **B안**(가입 때 별도 명시 동의 한 번 + 3일 전·1일 전 알림·해지 버튼 — 전환율 높음, 해설상 다툼 소지)
2. 가입 때 카드 등록을 **필수**로 할지, **건너뛰기**(지금처럼 카드 없이 체험)도 둘지
3. 결제 실패 재시도: 지금 **3·7일** → 요청대로 **1·3·5일**로 바꿀지
4. 실 빌링 확인용 [실 빌링 시험] 버튼을 먼저 만들지(대표 카드 100원, 즉시 취소)
