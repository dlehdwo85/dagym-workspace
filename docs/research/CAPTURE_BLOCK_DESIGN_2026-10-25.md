# 화면 캡처·AI 도구 접근 차단 — 설계·작업량 (#570 → #236, 대표 결정 #595)

- 요청: 대표 10/24 저녁 "AI 도구·사람 모두 워크인 화면 캡처 불가하게"(#570). 로컬 10/24 1차 판단: 웹은 OS 캡처 완전 차단 불가 → 워터마크·인쇄/복사 막기·자동화 브라우저 감지, 안드로이드 앱은 차단 가능, 아이폰은 가림만.
- 대표 결정 10/25 16:30(#595): **우리 회사(내부 테넌트 `default`, 주식회사 다짐)에 가입된 직원은 캡처 가능, 외부 가입 고객사는 우리 화면·기술을 캡처할 수 없게** → 테넌트 단위 정책, 내부 테넌트 예외.
- 이 문서 = 설계와 작업량만. 구현은 4절의 대표 결정 뒤(로컬 10/24 저녁 7 지시). 비밀값·기기 식별 정보는 쓰지 않는다.

## 0. 한 줄 결론 — 막을 수 있는 것과 없는 것

| 어디서 | 실제로 막을 수 있나 | 할 수 있는 것 |
|---|---|---|
| 안드로이드 앱 | **예** | 스크린샷·화면 녹화·최근 앱 미리보기·미러링 모두 검정(OS 기능 `FLAG_SECURE`) |
| 아이폰 앱 | **아니요(공식 API 없음)** | 캡처가 찍힌 것을 **감지**해 기록·안내, 녹화·미러링 중 **가림**, 앱 전환기 가림. 스크린샷을 검게 만드는 비공식 기법은 OS 판올림마다 깨지고 심사 지적 사례가 있어 권장 안 함 |
| 웹(PC·휴대폰 브라우저) | **아니요** — 캡처 키(Win+Shift+S, Cmd+Shift+4), 휴대폰 캡처 버튼, 녹화 프로그램, 카메라로 찍기는 브라우저가 알 수 없음 | ① 이름·회사·시각 **워터마크**(유출본 출처 식별) ② 인쇄·PDF 저장 차단 ③ 창을 벗어나면 **가림** ④ **자동화 브라우저·헤드리스 감지 차단**(AI 에이전트·스크립트) ⑤ (선택) 복사·드래그·우클릭 억제 ⑥ 서버 **감사 기록** |
| "AI 도구" | 두 가지로 나뉨 | (a) 브라우저 자동화 에이전트(컴퓨터 사용형·확장형): 자동화 흔적은 감지해 차단, 확장 프로그램이 DOM 을 읽는 것은 못 막음 (b) 사람이 찍어서 AI 에 붙여넣기: 못 막음 → 워터마크로 출처 추적 + **#602 처럼 화면에 기술·원가·내부 정보를 애초에 내보내지 않기**(149차에서 이미 서버 응답에서 제거)가 실효 대책 |

정직하게: 웹에서 "캡처 불가"는 만들 수 없다. 웹은 **억제 + 출처 추적 + 자동화 차단**, 앱은 **안드로이드 실제 차단 + 아이폰 감지·가림**이 상한이다.

## 1. 정책(대표 결정 반영)

| 대상 | 캡처 정책 | 비고 |
|---|---|---|
| 내부 테넌트 `default` | **허용**(지금과 같음) | 슈퍼관리자·내부 직원 모두. 스토어 캡처·소개 자료·대표 검수 캡처가 여기서 나옴 |
| 외부 고객사 `t_…` | **차단 켬(기본)** | 플랫폼 운영 › 회사·가입 › 회사 상세에서 회사별로 끌 수 있음(사유 메모·감사 기록) |
| 체험 `demo` | 허용(권장) | 스토어 심사·소개용 계정. 4절 결정 항목 |
| 시험 서버(E2E)·개발 | 환경 변수 `CAPTURE_BLOCK=0` 이면 전부 끔 | 자동화 감지가 Playwright 를 막지 않게 |

- 판정은 서버가 한 번: `capturePolicy({ tenant, override, env })` → `'off' | 'on'`. 내부 테넌트와 `demo` 는 `off`, 외부는 `tenants.capture_block`(null = 기본 `on`) 을 따름, `CAPTURE_BLOCK=0` 이면 모두 `off`.
- 세션에 실어 화면이 쓴다: `src/app/(app)/layout.tsx` 의 `tenant: { … }` 에 `captureBlock: boolean` 추가. 로그인 API(`/api/auth/me`)에도 같은 값(앱이 네이티브에 넘길 때 씀).
- `src/lib/customerScope.ts`(149차) 옆에 두어 "내부 테넌트 예외" 기준(`INTERNAL_TENANT`)을 한 곳에서 쓴다.

## 2. 층별 설계

### 2-1 서버(공통) — 클라우드
- DB: `tenants.capture_block boolean` (null = 기본 규칙) — 마이그레이션 **201** 추가형.
- 플랫폼 운영 › 회사·가입 › 회사 상세에 '화면 캡처 차단' 스위치(기본 켬) + 끌 때 사유 한 줄 → `PUT /api/platform/tenants/[tenant]/capture` (`src/app/api/platform/tenants/[tenant]/` 에 `capture/route.ts` 추가, 슈퍼관리자만, `audit()` 기록 `tenant.capture_block`).
- 감사 기록 API `POST /api/security/capture-events` — 화면이 감지한 사건만: 종류(인쇄 시도·자동화 감지·아이폰 캡처 감지·녹화 감지), 화면 주소(경로만, 쿼리 제외), 시각, 사용자. **화면 내용·기기 식별값은 저장하지 않는다.** 회사 관리자 '관리 › 보안 기록' + 플랫폼 운영 '오늘 볼 것'에 건수. 같은 사용자·같은 종류는 10분에 1건만(도배 방지).
- 로그인 API: 외부 테넌트 계정이 봇·헤드리스 User-Agent(HeadlessChrome·python-requests·curl·bot 등)로 로그인하면 거부(401 + '자동화된 접속은 쓸 수 없습니다'). 내부 테넌트·`CAPTURE_BLOCK=0` 은 제외.

### 2-2 웹(브라우저) — 클라우드, `CaptureGuard` 클라이언트 컴포넌트 1개를 `AppShell` 에 마운트
정책 `on` 인 세션에서만 켜진다. 내부 테넌트는 아무것도 안 바뀐다.

| 단계 | 하는 일 | 구현 | 우회 가능성 |
|---|---|---|---|
| A 워터마크 | 화면 전체에 사선으로 반복된 '회사 이름 · 사용자 이름 · 10/25 14:03' 글자(연한 회색, 6% 불투명) — 캡처본·녹화본에 남아 유출 출처 식별 | 고정 레이어 `pointer-events:none`, `aria-hidden`, 휴대폰은 글자 작게. 인쇄에도 포함 | 그림 편집으로 지울 수 있으나 흔적·시간이 든다 |
| B 인쇄·PDF 저장 | 인쇄 시 본문 대신 "이 화면은 인쇄할 수 없습니다" 한 장 | `@media print` 에서 정책 켜진 때만 본문 숨김(기존 QR 인쇄 `.print-area` 예외는 내부 테넌트·정책 꺼짐만), `beforeprint` 안내, Ctrl/Cmd+P·Cmd+S 가로채기 | 캡처키로는 못 막음 |
| C 창 이탈 가림 | 탭·창을 벗어나거나(blur·visibilitychange) 휴대폰 브라우저 앱 전환 때 본문을 흐리게(blur 8px) + "눌러서 다시 보기" | 전환기 미리보기·녹화 프로그램 전환 순간 노출 줄임 | 보고 있는 동안의 캡처는 못 막음 |
| D 자동화·헤드리스 감지 | `navigator.webdriver`, 헤드리스 UA, 플러그인·언어·화면 크기 비정상, CDP 흔적, 스크립트 주입 흔적 → 화면 대신 "자동화된 브라우저에서는 쓸 수 없습니다" + 감사 기록 | 로그인 직후·화면 전환마다 가벼운 검사(수 ms). 시험 환경은 `CAPTURE_BLOCK=0` | 위장 자동화(stealth) 는 감지 못 할 수 있음 — '기록'이 목적 |
| E (선택·'강함') 복사·드래그·우클릭 | 본문 `user-select:none`, copy/cut·contextmenu·dragstart 차단(입력 칸·편집기·메신저 입력은 제외) | 정책 강도 2단계 중 '강함'에서만 | 개발자 도구로 우회 가능, **정상 업무(설명 복사·주소 복사) 불편** → 4절 결정 |
| F 개발자 도구·확장 | 막지 않음(우회 쉽고 오탐 큼). AI 확장이 DOM 을 읽는 것은 못 막음 | — | 대책은 #602 '애초에 내보내지 않기' |

- 못 막는 것(정직하게 안내문에도): OS 캡처키·휴대폰 캡처·카메라 촬영·녹화 프로그램·확장 프로그램. 워터마크 + 감사 기록으로 '누가 언제 찍었나'를 좁히는 것이 현실적 상한.
- 고객 안내 문구(정책 켜진 회사 첫 로그인 1회): "이 서비스 화면에는 이용자 식별 워터마크가 표시되며, 인쇄·자동화 접속이 제한됩니다." — 이용약관 보안 조항과 맞춤(#282 약관에 한 줄 추가 필요, 로컬 확인).

### 2-3 안드로이드 앱 — 실제 차단(로컬: 네이티브 설정 담당)
- `WorkinNativePlugin` 에 `setSecureScreen({ on })` 추가(caps `android-secure-1`): `MainActivity` 창에 `WindowManager.LayoutParams.FLAG_SECURE` 켜고 끔 → 스크린샷·화면 녹화·최근 앱 미리보기·Cast 미러링 모두 검정.
- 웹 쪽(클라우드): 로그인 뒤 세션 `captureBlock` 을 `WorkinNative.setSecureScreen` 으로 전달, 로그아웃·내부 테넌트는 끔. 옛 앱(1.1.2 이하)은 플러그인이 없어 웹 억제만.
- 전체화면 알람 액티비티(AlarmActivity)는 별도 창이라 영향 없음.
- 부작용: 회의 중 화면 공유·캐스트가 막힘(고객 불만 가능) → 회사별 끄기 스위치로 대응. 접근성 화면 읽기(TalkBack)는 영향 없음.

### 2-4 아이폰 앱 — 감지·가림(로컬)
- ① 캡처 감지 `UIApplication.userDidTakeScreenshotNotification` → 웹으로 이벤트 → 감사 기록 + 화면 안내 "캡처가 기록되었습니다".
- ② 녹화·미러링 감지 `UIScreen.capturedDidChangeNotification` → 검정 가림 뷰 "녹화·미러링 중에는 볼 수 없습니다".
- ③ 앱 전환기 가림: `sceneWillResignActive` 에 블러 뷰, `sceneDidBecomeActive` 에 제거.
- ④ 스크린샷 자체를 검게 만드는 비공식 기법(보안 텍스트 필드 레이어 트릭)은 **권장 안 함** — 4절 결정 항목.

## 5. 시험 계획
- API: `capturePolicy` 판정(내부 off·외부 on·`capture_block=false` override·`demo` off·`CAPTURE_BLOCK=0` off), 플랫폼 스위치는 슈퍼관리자만(404), 감사 기록 10분 1건, 봇 UA 로그인 거부(외부만).
- E2E: 외부 테넌트 로그인 → 워터마크 레이어(`data-testid="capture-watermark"`)·인쇄 CSS·창 이탈 가림 확인, 내부 테넌트 → 레이어 없음. 자동화 감지는 시험 서버에서 `CAPTURE_BLOCK=0` 으로 끄고 판정 함수는 단위 시험(가짜 navigator)으로.
- 실기기(로컬): 안드로이드 캡처 → 검정, 화면 공유 → 검정, 끄기 스위치 → 정상 / 아이폰 캡처 → 기록·안내, 녹화 → 가림.
