# 워크인 화상회의 설계 (결정 15-37 · 2026-10-28 클라우드)

요청: 로컬 10/28 02:45 — 대표 10/27 "줌뿐 아니라 구글 미트 등 다른 화상채팅도 레퍼런스, 엔진은 클로드 코드가 직접 개발해 워크인에 도입".
바탕 자료: `docs/reference/zoom/`(줌 기능 34개, 필수 15) · `docs/reference/video/`(미트·팀즈·웨어바이·지트시·네이버웍스 42개, 필수 3 · `engine_plan.md` 현실안·비용·기간·위험).

## 0. 결론 먼저

- **영상·음성 처리는 브라우저 안에 이미 있는 것(WebRTC)**, **영상 중계 서버는 공개 소스를 서울에서 직접 운영**(라이브킷 추천 — 미디어수프로 바꿔 끼울 수 있게 '엔진 어댑터'로 감쌈), **회의 규칙·화면·기록·회의 뒤 정리는 100% 워크인 코드**.
- 이번에 먼저 만드는 것 = **엔진과 상관없는 부분**: 회의 자료 표 · 입장권 API(엔진 어댑터 뒤) · 권한 · 일정 [화상회의 켜기] · 손님 이름 입장 · 대기실 · 직원 입장 전 대기 · 호스트 도구 · 회의 기록(입장·퇴장·시간) · 회의 뒤 기존 회의록 → [업무로 만들기] 연결. 모두 **기능 스위치 `FEATURE_MEETINGS`(기본 꺼짐)** 뒤에 두고, **가짜 엔진(`MEETING_ENGINE=fake`)으로 시험**한다.
- 하지 않는 것(대표 결정 뒤): 서버 임대·유료 계정·실제 녹화·음성 인식 호출. 실제 영상이 오가는 '0단계 시험대'는 대표 결정 ①②(아래 9장) 뒤.
- 줌·마이크로소프트 로고·색·아이콘·화면 디자인·문구는 쓰지 않는다(약관). 화면은 `docs/DESIGN_SYSTEM.md` 기준으로 새로 그린다.

## 1. 구조

```
[직원 브라우저·앱 웹뷰]                      [손님 브라우저 — 계정 없음]
        │  ① 워크인 로그인 세션                     │  ① 회의 주소(/meet/<code>) + 이름
        ▼                                           ▼
[워크인 (Vercel) — 회의 규칙]  ───── 입장권(서명 토큰, 10분) ─────►  각 참가자
  · meetings / meeting_participants / meeting_log (Neon)
  · 권한(access.ts 규칙) · 대기실 · 호스트 도구 · 회의 기록 · 회의 뒤 정리
  · 엔진 어댑터(src/lib/meetings/engine.ts): livekit | mediasoup | fake
        ▲   ③ 엔진 알림(입장·퇴장·회의 끝) — 서명 확인 뒤 기록
        │
[영상 중계 서버(SFU) — 서울, 우리가 운영]  ◄── ② 참가자가 입장권으로 직접 접속(영상·음성은 워크인을 지나가지 않음)
  · 라이브킷(내장 방화벽 통과 TURN 443) — 0단계 시험대에서 설치(대표 결정 뒤)
```

- Vercel 에는 영상 서버를 올릴 수 없다(오래 켜진 UDP 연결 불가 — `engine_plan.md` 2장). 워크인은 **입장권 발급·회의 규칙·기록**만.
- 영상은 워크인을 지나가지 않는다 → 워크인 장애가 이미 시작된 회의를 끊지 않는다(입장권 재발급만 영향).

## 2. 자료 구조 (마이그레이션 `217_meetings.sql`, 추가형)

### meetings — 회의 1건(일정 1건·방 1개·즉석 1번)
| 칸 | 뜻 |
|---|---|
| id uuid | |
| tenant text | 회사(다른 회사 = 404) |
| code text unique | 회의 주소용 무작위 문자열(22자, 추측 불가) — `/meet/<code>` |
| kind | `event`(일정) · `room`(메시지방 즉석 통화) · `instant`(바로 회의) · `personal`(내 고정 회의실) |
| event_id uuid · room_id uuid | 연결된 일정(반복 일정은 마스터 = 같은 주소) · 메시지방 |

| host_id uuid | 주최자(일정 만든 사람) |
| status | `open`(아직 아무도 없음) · `live`(직원 1명 이상 들어옴) · `ended` |
| lobby | 대기실 정책: `guests`(기본 — 손님만 대기) · `everyone`(호스트 말고 모두 대기) · `invited`(일정 참석자·초대받은 사람 말고 대기) · `none` |
| staff_first bool | 기본 켬 — 직원이 한 명도 없으면 손님은 들어올 수 없음(팀즈 기본값·네이버웍스와 같음) |

| share | 화면 공유: `all` · `host`(호스트·공동 호스트만) |
| engine text · engine_room text | 쓴 엔진·엔진 안의 방 이름(회의 id) |
| started_at · ended_at · expires_at | 시작·끝·주소 유효기간(안 쓰면 90일 뒤 만료, 쓰면 연장 — 네이버웍스 방식) |
| created_by · created_at · updated_at | |

## 3. 권한 (서버 `src/lib/meetings/access.ts`, 규칙은 `src/lib/access.ts` 와 같은 방식)

| 누가 | 무엇을 | 규칙 |
|---|---|---|
| 다른 회사 사람·로그인 안 한 사람(회의 주소 모름) | 아무것도 | **404**(있는지조차 숨김) |
| 같은 회사 직원 | 일정 회의 | 그 일정을 볼 수 있는 사람(`loadEvent` 의 view — 비공개 일정은 참석자·만든 사람만) → `member`. 일정 편집 권한자 → `cohost` 후보 |
| 같은 회사 직원 | 메시지방 통화 | 그 방 멤버(`loadRoom`) |
| 같은 회사 직원 | 즉석·내 고정 회의실 | 주소를 받은 같은 회사 직원 → `member`(대기실 정책을 따름) |
| 손님(계정 없음) | 회의 주소를 아는 회의 1개 | 이름만 받고 `guest` + `waiting` → 호스트 허락 뒤 입장권. **그 회의의 참가자 이름·회의 채팅 말고는 회사 자료 접근 없음** |
| 호스트·공동 호스트 | 호스트 도구 | 일정 만든 사람(또는 즉석 회의 만든 사람) = host, host 가 지정한 사람 = cohost |
| 플랫폼 관리자 | 다른 회사 회의 | 내용 접근 없음(건수만 — 요금제 한도용) |

- 손님 공개 API(`/api/meet/<code>…`)는 **회사 이름·회의 이름·상태만** 돌려준다(참석자 메일·일정 내용 없음). 같은 주소로 1분에 손님 요청 20번까지(무차별 대입 방지).
- 내보낸 손님(`removed`)은 같은 비밀값으로 다시 들어올 수 없다. 새 이름으로 다시 요청하면 다시 대기실.

## 4. 입장권(토큰) API

| 길 | 누가 | 하는 일 |
|---|---|---|
| `POST /api/meetings` | 직원 | 즉석·내 고정 회의실·메시지방 통화 만들기 → `{ id, code, url }` |
| `GET /api/meetings/:id` · `PATCH` | 직원(권한) · 호스트 | 회의 정보·설정(대기실 정책·잠금·화면 공유·공동 호스트) |
| `POST /api/meetings/:id/join` | 직원 | 대기실 정책 판단 → `{ state: 'waiting' }` 또는 `{ state: 'admitted', engine, url, token, expiresIn }` |
| `GET /api/meetings/:id/lobby` · `POST …/lobby` | 호스트 | 대기 목록 · `admit` / `deny` / `admitAll` |
| `POST /api/meetings/:id/participants/:pid` | 호스트 | `remove`(재입장 금지) · `cohost` · `mute`(엔진) |
| `POST /api/meetings/:id/end` | 호스트 | 회의 끝내기(엔진 방 닫기 → 모두 나감) |
| `GET /api/meet/:code` | 누구나(주소를 아는 사람) | 회사 이름·회의 이름·상태(시작 전/진행 중/끝남)만 |
| `POST /api/meet/:code/guest` | 손님 | `{ name }` → `{ participantId, secret, state: 'waiting' }`(비밀값은 이때 한 번만) |
| `GET /api/meet/:code/guest/:pid` | 손님(헤더 `x-guest-secret`) | 대기 상태 → 허락되면 입장권(직원이 아직 없으면 '주최 측이 들어오면 시작합니다') |
| `POST /api/meetings/engine-hook` | 엔진 | 서명 확인(어댑터) → 입장·퇴장·회의 끝 → 회의 기록 |

- 입장권 = 엔진이 확인하는 **서명 토큰**(라이브킷이면 HS256 JWT, `video` 권한: 방 이름·발행(마이크·카메라)·구독·데이터·화면 공유(회의 `share` 정책)·방 관리(호스트만)). **유효 10분**(입장할 때만 씀 — 회의 중 끊기면 다시 발급), 참가자 id 가 이름표.
- 입장권을 줄 때마다 `meeting_log` 에 남긴다(누가 언제 받았나).

## 5. 엔진 어댑터 (`src/lib/meetings/engine.ts`)

```ts
interface MeetingEngine {
  id: 'livekit' | 'mediasoup' | 'fake';
  /** 브라우저가 접속할 주소와 입장권 */
  issue(p: { room: string; identity: string; name: string; role: 'host'|'cohost'|'member'|'guest'; canShare: boolean; ttlSec: number }): Promise<{ url: string; token: string }>;
  remove(room: string, identity: string): Promise<void>;   // 내보내기
  muteAll(room: string, exceptIdentity?: string): Promise<void>;
  end(room: string): Promise<void>;                         // 방 닫기 → 모두 나감
  /** 엔진 알림 → 공통 사건(서명이 틀리면 throw) */
  hook(req: Request): Promise<{ kind: 'join'|'leave'|'end'; room: string; identity?: string; at: Date }[]>;
}
```

- 고르는 법: 환경변수 `MEETING_ENGINE`(`fake` · `livekit` · `mediasoup`). 비어 있으면 회의 화면은 '영상 연결 준비 중'만 보이고 입장권 API 는 503.
- `fake`: 시험용 — 받은 호출을 기억하고, 입장권은 `fake.<참가자 정보>` 글자. 화면 시험·서버 시험은 이걸로(**'구조 시험 통과, 실제 연동 미확인'**으로 보고).
- `livekit`: 입장권은 라이브킷 공개 규격의 JWT 를 워크인 서버에서 직접 서명(외부 호출 없음). 내보내기·음소거·방 닫기는 라이브킷 방 관리 API(HTTP) — **0단계 시험대에서 실제 서버로 확인**하기 전까지 '확인 못함'.
- `mediasoup`: 연결 안내(시그널링) 서버를 우리가 따로 만들어야 함(+6~10주, `engine_plan.md` 3장) — 어댑터 자리만.
- 엔진 키 이름(값은 대표가 Vercel 에): `MEETING_ENGINE` · `LIVEKIT_URL` · `LIVEKIT_API_KEY` · `LIVEKIT_API_SECRET`.

## 6. 흐름

### 6-1. 일정 [화상회의 켜기] (184차 '회의 주소' 칸과 연결)
- 일정 만들기·고치기 창의 '회의 주소' 칸 옆 **[워크인 화상회의]** 켜기 → 회의 1건(`kind=event`) 만들고 `events.meeting_url` 에 `https://…/meet/<code>` 를 넣음 → 지금 있는 일정 화면·알림·초대·캘린더 내보내기(ICS)가 그대로 그 주소를 보여 준다.
- 끄면 회의를 닫고(`ended`) 회의 주소 칸을 비움 — 줌·구글 미트 주소를 직접 붙여 넣는 길은 그대로.
- 반복 일정은 마스터 일정에 회의 1건 = 매 회차 같은 주소. 회의 기록은 회차(시작 시각)별로 나눠 보여 줌.
- 참석자 알림·외부 손님 초대 메일은 지금의 일정 알림·메일 기능을 그대로 쓴다(주소만 바뀜).

### 6-2. 손님 이름 입장·대기실·직원 입장 전 대기
1. 손님이 `/meet/<code>` → 회사 이름·회의 이름 · **이름 입력** · 카메라·마이크 미리보기(브라우저 기능, 엔진과 무관) → [참가 요청].
2. 대기 화면(3초마다 상태 확인): '주최 측이 허락하면 들어갑니다' · 직원이 아직 없으면 '주최 측이 들어오면 시작합니다'.
3. 호스트·공동 호스트 화면에 '대기 중 n명' 띠 + 알림(앱 푸시) → [허락]·[거절]·[모두 허락].
4. 허락되면 손님 화면이 입장권을 받아 회의 화면으로.
- 직원은 대기실 정책이 `guests`(기본)면 바로 입장. `everyone` 이면 호스트 말고 모두 대기.
- 회의 잠금이면 새 입장 요청 자체를 받지 않음('회의가 잠겨 있습니다').

### 6-3. 호스트 도구
허락·거절·모두 허락 · 내보내기(재입장 금지) · 회의 잠금 · 전체 음소거(엔진) · 화면 공유 허용(모두/호스트만) · 공동 호스트 지정 · 회의 끝내기. 모두 `meeting_log` 에 남김.

### 6-4. 회의 기록
- 엔진 알림(입장·퇴장)이 기준, 브라우저도 30초마다 '아직 있음'을 보내 알림이 빠져도 퇴장 시각을 추정(마지막 신호 + 30초).
- 일정 상세에 '회의 기록: 시작 10:02 · 42분 · 직원 3 · 손님 2' + 사람별 들어온 시각·나간 시각·시간.
- 손님 이름은 그 일정을 볼 수 있는 직원에게만 보임.

### 6-5. 회의 뒤 정리 → [업무로 만들기]
- 지금 있는 일정 회의록(`event_minutes`, V30 ⑥ — 녹음 → AI 요약·결정 사항·할 일 → [업무로 만들기])을 그대로 쓴다. 회의가 끝나면 그 일정 상세에 '회의록 만들기' 안내를 띄움(지금은 녹음 파일 올리기 길).

## 7. 기능 스위치·한도
- `FEATURE_MEETINGS=1` 일 때만: 회의 API(꺼지면 404) · 일정 창 [워크인 화상회의] · `/meet/<code>` 화면. 기본 꺼짐.
