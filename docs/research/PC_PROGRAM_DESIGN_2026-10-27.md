# PC 전용 프로그램(설치형) — 설계·작업량 (결정 15-31 · #669 · #691)

작성 2026-10-27 클라우드. 앞선 견적은 [CAPTURE_BLOCK_DESIGN_2026-10-25.md §7](CAPTURE_BLOCK_DESIGN_2026-10-25.md) — 이 문서가 그 견적과 서명 비용을 갱신한다.
대표 결정 15-31(10/26 14:20): PC 전용 프로그램 진행, 윈도 서명 인증서(연 30~50만 원)는 결제 전 승인. #691(16:40): 연 30만 원이 안 들게 → 마이크로소프트 스토어(MSIX) 배포.

## 0. 한 줄 결론

- 같은 워크인을 주소창 없는 전용 창에 담은 설치형 프로그램(Electron)이다. 화면·기능은 지금처럼 서버에서 바로 바뀌고, 프로그램은 '창'만 맡는다.
- 윈도는 **마이크로소프트 스토어(MSIX 꾸러미)** 로 낸다. 마이크로소프트가 서명해 주므로 '알 수 없는 게시자' 경고가 없고, 인증서·등록비 모두 0원이다(회사 개발자 계정 2026-05-07부터 무료).
- 맥은 기존 애플 개발자 계정으로 서명·공증해 www 내려받기 페이지에서 준다(추가 비용 0원).
- 작업량: 클라우드 5~5.5일 + 로컬·대표 1.5~2일(스토어 계정·제출·맥 서명·실제 PC 시험) + 스토어 심사 대기.
- 화면 보호: 윈도 10(2004판) 이상은 캡처·녹화·화면 공유에서 창이 빠진다(원격 접속 프로그램 포함). 맥은 새 캡처 방식(ScreenCaptureKit)을 쓰는 앱에는 찍힌다 → 맥은 '부분'. 휴대폰 카메라 촬영은 못 막는다.

## 1. 확인한 사실

| 사실 | 출처 |

| 스토어 밖 배포용 OV 인증서 연 $150~300 + 하드웨어 보안 토큰 필수 · EV 는 2024년부터 경고 바로 통과 혜택 없음 | 같은 문서 |

| `setLoginItemSettings`(자동 실행)는 문서에 MSIX 언급 없음 · 맥은 서명·공증된 앱에서만 확실 | Electron 문서 app |
| 애플 Developer ID 인증서는 계정 소유자(Account Holder)만 만들 수 있음 | Apple Account Help |

우리 코드에서 확인한 것:
- 캡처 정책은 서버가 한 번 판정한다(`src/lib/capturePolicy.ts`): 우리 회사·체험·슈퍼관리자는 허용, 외부 고객사는 기본 차단(플랫폼 운영에서 회사별로 끔).
- 웹은 `CaptureGuard` 가 워터마크·인쇄 차단·창 이탈 흐림·기록을 하고, 안드로이드 앱 화면 잠금은 `native.ts setSecureScreen` 하나로 부른다 → PC 프로그램도 같은 자리에 붙이면 된다.
- 휴대폰 앱의 소셜 로그인 길이 이미 있다: 시스템 브라우저에서 로그인 → `/auth/app-return` → `workos://open/auth/app?t=…` → 앱이 `/api/auth/oauth/app-exchange` 로 1회용 표를 바꿔 세션.
- 웹은 2분마다 알림을 확인하지만 **가려진 탭이면 확인을 쉰다**(10/21 DB 쿼터 장애 뒤, `AppShell.tsx`). 트레이에 숨은 프로그램은 따로 가볍게 확인해야 한다.

## 2. 직원이 보는 것

- 바탕화면·시작 메뉴의 '워크인' → 주소창 없는 전용 창, 로그인 유지.
- 회사 정책이 '캡처 차단'이면 창이 캡처·녹화·화면 공유에서 빠진다(윈도). 우리 회사·체험·슈퍼관리자는 예외 — 서버 판정 그대로.
- 창을 닫아도 작업 표시줄 오른쪽(트레이)에 남아 새 업무·메시지·알람을 윈도 알림으로 띄우고, 작업 표시줄 아이콘에 안 읽은 수.
- 윈도를 켜면 자동으로 열림(끌 수 있음).
- 구글·카카오·네이버 로그인은 기본 브라우저에서 하고 프로그램으로 돌아옴(휴대폰 앱과 같은 길).
- 업데이트: 화면·기능은 서버 배포로 바로. 프로그램 껍데기는 스토어가 자동 업데이트(바뀔 일이 드묾).

## 3. 구조

### 3-1 껍데기 (`desktop/` 폴더, Electron)
- 한 번만 실행(두 번째 실행은 열린 창을 앞으로), 창 하나, 안전 설정(contextIsolation·sandbox, Node 끔).
- 시작 주소는 서버 설정에서 받는다(`GET /api/public/desktop-config` → 지금 `https://www.work-in.dev`, 주소 분리(15-29)를 켜면 `https://app.work-in.dev`). 주소가 바뀌어도 껍데기를 다시 내지 않는다.
- 우리 주소만 창 안에서, 그 밖 링크·새 창은 기본 브라우저로.
- 사용자 에이전트 끝에 `WorkInDesktop/<판>` — 로그인 기기 목록에 '워크인 PC 프로그램'(지금 `uaLabel.ts` 의 `WorkInApp` 과 같은 방식).
- 웹에 주는 작은 창구(preload): `window.workinDesktop = { version, setContentProtection(on), notify({ title, body, url }), setBadge(n), openExternal(url) }`.
- 첨부 내려받기는 저장 위치를 묻고, 인쇄는 차단 정책일 때 메뉴·Ctrl+P 모두 막음(웹과 같음).

### 3-2 화면 보호
- `native.ts setSecureScreen(on)` 이 `workinDesktop` 이 있으면 `setContentProtection(on)` 도 부른다 — 정책 판정·켜고 끄기는 지금 웹·안드로이드와 한 곳.
- 새로 여는 창(첨부 미리보기 등)도 같은 값.
- 보호가 켜진 PC 프로그램에서는 웹의 '창 이탈 흐림'을 끈다(다른 창으로 옮길 때마다 흐려지는 불편 — OS 가 캡처에서 빼므로 필요 없음). 워터마크·인쇄 차단·기록은 그대로(휴대폰 촬영 추적용).
- 처음 켤 때 '보호 켜짐(PC 프로그램 판)'을 서버 기록에 남긴다.

### 3-3 로그인
- 이메일·비밀번호·2단계 인증은 창 안에서 그대로.
- 소셜 로그인: 구글은 프로그램 안 내장 브라우저 로그인을 막으므로 휴대폰 앱과 같은 길(시스템 브라우저 → `workos://open/auth/app?t=…` → 1회용 표 교환).
- `workos://` 등록: 윈도 MSIX 매니페스트 주소 형식 선언, 맥 Info.plist. 윈도는 두 번째 실행 인자로, 맥은 open-url 사건으로 받는다.

### 3-4 알림·트레이·배지
- 창이 보이는 동안은 웹의 기존 확인(2분)을 그대로 쓰고, 트레이에 숨은 동안만 껍데기가 2분마다 새 서버 길 `GET /api/notifications/desktop?after=<마지막 번호>`(새 알림의 제목·내용·주소만, 색인 쿼리 1개)를 부른다 — DB 부담은 탭 하나와 같거나 적음.
- 윈도·맥 알림 센터 알림 → 누르면 창을 열고 그 화면으로. 업무 알람은 알림 + 창을 앞으로(전체 화면 알람은 휴대폰만).
- 안 읽은 수: 윈도 작업 표시줄 아이콘 겹침 그림, 맥 Dock 배지.
- 트레이 메뉴: 열기 · 알림 1시간 끄기 · 로그아웃 · 종료.
- 웹 푸시(서비스 워커)가 Electron 에서 되는지는 문서로 확인 못함 → 기대지 않는다.

### 3-5 자동 실행
- 윈도(MSIX): 매니페스트의 '시작 작업(StartupTask)' 선언 — 직원은 설정 › 앱 › 시작 프로그램에서 끔. 처음 한 번 실행한 뒤부터 동작하는지는 실제 PC 시험으로 확인.
- 맥: 로그인 항목(openAtLogin) — 서명·공증된 판에서만 확실.

### 3-6 '직원은 PC 프로그램에서만' (결정 ⓑ, 회사 설정, 기본 꺼짐)
- 켜면 그 회사 직원(관리자·슈퍼관리자 예외)이 일반 브라우저로 로그인했을 때 '워크인 PC 프로그램에서 열어 주세요 + 내려받기' 화면. 휴대폰 앱은 그대로.
- 판별: 사용자 에이전트 + 프로그램이 처음 실행 때 서버에서 받아 둔 기기 표(머리줄). 브라우저가 흉내 내는 것을 완전히 막지는 못한다(억제 수준).

## 4. 배포

### 4-1 윈도 — 마이크로소프트 스토어(MSIX)
- 회사 개발자 계정(무료, D-U-N-S 있으면 빠름) → 앱 이름 '워크인' 예약 → 꾸러미 이름·게시자 값을 빌드 설정에 넣음.
- 빌드: GitHub Actions 윈도 실행기에서 electron-builder 'appx' 대상으로 MSIX 를 만든다(서명하지 않음 — 스토어가 서명). 데스크톱 앱 기본 권한(runFullTrust)은 제출 때 사유를 적는다.
- 제출: 개인정보 처리방침 `https://www.work-in.dev/privacy`, 심사용 계정(체험 회사 계정 1개, 'Notes for certification'), 첫 화면에서 무엇인지 보이게.
- 공개 범위 권장: **공개 + 검색에는 안 나오고 직접 링크로만** → www 내려받기 페이지의 [Microsoft Store 에서 받기] 버튼이 그 링크. 비공개는 개인 마이크로소프트 계정 메일만 넣을 수 있어 직원 배포에 맞지 않는다.
- 업데이트: 스토어가 자동. 껍데기가 바뀔 때만 새 제출.
- 스토어가 막힌 고객사 PC 에 깔아야 하면 그때 스토어 밖 배포용 OV 인증서(연 $150~300, 대표 승인 뒤). 월 과금 서명은 한국 회사 대상이 아니다.

### 4-2 맥 — Developer ID 서명 + 공증, www 에서 DMG
- 기존 애플 개발자 계정. Developer ID 인증서는 계정 소유자만 만들 수 있으므로 대표 계정으로 1회.
- 공증은 App Store Connect API 키로 빌드 중에 자동(키는 GitHub Actions 비밀값 — 저장소에 쓰지 않음).
- 자동 업데이트: 우리 서버의 업데이트 목록 파일 + electron-updater.
- 맥 앱스토어는 쓰지 않는다(샌드박스·'최소 기능' 심사 위험).

### 4-3 www 내려받기 페이지 (`/download`)
- 윈도: Microsoft Store 링크 · 맥: DMG · 휴대폰 앱 링크 · 설치 → 로그인 → 시작 때 열기 안내.
- 로그인 없이 보는 소개 쪽 화면이므로 주소 분리 뒤에도 www 에 둔다(`src/lib/hostSplit.ts` www 허용 목록에 `/download` 추가).

- ⓑ '직원은 PC 프로그램에서만'을 회사 설정으로 둘지(제안: 두되 기본 꺼짐).
- ⓒ 윈도 먼저, 맥은 다음 차수(제안 — 맥은 캡처 차단이 부분이라 효과가 작음).
- ⓓ 스토어 공개 범위: 직접 링크로만(제안) / 스토어 검색에도 노출(홍보 효과).
- ⓔ 프로그램 이름·아이콘: '워크인'(앱과 같게, 제안).

## 7. 순서

1. 대표 ⓑ~ⓔ 답.
2. 로컬: 스토어 회사 계정·이름 예약(확인 기간이 있으니 먼저).
3. 클라우드: 껍데기·서버 길·빌드·`/download`.
4. 로컬: 실제 PC 시험(5절 표).
5. 스토어 제출(직접 링크) → 통과 뒤 `/download` 공개.
6. (선택) 회사 설정 '직원은 PC 프로그램에서만'.

주소 분리(15-29)와는 순서가 묶이지 않는다 — 시작 주소를 서버에서 받으므로 전환 때 껍데기를 다시 내지 않는다.

## 8. 못 하는 것

- 휴대폰 카메라로 화면 찍기(워터마크로 출처만 추적).
- 맥에서 ScreenCaptureKit 를 쓰는 새 캡처·녹화·회의 앱.
- 윈도 10 2004판 이전: 검은 창으로 찍힘(창이 빠지지는 않음).
- 일반 브라우저 접속 — ⓑ 를 켜도 흉내 낸 브라우저는 완전히 못 막음.
- 운영체제 깊은 권한의 캡처 도구.
