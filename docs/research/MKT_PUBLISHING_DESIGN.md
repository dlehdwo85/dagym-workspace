# 마케팅 고객 게시 경로 설계 (상용화 ⑤) — 2026-10-18 초안

> 상태: 5-1 운영 중(게시 도우미·게시 기록). **5-2 개정(대표 결정 10/19): 모든 채널 직접 연동, 구독형 통합 게시 API 미사용** — 아래 5절.
> 상태(이전): 설계 초안. 외부 플랫폼 정책·권한 이름·할당량은 제출 직전 공식 문서로 다시 확인한다(아래 "확인 필요" 표시).
> 원칙: 게시는 **승인된 버전만**, 사람이 마지막 [게시]를 누른다(자동 게시는 회사 설정으로 켜는 선택 기능, 기본 꺼짐). 시험 콘텐츠(is_test)는 게시 불가. 실패하면 **이미 올라갔는지 먼저 확인한 뒤에만** 다시 시도한다(운영실 SNS 게시 정책과 같음).

## 0. 공통 구조(워크인)

| 항목 | 설계 |
|---|---|
| 연결 계정 | `mkt_publish_accounts` (tenant, provider = meta_ig·meta_fb·youtube·naver_blog, external_id, label, brand_id, token_enc(AES-GCM, crypto.ts), scopes, expires_at, status, last_error) — 회사 관리자만 연결·해제 |
| 게시 작업 | `mkt_publish_jobs` (content_id, version, account_id, status = queued·running·verify·done·failed·canceled, idempotency_key = content_id:version:account_id, external_post_id, permalink, attempts, last_error, requested_by) — 같은 키는 한 번만 |
| 게시 흐름 | 승인된 버전 → [게시](관리자) → job queued → tick 이 실행 → 성공이면 `markPublished`(게시 주소 자동 기록) / 시간 초과·모호한 오류면 **verify**(최근 게시물에서 같은 캡션·미디어를 찾아 확인) → 없을 때만 1회 재시도 |
| 토큰 | 만료 전 tick 이 갱신. 갱신 실패 → 계정 status=error + 받는 사람 알림(하루 1번) |
| 권한 | 게시·계정 연결 = 회사 관리자. 직원은 결과만 봄. 다른 회사 계정·작업은 404 |
| 감사 | 연결·해제·게시 요청·재시도는 audit_logs |
| 데이터 삭제 | 계정 해제 시 토큰 즉시 삭제, 회사 탈퇴 시 전부 삭제(플랫폼 데이터 삭제 콜백도 같은 함수) |

## 1. Meta (Instagram·Facebook 페이지) — 심사가 가장 오래 걸리므로 먼저

**방식**: 고객 회사가 자기 Facebook 계정으로 OAuth 로그인 → 관리하는 페이지·연결된 Instagram 비즈니스(프로페셔널) 계정 선택 → 워크인 서버가 Graph API 로 게시.
- Instagram: 미디어 컨테이너 생성(`/{ig-user-id}/media`, image_url·caption) → 게시(`/{ig-user-id}/media_publish`). 여러 장은 carousel, 릴스는 media_type=REELS(영상 URL은 공개 접근 가능해야 함 → 워크인 저장소의 짧은 서명 URL).
- Facebook 페이지: `/{page-id}/photos` 또는 `/feed` (페이지 액세스 토큰).
- 게시 한도: Instagram 계정당 24시간 게시 수 제한 있음(확인 필요 — `content_publishing_limit` 으로 조회 가능).

**필요 권한(확인 필요 — 제출 직전 Meta 문서로 확정)**: `instagram_basic`, `instagram_content_publish`, `pages_show_list`, `pages_read_engagement`, (페이지 게시 시) `pages_manage_posts`, 비즈니스 자산 접근 시 `business_management`.

**앱 심사 준비물(지금 만들 수 있는 것부터)**
1. 개인정보 처리방침·서비스 약관 공개 URL(워크인 /legal 에 있음 — Meta 데이터 사용 문구 추가 필요)
2. 데이터 삭제 콜백 URL 또는 삭제 안내 페이지(`/api/marketing/publish/meta/data-deletion` 설계)
3. 앱 아이콘·이름·카테고리, 앱 도메인(work-in.dev), OAuth 리디렉션 URI(`/api/marketing/publish/meta/callback`)
4. **권한별 사용 설명 + 화면 녹화(screencast)**: 연결 → 페이지·IG 계정 선택 → 승인된 콘텐츠 [게시] → 인스타그램에 올라간 결과 확인 → 연결 해제. 시험 계정(검수자용 로그인 정보)은 심사 양식에만 입력하고 저장소에는 두지 않는다.
5. 비즈니스 인증(Business Verification) — 대표 진행(사업자 정보 필요)
6. 앱을 Live 모드로 전환하기 전까지는 앱 역할(개발자·테스터)에 등록된 계정만 연결 가능 → 우리 회사 계정으로 먼저 실연동 시험

**대표 결정 필요**: Meta 앱을 새로 만들지(워크인 전용) / 운영실 기존 앱을 옮길지, 비즈니스 인증 주체.

## 2. YouTube (쇼츠·영상)

- YouTube Data API v3 `videos.insert`(재개 가능한 업로드), OAuth 범위 `https://www.googleapis.com/auth/youtube.upload`.
- **확인 필요**: Google 감사(API 서비스 감사)를 통과하기 전 미인증 프로젝트로 올린 영상은 비공개로 고정됨 → 감사 신청 자료(용도·화면 녹화) 준비.
- 할당량: 기본 하루 10,000 단위, 업로드 1건 약 1,600 단위(확인 필요) → 하루 약 6건. 회사가 늘면 할당량 증설 신청.
- OAuth 동의 화면 검증(민감 범위) 필요 — 개인정보처리방침·도메인 소유 확인.
- 기존 Google 캘린더 동기화와 **별도 OAuth 클라이언트**로 분리(범위 최소화, 캘린더 동기화는 선택 기능이라 영향 없게).

## 3. 네이버 블로그 — 공식 쓰기 API 없음 → 게시 도우미

- 공식 글쓰기 API 가 없으므로(확인 필요 — 예전 API 종료) 서버 자동 게시는 하지 않는다. 브라우저 자동화·비공식 API 는 **약관 위반·계정 제재 위험**이라 쓰지 않는다.
- **게시 도우미**: 승인된 원고를 [제목 복사]·[본문 복사(네이버 편집기에 맞는 서식)]·[사진 한꺼번에 내려받기(순서 번호)]·[네이버 블로그 글쓰기 열기] 버튼으로 제공 → 사람이 붙여 넣고 올린 뒤 **게시 주소를 붙여 넣어 게시 확인**(지금의 markPublished 와 같음).
- 화면에 위험 고지: "네이버는 자동 게시를 허용하지 않아 직접 올립니다. 같은 글을 여러 블로그에 반복 게시하면 저품질 판정 위험이 있습니다."

## 5. 5-2 개정 — 직접 연동 + 심사 전 도우미 (대표 결정 2026-10-19)

### 5-1. 운영 원칙
- 구독형 통합 게시 API(Upload-Post·Zernio)는 쓰지 않는다. 채널마다 워크인이 직접 연동한다.
- 고객 화면은 채널마다 **[연결] 하나**와 **사용 켜기/끄기**만 보인다. 앱 ID·콜백 주소·권한 이름 같은 기술 값은 플랫폼 관리자에게만 보인다(광고 계정 콜백도 같은 기준으로 바꿈).
- **심사 통과 전(출시 10/27 포함)**: 연결 여부와 상관없이 인스타·페이스북·스레드·유튜브도 게시 도우미로 운영한다. 네이버 블로그 도우미와 같은 구조이고 채널만 늘렸다.
  - 캡션 복사
  - 사진·영상을 순서대로 내려받기(모두 내려받기)
  - 휴대폰: [앱으로 공유] — 캡션을 복사해 두고 공유 시트로 사진·영상을 넘긴다. 인스타·페북 앱은 공유된 글을 받지 않으므로 붙여 넣는다.
  - PC: 웹 작성 화면 열기(인스타 웹, Meta 비즈니스 게시물 만들기, 스레드, 유튜브 스튜디오, 스마트플레이스)
  - 올린 뒤 주소를 붙여 넣고 [게시 확인]
- 자동 게시는 앱 심사 통과 후 `META_PUBLISH_LIVE=1` 로 켠다(서버 게시 작업 코드는 다음 단계).

### 5-3. Meta 연결(앱 ID 없이 먼저 만듦)
- `META_APP_ID`/`META_APP_SECRET` 이 없으면 [연결 곧 열림]으로 보이고, 시작 API 는 409 + 쉬운 안내를 돌려준다.
- 요청 권한: pages_show_list, pages_read_engagement, pages_manage_posts, instagram_basic, instagram_content_publish, business_management.
- 콜백 처리:
  1. 장기 사용자 토큰을 받는다.
  2. `/me/permissions` 로 빠진 권한을 확인한다.
  3. `/me/accounts`(tasks, instagram_business_account)로 페이지와 IG 계정을 등록한다. 토큰은 암호화해 저장한다.
- **연결 전 점검**(대표 10/19): 연결 전에는 3가지 확인 항목을 접어서 보여 준다. 연결 후에는 **안 된 항목만** 계정 아래에 '확인 필요'로 보여 준다.
  - 관리자 권한 없음(tasks 에 MANAGE·CREATE_CONTENT 없음)
  - 페이지에 IG 비즈니스 계정 없음(계정 유형이 개인이거나 페이지와 연결 안 됨)
  - 동의 화면에서 권한 일부를 끔
- 끊기: 행을 삭제해 토큰을 즉시 지운다. 게시 기록은 남는다.
- 데이터 삭제 콜백 `POST /api/marketing/publish/meta/data-deletion`: signed_request 를 HMAC 으로 확인하고, 그 Meta 사용자(owner_ext_id)가 연결한 계정을 모두 지운 뒤 `{url, confirmation_code}` 를 돌려준다.
- 시험: 가짜 Graph 서버로 연결·점검·암호화·비노출·끊기·삭제 콜백을 확인했다(**구조 시험**). 실연동은 Meta 앱이 생긴 뒤 우리 회사 계정으로 확인한다.

### 5-4. 유튜브·틱톡 심사 자료(준비)
- 유튜브: OAuth 동의 화면 민감 범위 검증(`youtube.upload`)과 API 서비스 감사(감사 전 업로드는 비공개로 잠김, 확인 필요)가 필요하다.
  - 시연 영상: 연결 → 승인된 영상 [게시] → 스튜디오에서 확인 → 끊기
  - 사용 이유: 고객 회사가 승인한 쇼츠·영상을 자기 채널에 올림. 읽기·삭제 없음.
  - 클라이언트는 로그인용과 분리한다(범위 최소화).
- 틱톡: Content Posting API 앱 등록 → 감사 신청 전에는 비공개(SELF_ONLY) 게시만 된다.
  - 감사 자료: 서비스 설명, 게시 흐름 화면 녹화, 사용자 동의·게시 전 미리보기 화면(틱톡 UX 가이드 필수 항목: 계정 표시, 공개 범위 선택, 콘텐츠 공개 동의)
- X·링크드인: 후순위.

## 6. Meta 앱 이용 사례 반영(로컬 요청 10/19 — 대표: '경쟁사보다 높은 수준으로')

- Meta 앱은 김소담 부사장 계정으로 만든다. 이용 사례는 5개다: 인스타 메시지·콘텐츠, 페이지 관리, 광고 성과, Lead Ads, 광고 MCP.
- 권한과 심사 녹화 시나리오는 `META_APP_REVIEW_PLAN.md` 에 정리했다.
- 게시(⑤-2) 연결 권한에 문의함용 권한(instagram_manage_messages·instagram_manage_comments·pages_manage_engagement·pages_read_user_content·pages_manage_metadata)을 더한다. 한 번 [연결]로 같이 받는다.

**A. 인스타·페북 DM·댓글 통합 문의함** — 전화 문의(mkt_calls)와 같은 흐름이다.
1. 웹후크가 들어오면 문의를 자동 등록한다(채널·보낸 사람·원문·게시물 링크).
2. AI 가 답장 초안을 만든다. 브랜드 말투와 금지 표현을 검사한다.
3. 담당자를 배정하고 업무를 만든다.
4. 사람이 고친 뒤 [보내기]. 자동 발송은 없다.
5. 화면에 **24시간 응답 창**을 표시한다. 남은 시간이 보이고, 지나면 보내기가 잠기며 안내가 나온다(사람 상담원 태그 조건은 확인 필요).
6. 영업 문의로 보이면 [영업 리드로] 버튼을 보여 준다(전화 문의와 같다).

- 페이스북 Messenger DM 은 1차에서 제외한다(Messenger 이용 사례 제외). 페이지 댓글은 포함한다.
- 데이터: `mkt_inbox_threads` / `mkt_inbox_messages` (추가형). 원문은 회사 안에서만 보인다. 연결을 끊거나 데이터 삭제 콜백이 오면 지운다.

**E. 승인된 콘텐츠 부스트**
1. 게시물 인사이트(instagram_manage_insights)로 반응이 좋은 글을 AI 가 추천한다. 근거는 같은 계정 평균 대비 참여율이다.
2. 고객이 예산·기간·대상을 정하고 승인한다.
3. 광고를 꺼진 상태로 만든다 → [켜기]. V44 승인·상한 규칙을 그대로 따른다.
