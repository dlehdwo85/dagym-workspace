# AI 광고 운영실 설계 (V44) — 2026-10-19 초안

> 대표 방향: `docs/handoff/WORKIN_V44_AI_ADS_OPERATIONS.md`. 매체별 API 조사는 `AI_ADS_API_SURVEY.md`(확인일 10/19)에 있다.
> 상태: **설계 초안 · 코드 없음.** 지금의 '광고 성과(읽기 전용)' 위에 '광고 운영(만들기·조정)'을 얹는다.
> 원칙: AI 는 제안하고 만든다. **돈이 나가는 변경은 고객이 승인한 것만** 반영한다. 결제수단 등록·충전은 고객이 매체에서 직접 한다.

## 1. 흐름(고객 화면: 마케팅 › 광고 운영)

| 단계 | 화면 | 서버 |
|---|---|---|
| ① 진단 | 업종·지역·목표(전화·방문·문의·예약)·월 예산·홈페이지/플레이스 주소 입력 → AI 가 매체 조합·예산 배분안 제안(근거: 업종 평균 CPC 범위·지역 검색량·지난 성과) | `mkt_ad_plans` 초안(status=draft) |
| ② 세팅안 미리보기 | 매체별 캠페인·광고그룹·키워드(입찰가)·제외어·광고 문구·이미지(자동 제작 연결)·랜딩 한 화면. 고객이 문구·키워드를 고칠 수 있음. **사전 검사**(4절) 통과해야 다음 단계 | 세팅안 = JSON(매체 독립 구조) → 매체별 변환기 |
| ③ [승인하고 시작] | 승인한 사람·시각·세팅안 버전 기록 → **꺼진 상태로 생성**(네이버 `userLock=true`, Google·Meta `PAUSED`) → 생성 결과(매체 ID) 확인 화면 → [켜기] | `mkt_ad_changes`(kind=create) 로 한 건씩 실행, 실패하면 거기서 멈춤 |
| ④ 운영 | 매일 성과 읽기(지금 있음) → 주 1회 AI 개선안(입찰 조정·제외 키워드·문구 교체·예산 이동) → 고객 승인 → 반영. 이상 징후(비용 급증, 클릭은 있는데 전화 0, 소재 반려) 즉시 알림 | 개선안 = `mkt_ad_changes`(status=proposed) 묶음 |
| ⑤ 보고 | 월간 마케팅 보고에 '광고비 대비 전화·문의·리드'(전화 문의·영업 리드 연결) | mktReport 확장 |

## 2. 데이터(추가형 마이그레이션 — 구현 때)

- `mkt_ad_plans` (tenant, brand_id, goal, region, monthly_budget, plan jsonb, version, status draft·approved·active·paused·ended, approved_by/at)
- `mkt_ad_changes` (tenant, account_id, plan_id, kind create·update·enable·pause·budget·bid·negative·creative, target(매체·객체 종류·외부 id), before jsonb, after jsonb, money_up bool, status proposed·approved·applied·failed·reverted·rejected, approved_by/at, applied_at, error, revert_of) — **모든 변경의 기록이자 되돌리기 근거**
- `mkt_ad_caps` (tenant, monthly_cap, hard_stop bool) — 회사별 월 광고비 상한

## 3. 안전 장치

1. **승인 필수**: `money_up`(켜기·예산 증액·입찰 상향·새 캠페인) 변경은 승인 없이 `applied` 로 못 감(서버 검사, 관리자만 승인). 감액·끄기는 자동 허용(돈이 덜 나가는 방향).
2. **월 광고비 상한**: 매일 성과 읽기 때 이번 달 누적 비용 + 오늘 예상 ≥ 상한이면 워크인이 만든 캠페인을 모두 **끄고**(네이버 userLock, Google/Meta PAUSED) 관리자에게 알림. 다시 켜기는 승인 필요. 상한은 매체 일예산 합 × 남은 날로도 미리 검사해 승인 단계에서 경고.
3. **변경 기록·되돌리기**: 적용 전에 매체에서 현재 값을 읽어 `before` 에 저장. [되돌리기] = before 로 되돌리는 새 변경(돈이 늘면 다시 승인).
4. **사전 문구 검사**(업종별 광고 심사 기준): 의료(효능·치료 보장·전후 비교), 금융(수익 보장), 최상급·근거 없는 수치, 가격·할인 표현 규칙, 매체 글자 수(네이버 제목 15자·설명 45자 등). 자동 제작의 품질 검사(qualityCheck)와 같은 규칙 표를 쓰고 업종별 규칙을 더한다. 걸리면 세팅안 승인 버튼이 잠긴다.
5. **권한**: 연결·승인은 회사 관리자. 직원은 보기만. 다른 회사 계정·변경은 404.
6. **시험 구분**: 가짜 매체 서버 시험은 '구조 시험'. 실연동 완료는 우리 회사 실계정에서 꺼진 상태 생성 → 매체 화면 확인 → 삭제까지 한 뒤에만 기록.

## 4. 매체 순서(조사 반영)

1. **네이버 검색광고 쓰기**: 파워링크 → 플레이스.
   - 이미 고객 API 라이선스 연결이 있다(읽기).
   - 문서상 `PLACE`·`POWER_CONTENTS` 생성이 가능하지만 실계정 시험이 필요하다.
   - 플레이스는 스마트플레이스 비즈채널이 연결돼 있어야 한다.
2. **Google Ads**: 2026-09-09 개발자 토큰 폐지 → 접근 등급은 OAuth 클라이언트의 Cloud 프로젝트 기준(조사 문서). 현재 403 은 프로젝트 등급(Explorer 신청) 문제일 가능성이 크다 → 실제 오류 코드 확인 후 신청.
3. **Meta 광고**: `ads_management` 고급(Full) 액세스 + 앱 심사 + 비즈니스 인증 — 워크인 Meta 앱(김소담 부사장 계정으로 생성 예정) 심사와 함께.
4. 카카오모먼트: 외부 SaaS 가 고객 계정을 다룰 수 있는지 카카오에 서면 문의 먼저. 틱톡: 국내 수요 확인 후. 당근·스마트플레이스·GFA: 공개 API 없음 → 고객 직접 입력 안내(화면 자동 조작은 쓰지 않음).

## 5. 대표 결정 필요

- 회사별 월 광고비 상한 기본값(예: 고객 입력 필수, 기본 없음)과 상한 초과 시 자동 중지 기본 켜짐 여부
- 감액·끄기 자동 허용 범위(이상 징후 때 AI 가 먼저 끌 수 있게 할지)
- 광고 운영 기능의 요금(요금제 포함 / 광고비 비례 / 정액 추가)
