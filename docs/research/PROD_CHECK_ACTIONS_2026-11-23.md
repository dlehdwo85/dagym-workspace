# 노트북 없이 운영 확인하기 — 깃허브 Actions + 검수용 시험 회사 (검토, 2026-11-23)

로컬 11/23 요청(대표 지시 "데스크톱이 멈춰도 클라우드는 멈추지 않게"): 배포 직후 운영 화면 확인을 노트북 없이 할 수 있는지.
목표는 **대표 계정 전용 화면·실기기 확인만 노트북(로컬)에 남기는 것**.

## 결론(추천)

**가능합니다. 깃허브 Actions 비용은 0원이고(공개 저장소), 대표님이 하실 일은 두 가지입니다.**
1. 운영에 '검수용 시험 회사'(다짐과 분리된 빈 회사)를 만드는 것을 승인
2. 그 회사 계정의 이메일·비밀번호를 깃허브 비밀값에 직접 넣기

이 두 가지가 끝나면 클라우드가 워크플로를 만듭니다. `main`에 올라간 커밋이 운영에 반영되면 그 회사 계정으로 로그인해 주요 화면을 자동으로 확인합니다.

## 지금 있는 것

| 무엇 | 하는 일 | 한계 |
|---|---|---|
| `scripts/verify-prod.mjs` (11개) | 헬스체크·정기 실행·보안 헤더·로그인 화면·앱 링크 파일 등. 클라우드가 배포마다 직접 돌림 | 로그인하지 않음. 화면을 열지 않음 |
| 같은 스크립트의 `SMOKE_EMAIL`/`SMOKE_PASSWORD` | 값을 주면 로그인·내 정보·업무 목록까지 확인(데이터는 만들지 않음) | 계정이 없어서 아직 안 씀 |
| `ci.yml` 화면 시험 284개 | 가짜 서버로 모든 화면 흐름 | 운영 서버·운영 DB가 아님 |

## 새로 만들 것

| 항목 | 내용 |
|---|---|
| 검수용 시험 회사 | 운영에 회사 1개(예: '워크인 검수(시험)'), 대표·관리자·직원 계정 2~3개. 다짐 조직과 섞이지 않게 별도 회사. 자료는 모두 가짜(실명·실제 고객 없음) |
| 깃허브 비밀값 | `PROD_QA_EMAIL`, `PROD_QA_PASSWORD`(필요하면 직원 계정 한 쌍 더). **대표가 저장소 Settings › Secrets 에 직접 입력**. 클라우드·로컬은 값을 보지 않음 |
| 워크플로 `prod-check.yml` | ① Vercel 운영 배포 성공 알림(`deployment_status`) 또는 `main` 푸시 뒤 `/api/health` 의 commit 이 새 커밋이 될 때까지 기다림 → ② `verify-prod.mjs`(로그인 포함) → ③ Playwright 로 운영 화면 확인 |
| 화면 확인 범위(1차) | 로그인 · 홈 · 내 업무(목록·상세 패널) · 업무 하나 만들기→완료→지우기(시험 회사 안에서만) · 캘린더 주 보기 · 메신저 방 열기·글 하나 · 결재함 · 설정. 화면폭 390·1440 |
| 결과 | 성공·실패를 Actions 화면에 표시. 실패하면 클라우드가 고치거나, 대표결정함·노트북에 알림 |

## 비용

| 항목 | 비용 | 근거 |
|---|---|---|
| 깃허브 Actions | 0원 | 공개 저장소의 기본 실행기는 무료 |
| Vercel·DB | 거의 0 | 배포 1번에 요청 수십 개, 시험 회사 줄 몇 개 |
| AI | 0원(쓰지 않음) | 시험은 AI 단추를 누르지 않음. AI 화면은 열기만 |
| 메일·알림톡·푸시 | 0원(보내지 않음) | 초대 메일·알림톡이 나가는 동작은 시험에서 빼고, 시험 회사는 알림톡을 끈다 |

## 한계·주의 (꼭 지킬 것)

| 주의 | 왜 | 어떻게 |
|---|---|---|
| **저장소가 공개라 실행 기록(로그)도 공개** | 시험 화면 사진·로그가 누구에게나 보임 | 화면 사진·실패 사진을 올리지 않음(artifact 없음). 로그에 이메일·이름을 찍지 않음. 시험 회사 자료는 모두 가짜 |
| 비밀값 노출 | 다른 사람이 보낸 PR 에서 비밀값을 읽으려는 시도 | `main` 푸시·배포 알림에서만 돌림(PR 에서는 안 돌림). 비밀값은 로그에 가려짐 |
| 운영 데이터 오염 | 시험이 실제 회사 자료를 건드리면 안 됨 | 시험 회사 안에서만 만들고 지움. 다짐·다른 회사는 읽지도 않음(권한상 404) |
| 통계·요금 섞임 | 시험 회사가 가입·매출 통계에 잡힘 | 시험 회사를 체험·시험 표시로(플랫폼 관리 통계에서 빼는 표시가 있는지 만들 때 확인) |
| 로그인 보호 | 같은 IP 에서 자주 로그인하면 막힐 수 있음 | 배포 1번에 로그인 1~2번. 2단계 인증 없는 계정 |
| 못 하는 것 | — | 대표 계정 전용 화면(지점 보고 실제 숫자·다짐 영업 자료), 실제 휴대폰(푸시·앱 화면·카메라), 간편 로그인(카카오·구글 — 사람 확인 필요), 실제 메일 받은편지함, 결제 → **이것만 노트북(로컬)에 남김** |

## 대표님께 여쭐 것 (대표결정함에 올림)

- 운영에 '검수용 시험 회사'(가짜 자료만)를 하나 만들어도 될까요? → 승인하시면 클라우드가 만드는 방법을 정리하고, 대표님은 깃허브 비밀값 두 칸만 넣으시면 됩니다.
  - 돈: 없음 · 삭제: 없음 · 공개: 실행 결과(성공·실패)가 공개 저장소에 보임(화면 사진·개인정보는 올리지 않음)
