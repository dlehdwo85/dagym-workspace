# 고객이 보는 외부 동의(OAuth) 화면 목록 — 인증·검수 상태와 필요한 자료 (2026-10-19 초안)

> 대표 원칙(10/19): 상용화 때 '확인되지 않은 앱 → 고급 → 안전하지 않은 사이트로 이동' 같은 번거로움·신뢰 저하 요소는 모두 없앤다.
> 상태 칸은 **코드 기준**으로 적었다. 실제 콘솔(Google Cloud·카카오·네이버·Meta)의 검수 상태는 로컬·대표가 콘솔에서 확인해 채운다(☐).
> 비밀값·콘솔 계정 정보는 이 문서에 쓰지 않는다.

## 1. 한눈에

| # | 동의 화면 | 어디서 뜨나 | 요청 범위(코드) | 민감도 | 검수 없이 생기는 문제 | 콘솔 상태(☐ 확인) |
|---|---|---|---|---|---|---|
| 1 | Google 로그인 | 로그인·가입 [Google로 계속] | `openid email profile` | 비민감 | 브랜드 검증 전에는 앱 이름·로고가 동의 화면에 안 나오거나 '확인되지 않음' 경고 가능 | ☐ 브랜드 검증·게시 상태(테스트/프로덕션) |
| 2 | Google 캘린더 동기화(선택 기능, 기본 꺼짐) | 내 설정 › Google 캘린더 | `calendar.calendarlist.readonly` + `calendar.events`(또는 `.readonly`) | **민감** | 검증 전: '확인되지 않은 앱' 경고 + 사용자 100명 제한 | ☐ 민감 범위 검증 |
| 3 | Google Ads 연결 | 마케팅 › 광고 성과(→ 연결 계정) | `https://www.googleapis.com/auth/adwords` | **민감** | 검증 전: '확인되지 않은 앱' 경고. 그 밖에 **개발자 토큰 등급**(테스트/기본)이 별도 — 403 원인 | ☐ 민감 범위 검증 · ☐ 개발자 토큰 기본 액세스(MCC) |
| 4 | 카카오 로그인 | 로그인·가입 [카카오로 계속] | `account_email profile_nickname` | 이메일은 **검수 동의항목** | 비즈 앱 전환·검수 전에는 이메일 필수 동의 불가 → 가입 막힘 가능 | ☐ 비즈 앱 · ☐ 이메일 검수 |
| 5 | 네이버 로그인 | 로그인·가입 [네이버로 계속] | 범위 없음(기본 프로필) | — | **검수 전에는 등록된 개발자·테스터 계정만 로그인됨**(일반 고객 불가) | ☐ 네이버 로그인 검수 |
| 6 | Meta 광고(읽기) | 마케팅 › 광고 성과(→ 연결 계정) | `ads_read` | 고급 액세스 필요 | 앱 역할 없는 고객은 권한 거부. 비즈니스 인증·앱 심사 필요 | ☐ 앱 심사 · ☐ 비즈니스 인증 |
| 7 | (향후) Meta 게시 | 게시 채널 | instagram_content_publish 등 | 고급 | 통합 게시 API 로 가면 **우리 동의 화면 없음**(업체 화면) — MKT_PUBLISH_DIRECT_VS_RELAY.md | 결정 대기 |
| 8 | (향후) YouTube 업로드 | 게시 채널 | `youtube.upload` | **민감** | 검증 + API 감사 전: 경고, 영상 비공개 잠김 가능(확인 필요) | 결정 대기 |

메일 보내기(네이버·다음·Gmail SMTP)는 **OAuth 가 아니라 앱 비밀번호** 방식이라 동의 화면이 없다. 대신 앱 비밀번호 발급 안내(이미 화면에 있음)가 번거로움 요소다.

## 2. 줄이는 순서(제안)

1. **Google 프로젝트 한 곳에서 브랜드 검증 먼저**: 앱 이름 '워크인', 로고, 홈페이지 https://www.work-in.dev, 개인정보처리방침(/privacy)·약관 URL, 승인된 도메인 work-in.dev.
   - 로그인(비민감)은 브랜드 검증만으로 경고가 없어진다.
2. **민감 범위는 쓰는 것만**:
   - 캘린더는 선택 기능이다. `calendar.events` 하나 + 목록 읽기로 줄이는 안을 검토한다.
   - Ads 는 `adwords` 하나다.
   - 범위마다 사용 이유와 시연 영상이 필요하다. 한 번에 제출하면 검토가 한 번에 끝난다.
3. **네이버 로그인 검수**: 검수 전에는 고객이 아예 로그인할 수 없으므로 우선순위가 높다. 서비스 소개·화면 캡처·개인정보 사용 설명이 필요하다.
4. **카카오 비즈 앱 + 이메일 동의항목 검수**: 사업자 정보가 필요하다(판매 명의 하이링크).
5. Meta 는 통합 게시 API 결정에 따라 갈린다. 광고 읽기(ads_read)만 우리 앱 심사로 갈지 함께 정한다.

## 3. Google `adwords` 범위 사용 이유(초안, 1,000자 이내)

> 워크인(Workin)은 중소기업용 업무·마케팅 관리 서비스입니다. 고객 회사의 관리자가 자신의 Google Ads 계정을 직접 연결하면, 워크인은 https://www.googleapis.com/auth/adwords 범위로 그 계정의 캠페인 성과 보고서(날짜별 노출수·클릭수·비용·전환수, 캠페인 이름)를 **읽기만** 합니다. 이 데이터는 워크인의 '광고 성과' 화면과 '월간 마케팅 보고'에서 고객 회사 안의 권한 있는 사람에게만 보이며, 네이버·Meta 광고 성과와 한 화면에서 비교하는 데 쓰입니다. 워크인은 이 범위로 캠페인·예산·입찰·광고를 만들거나 바꾸지 않습니다. Google Ads API 에 읽기 전용 범위가 따로 없어 adwords 범위를 요청합니다. 토큰은 서버에서 암호화해 저장하고, 고객이 '연결 끊기'를 누르면 토큰과 가져온 성과 데이터를 즉시 삭제합니다. 데이터는 광고 판매·제3자 제공·AI 학습에 쓰지 않습니다. 개인정보처리방침: https://www.work-in.dev/privacy

(글자 수: 약 560자 — 쓰기 기능을 추가하면 문구를 고쳐 다시 제출)

## 4. 시연 영상 대본(초안, Google Ads — 2~3분, 화면 녹화 + 한국어 자막/영문 자막)

1. (0:00) 브라우저 주소창에 https://www.work-in.dev 가 보이는 상태로 로그인. OAuth 클라이언트 이름이 '워크인'인 것을 보여 줌.
2. (0:15) 마케팅 공간 › 설정 › **연결 계정** → Google Ads [연결] 클릭.
3. (0:25) Google 동의 화면: 앱 이름 '워크인', 요청 범위 'Google Ads 캠페인 관리'가 보이게 멈춤 → 계정 선택 → 허용.
4. (0:45) 워크인으로 돌아와 '연결됨 · 계정 1개' 표시. 계정 번호(가림 처리 가능)·마지막 불러온 시각을 보여 줌.
5. (1:00) **광고 성과** 화면: 날짜별 노출·클릭·비용·전환 표와 캠페인 이름. "읽기만 하며 캠페인을 바꾸는 기능은 없음"을 자막으로 표시.
6. (1:30) **월간 보고** 화면: Google 광고 성과가 다른 매체와 합산되어 보이는 것.
7. (1:50) 연결 계정 › [끊기] → 확인 → 계정과 성과 데이터가 사라진 것을 보여 줌. Google 계정 권한 페이지(myaccount.google.com/permissions)에서 앱 접근 해제도 가능함을 자막으로.
8. (2:10) 개인정보처리방침 페이지(/privacy)의 'Google 사용자 데이터' 항목을 보여 주며 끝.

준비물: 시험용 Ads 계정(실데이터 가림). 지금 /privacy 에는 Google 로그인·캘린더만 있고 **Google Ads 연결로 받는 데이터(성과 보고서 읽기·보관·삭제) 문단이 없음 → 추가 필요(문구 대표 확인)**.

## 5. 다른 화면에 필요한 자료(체크리스트)

| 화면 | 필요한 자료 |
|---|---|
| Google 로그인·캘린더 | 브랜드 정보(이름·로고 120×120·홈페이지·처리방침·약관·도메인 소유 확인). 캘린더 범위 사용 이유 + 시연 영상(연결 → 일정 양방향 → 끊기) |
| 네이버 로그인 | 서비스 URL, 로그인 버튼 위치 화면 캡처, 받는 정보(이름·이메일)와 사용 목적 |
| 카카오 로그인 | 비즈 앱 전환(사업자등록), 이메일 동의항목 사용 목적, 화면 캡처 |
| Meta(ads_read) | 앱 심사: 권한 사용 설명, 화면 녹화(연결 → 성과 → 끊기), 데이터 삭제 콜백 URL, 비즈니스 인증 |
