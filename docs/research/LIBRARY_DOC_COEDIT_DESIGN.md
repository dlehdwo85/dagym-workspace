# 자료실 문서 공동 편집 설계 (한 장) — 2026-10-19 클라우드

대표 결정(10/19, 로컬 전달): **업무 설명·체크리스트·회의 메모 공동 편집은 만들지 않음**(작성자 의도가 바뀔 수 있음). 만들 것은 **자료실 '문서' 공동 편집** — 워크인 문서(워드 대체)·표(엑셀 대체)를 여러 명이 동시에, 다른 사람 커서·이름, 변경 기록·되돌리기, 보기/편집 공유. **비용 0: 외부 유료 실시간 서비스 쓰지 않음.** 지연 1~2초면 충분. 앱에서도.

## 1. 구성
| 부분 | 쓰는 것 | 비용 |
|---|---|---|
| 편집 엔진 | Yjs(CRDT, 오픈소스) — 같은 곳을 동시에 고쳐도 자동 합침, 끊겼다 돌아와도 합침 | 0 |
| 편집기 | 1차 문서: Tiptap(ProseMirror) + y-prosemirror — 제목·본문·목록·표 블록·굵게·링크 / 2차 표 문서: `Y.Map` 셀(행·열) 격자 화면 | 0 |
| 동기화 | 워크인 API(Vercel 함수) + Neon(Postgres)에 **추가형 저장** | 지금 요금제 안(아래 계산) |
| 커서·이름 | Yjs awareness 를 같은 요청에 실어 보냄(저장 안 함, 15초 지나면 사라짐) | 0 |

※ `src/lib/presence.ts` 는 근무 상태(휴가·출장·외근)라 문서 커서와는 별개. 문서 위 "지금 보는 사람" 아바타 옆에 근무 상태 점을 같이 보여 주는 정도로 연결.

## 2. 동기화 방식(외부 서비스 없음)
- **보내기**: 고친 조각(Yjs update, 보통 수십~수백 바이트)을 0.3초 모아 `POST /api/library/docs/:id/sync` — 본문 `{ update, awareness, since }`.
- **받기**: 같은 요청의 응답으로 `since` 뒤 새 조각 + 다른 사람 커서를 받음 → **한 번의 왕복으로 보내기·받기**.
- **간격(적응형 짧은 폴링)**: 최근 10초 안에 누가 고쳤으면 1초, 조용하면 3초, 화면이 숨으면 멈춤(앱 배경 포함), 다시 보이면 즉시 1번.
- SSE(스트리밍)는 쓰지 않음: Vercel 함수가 연결을 붙잡는 동안 메모리 시간이 계속 과금되고 한도(최대 실행 시간)마다 끊겨 재연결해야 해서, 1~2초 요구에는 짧은 폴링이 더 싸고 단순함.
- 저장(Neon, 새 표 — 추가형 migration):
  - `lib_docs(id, tenant, library_file_id, kind 'doc'|'sheet', snapshot bytea, snapshot_seq, updated_at)`
  - `lib_doc_updates(doc_id, seq bigserial, update bytea, user_id, created_at)` — 조각은 추가만
  - `lib_doc_versions(doc_id, seq, snapshot bytea, by_users uuid[], created_at)` — 변경 기록
- **합치기**: 조각이 200개 넘거나 10분 지나면 정기 실행(tick)이 조각들을 하나로 합쳐 snapshot 갱신 후 오래된 조각 삭제. 처음 여는 사람은 snapshot + 그 뒤 조각만 받음.
- **변경 기록·되돌리기**: 10분마다(또는 편집하던 사람이 모두 나가면) 버전 저장 → "기록" 패널에서 그 시점 보기·되돌리기(되돌리기도 새 변경으로 기록, 다른 사람 화면에 바로 반영).
- **검색·AI 비서·내보내기**: 버전 저장 때 글자만 뽑아 `library_files.text_content` 에 넣음 → 기존 자료실 검색·AI 비서 읽기가 그대로 동작. 내보내기는 .docx/.xlsx 로 변환(기존 문서 엔진 활용).

## 3. 권한·공유
- 모든 sync 요청에서 서버가 자료실 권한 검사(`loadLibraryFile`): 보기 권한 = 조각 받기만, 편집 권한 = 보내기 가능. 다른 회사 404.
- 공유 창: 사람·팀별 **보기/편집** (자료실 문서에만 새 표 `lib_doc_shares(doc_id, user_id|team_id, role)`), 기밀 등급 문서는 지금 규칙 그대로(외부 공유 없음).
- 보기 권한 사람이 보낸 조각은 서버가 버림(403).

## 4. 서버 부담·요금 계산(대략)
가정: 동시에 문서를 여는 사람 평균 5명, 하루 2시간, 월 22일.
- 요청 수: 고치는 중 1초·조용할 때 3초 → 평균 약 2초에 1번 = 사람당 시간당 1,800번
  → 5명 × 2시간 × 22일 × 1,800 = **월 약 40만 번**
- 한 번의 처리: 권한 확인 + 조각 읽기/쓰기 쿼리 2~3개, 실제 CPU 수 ms ~ 수십 ms → **월 CPU 시간 약 1~3시간**, 응답 크기 대부분 1KB 미만(전송량 월 수백 MB 이하).
- 판단: Vercel 요금제의 함수 호출·CPU·전송 포함량은 계정 요금제(Hobby/Pro)와 최근 개편에 따라 다르므로 **배포 전 Vercel 대시보드 Usage 화면의 현재 포함량과 맞춰 확인**(로컬 요청). 위 숫자는 지금 업무·알림 화면 폴링(이미 3초 간격 일부 사용)과 같은 규모라, 사람 수가 몇 배로 늘지 않는 한 추가 요금 가능성은 낮음.
- Neon: 쿼리 수가 늘지만 저장은 조각 합치기로 문서당 수십~수백 KB. 편집 중에는 DB 가 깨어 있어 Neon 컴퓨트 시간이 그만큼 늘어남(지금 요금제 컴퓨트 한도 안인지 Neon 대시보드로 확인 필요).
- 줄이는 손잡이: 조용할 때 간격 3→5초, 한 문서 동시 열람 20명 제한, 화면 숨으면 멈춤.

## 5. 단계
1. **문서(1차)**: 새 자료실 종류 '워크인 문서' 만들기·열기, Tiptap+Yjs, 1~3초 동기화, 커서·이름·보는 사람, 오프라인 합치기(IndexedDB), 보기/편집 공유, 기록·되돌리기, 글자 추출(검색·AI), .docx 내보내기 — E2E: 두 브라우저가 같은 줄을 동시에 고쳐도 둘 다 같은 글, 끊긴 쪽 다시 연결 시 합쳐짐, 보기 권한은 입력 막힘
2. **표 문서(2차)**: 셀 단위 Y.Map 격자(행·열 추가·삭제, 숫자·간단 합계), .xlsx 내보내기
3. 휴대폰: 같은 화면(Capacitor) — 좁은 폭 도구 막대, 배경 전환 시 폴링 멈춤

## 대표 확인
- 위 방식은 외부 유료 서비스 없이 지금 Vercel·Neon 요금제 안에서 동작하도록 설계함. 사용량 포함량은 대시보드로 한 번 확인 부탁.
