## 1. 결론(고치기 전 확인)
- **지금 [영구 삭제 실행]은 약속한 '파기'를 다 하지 않는다.** 회사 상태를 '삭제됨'으로 바꾸고, 사람 계정을 익명화하고, 메모만 지운다.
- 업무·일정·자료실 파일(R2 저장소의 실제 파일 포함)·연락처·영업·마케팅·메일·전자계약·결재·점검 등 **회사 자료는 DB 와 파일 저장소에 그대로 남는다.**
- 개인정보처리방침 35줄은 "공간 삭제는 복구 기간 30일 후 파기"라고 적고 있다. → **방침과 실제 동작이 다르다.** 다음 작업으로 고친다(아래 2절).
- 운영에 삭제 예약된 회사가 있는지는 **확인 못함**(클라우드는 운영 DB 를 보지 못함). 지금 영구 삭제를 실행하기 전에 아래 고침을 먼저 올린다.

## 2. 지금 지우는 것 / 남는 것
| 구분 | 지금 | 고친 뒤 |
|---|---|---|
| 회사 줄(tenants) | 상태 '삭제됨'으로 남김 | 그대로(이름은 '삭제된 회사'로 바꿈, 결제 기록과 이어지게 id 는 남김) |
| 사람 계정 | 익명화(이메일·이름·전화 지움) | 그대로 |
| 메모·주요 메모 | 지움 | 그대로 |
| 회사 자료(tenant 칸이 있는 표 162개 중 아래 '남김' 제외 전부) | **남음** | 지움 |
| 파일 저장소(R2) 실제 파일(자료실·첨부·계약 PDF·마케팅 소재 — `storage_key` 칸 6곳) | **남음** | 지움(묶음으로 나눠 정기 실행이 이어서 — 중간에 끊겨도 다시 이어 감) |
| 결제·환불·세금계산서 기록 | 남음 | **남김** — 전자상거래법 대금결제 기록 5년 보관. 사람 이름·연락처는 이미 익명화 |
| 감사 기록 | 남음 | 남김(누가 언제 지웠는지 증거) — 내용 칸의 개인정보는 없음(이름 대신 id) |

## 3. 고칠 방법(다음 작업)
1. [영구 삭제 실행] = 지금처럼 이름 다시 입력 → 회사 상태 '삭제 중' + 정기 실행이 지움(한 번에 지우면 시간 초과).
2. 지우는 순서: 파일 목록을 먼저 모아 둔다 → DB 자료(회사 칸 있는 표, 딸린 표 먼저) → R2 파일을 묶음(예: 200개)씩.
3. 남길 표는 이름으로 정해 둔다(결제·환불·세금계산서·정산·감사 기록). 새 표가 생겨도 회사 칸이 있으면 자동으로 지우는 쪽에 들어간다(빠뜨림 방지).
4. 끝나면 상태 '삭제됨' + 운영자에게 '파기 완료(지운 줄 수·파일 수)' 알림 + 감사 기록.
5. 시험: 시험 회사에 업무·일정·파일·연락처·영업·결제를 만든 뒤 영구 삭제 → 회사 자료 0줄·가짜 저장소 파일 0개·결제 기록은 남음·다른 회사 자료는 그대로.

## 4. 회사 전체 내보내기(지금은 개인 JSON·CSV 뿐)
> **11/24 16:37 갱신 — 만듦(f995144, DB 287)**: `src/lib/companyExport.ts` · 설정 › 회사 전체 내보내기. 압축 파일 한 개 기본 1GB(`COMPANY_EXPORT_PART_MB`), 한 파일 200MB 넘으면 빼고 목록에 표시(서버가 한 번에 읽는 상한), 앱 수준 ZIP64 없음(압축 파일 하나 4GB 미만). 운영 R2 실제 동작은 로컬 확인 대기.
- 누가: 회사 대표·관리자(설정 › 내보내기). 삭제 예약 안내 메일의 "설정 > 내보내기"가 이것을 가리키게 한다.
- 무엇: 영역별 CSV(업무·일정·연락처·영업·결재·계약 목록 등) + 자료실 파일 원본 + 목록표(manifest) → 압축 파일 하나.
- 방식: 요청 → 정기 실행이 만들어 R2 에 둠 → 관리자에게 알림 + 7일짜리 내려받기 링크. 하루 1번, 감사 기록.
- 크기: 파일이 많으면 여러 개로 나눔(예: 2GB 씩).
- 앱(아이폰·안드로이드)에서는 요청만, 내려받기는 웹에서(앱 파일 저장 제약).
