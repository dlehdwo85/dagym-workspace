# #814 마케팅 요금제 — 브랜드 수·주 한도 설계 (설계만, 구현은 대표 결정 뒤)

## 2. #814-4 주 한도를 넘는 규칙 — 처리 안

규칙 합(주 32칸)이 요금제 주 한도(9칸)를 넘을 때. 셋 중 고르기:

| 안 | 동작 | 장점 | 단점 |
|---|---|---|---|
| A. 표시만(지금) | 다 만들고 칩만 주황 | 글이 안 빠짐 | 요금제 숫자가 의미 없음, 원가가 요금 밖으로 샘 |
| **B. 넘는 칸은 건너뜀(추천)** | 주(월~일) 단위로 종류별 한도까지만 만들고, 넘는 칸은 '요금제 주 한도(피드 5) 넘음 — 건너뜀' 사유로 남김. 순서 = 게시 시각 빠른 순, 같은 시각이면 브랜드 우선순위 | 요금제가 실제 상한이 됨, 사유가 보여 대표가 규칙을 줄이거나 요금제를 올릴 수 있음 | 규칙을 많이 만든 회사는 일부 칸이 빈다 |
| C. 넘는 칸은 '승인 필요' | 한도 밖 칸도 원고는 만들고 승인함에 '한도 밖' 표시 | 대표가 골라 쓸 수 있음 | 글쓰기 원가는 그대로 듦 |

- 우리 회사(내부, 비용 한도 원)는 B 를 적용하지 않음(내부는 원가 한도로만 막는 270차 결정 유지) — 대표가 원하면 켬.
- 구현량: 칸 만들 때 한 번 세는 검사 + 사유 칸 + 시험. 0.5일.

## 3. 브랜드별 요금 (설계)

| 칸 | 뜻 | 값 |
|---|---|---|
| `brandsIncluded` | 요금제에 든 브랜드 수 | 베이직 (대표 결정) · 스탠다드 (대표 결정) · 프로 (대표 결정) — 예: 1·2·3 |
| `extraBrandKrw` | 넘는 브랜드 1개당 월 추가 요금 | (대표 결정) |
| 추가 브랜드가 늘리는 것 | 둘 중 고르기: ① 주 한도·월 크레딧을 브랜드 수만큼 곱함(브랜드마다 같은 양) ② 회사 전체 한도는 그대로, 브랜드 칸만 늘림(나눠 씀) | (대표 결정) — 원가 기준으로는 ①이 정직함(275차 상용화 시험 보기의 브랜드별 원가로 단가를 잡을 수 있음) |

단가를 정하는 방법(제안): 275차 '상용화 시험 보기'에서 브랜드 1개 한 달 원가(글 작성 원 + 생성 크레딧 × 70원)를 2~4주 모은 뒤, `extraBrandKrw` = 그 원가 ÷ 목표 원가율(예: 0.5). 숫자는 운영 기록이 쌓인 뒤 정한다 — 지금 쓸 수 있는 확인된 원가는 없음(확인 못함).

화면·동작
- 마케팅 › 브랜드 [브랜드 추가]: 포함 수를 넘으면 '이 브랜드부터 월 n원이 더해집니다' 확인 → 동의해야 만들어짐. 체험 중에는 0원(체험 끝나면 결제 화면에 줄로 보임).
- 사용량·요금제 화면: '브랜드 4 / 포함 3 · 추가 1개 월 n원' 한 줄.
- 결제: 다음 달 청구서에 '추가 브랜드 n개 × 단가' 줄(billing). 브랜드를 지우거나 합치면(#754) 다음 달부터 빠짐.
- 플랫폼 운영 › 마케팅 요금제: 두 칸(`brands_included`, `extra_brand_krw`) 추가 — 추가형 마이그레이션 1개.

구현량(결정 뒤): 마이그레이션·요금제 칸 0.5일 + 브랜드 추가 확인·사용량 줄 0.5일 + 청구 줄·시험 1일.

## 4. #819 게시물 수 기준 과금 안 (대표 10/31 "브랜드추가요금은 월마다 게시물 제작 갯수에 따라 달리가야하지 않은지?")

브랜드 수가 아니라 **한 달에 실제로 만든 게시물 수**로 요금을 매기는 안. 원가는 브랜드 수보다 제작 건수에 비례하므로(글쓰기 AI·이미지 크레딧이 건마다 듦) 원가와 요금이 같이 움직인다.

| 칸 | 뜻 | 값 |
|---|---|---|
| `postsIncluded` | 요금제에 든 월 제작 건수(피드·블로그·릴스 합 — 종류별 가중치는 아래) | 베이직 (대표 결정) · 스탠다드 (대표 결정) · 프로 (대표 결정) — 예: 지금 주 한도 × 4.3 = 프로 약 39건 |
| 구간 | 넘는 건수를 구간으로 청구 | 예: +10건까지 (대표 결정)원 · +30건까지 (대표 결정)원 · 그 위 1건당 (대표 결정)원 |
| 가중치 | 종류별 원가 차이 | 예: 피드·스토리 1 · 블로그 1.5(글 길고 사진 여러 장) · 릴스·쇼츠 3(영상) — 원가 기록으로 정함 |
| 브랜드 | 브랜드 수는 무료로 두거나 아주 낮게 | 브랜드를 늘려도 만드는 건수가 같으면 원가가 같으므로 |

세는 방법(제안)
- '제작 건수' = 그 달에 처음 원고를 만든 게시물(승인 대기로 올라간 것). 수정본(v2·v3)·[다시 그리기]는 세지 않음 — 대표 수정 요청이 많을수록 요금이 느는 건 불공정. 대신 다시 만들기는 지금처럼 월 횟수 한도(regen_monthly)로 막음.
- 반려·취소한 글도 셈(원가는 이미 듦) — 다만 우리 쪽 품질 검사에 걸려 자동으로 다시 만든 것은 세지 않음.
- 시험 브랜드([시험])·내부 회사는 세지 않음.

장단점
| 안 | 장점 | 단점 |
|---|---|---|
| 3. 브랜드 수 기준 | 고객이 이해하기 쉬움, 청구가 미리 정해짐 | 브랜드 1개로 많이 만드는 고객은 원가가 요금을 넘을 수 있음 |
| **4. 게시물 수 기준(구간)** | 원가와 요금이 같이 움직임(원가율 관리 쉬움), 브랜드를 자유롭게 늘릴 수 있음 | 달마다 청구액이 달라짐 → 사용량 화면에 '이번 달 n건 / 포함 m건 · 예상 추가 요금' 이 꼭 필요 |
| 섞기(추천 후보) | 요금제에 브랜드 몇 개 + 건수 몇 건 포함, 넘는 건수만 구간 청구 | 칸이 두 가지라 설명이 조금 길어짐 |

화면·동작(게시물 수 기준을 고르면)
- 사용량·요금제: '이번 달 제작 27 / 포함 39건(가중치 반영) · 남은 12건' 막대 + 넘으면 '추가 n건 · 예상 m원'.
- 포함 건수의 80%·100% 도달 때 관리자에게 알림 1건(돈 항목 — #823 기준 휴대폰 알림).
- 넘은 뒤 동작: 계속 만들고 다음 달 청구(기본) / 회사 설정 '포함 건수에서 멈춤'을 켜면 자동 제작 멈춤(#814-4 B안과 같은 사유 칸).
- 청구서: '추가 제작 n건 × 구간 단가' 줄.

구현량(결정 뒤): 월 건수 세기(가중치)·사용량 막대 0.5일 + 80/100% 알림·멈춤 설정 0.5일 + 요금제 칸 마이그레이션·청구 줄·시험 1일.

단가 근거: 275차 상용화 시험 보기의 '브랜드별 글 작성 비용 + 생성 크레딧' 을 건수로 나눈 **건당 원가**를 2~4주 모은 뒤 정하기를 추천(지금 확인된 건당 원가 없음 — 확인 못함).

5. 단가 — 원가 2~4주 모은 뒤 정하기를 추천
