# 아이폰에서도 소셜 로그인·가입·결제 (#853~#855) — 설계·공수 (코드 전, 2026-10-31 클라우드)

대표 원문: "카카오 네이버 구글 로그인은 왜 아이폰에서 안 쓰나요?" / "아이폰에서도 가입하고 요금 선택 및 결제가 있어야 하는데요?"
지금: 294차 = 아이폰 앱은 로그인만(심사 통과용). 이 문서는 결정용 — 대표가 고르기 전에는 코드 변경 없음. 294차는 그대로 둔다.

## 0. 한 장 요약 (대표 결정 3가지)

|---|---|---|

| ② 아이폰 가입·결제 | (가) 웹에서만 가입·결제, 앱은 로그인만(지금) · (나) 앱 안 가입 + Apple 인앱 결제 | 매출·수수료 판단 필요 — (나)는 수수료 15~30%, 공수 약 2주(클라우드 5~7일 + 로컬 3~4일) |
| ③ 안드로이드 | 앱 안 가입은 지금 열려 있음, 결제 화면은 숨김 | '요금제는 PC 웹에서' 안내 문구만 아이폰처럼 중립 문구로 바꾸기(1시간) — 구글 결제는 ②와 같은 결정 뒤 |

## 1. 'Apple로 로그인' (웹·아이폰·안드로이드 공통)

### 왜
App Store 4.8: 앱이 카카오·네이버·구글 같은 제3자 로그인을 쓰면, 이름·이메일만 받고 이메일을 숨길 수 있는 동등한 로그인(대표적으로 'Apple로 로그인')을 같이 제공해야 한다. 넣으면 아이폰 앱에서도 카카오·네이버·구글 버튼을 다시 켤 수 있다(294차의 아이폰 숨김 해제).

### 설정 (Apple 개발자 계정 — 로컬 안내, 키는 대표가 만들어 붙여넣기)
| 무엇 | 어디 | 누가 |
|---|---|---|
| 앱 ID에 'Sign in with Apple' 켜기 | Certificates, Identifiers & Profiles › Identifiers › 워크인 앱 | 로컬 |
| Services ID(웹 로그인용) + 도메인·돌아올 주소 등록 | Identifiers › Services IDs — 도메인 `work-in.dev`(·`app.work-in.dev`), 주소 `https://…/api/auth/oauth/apple/callback` | 로컬 |
| 키(.p8) 만들기 — 'Sign in with Apple' 체크 | Keys › + | **대표**(한 번만 내려받을 수 있음) → 운영 환경 변수에 직접 붙여넣기 |
| 이메일 중계(이메일 숨김 사용자에게 메일 보내기) | Services › Sign in with Apple for Email Communication — 보내는 도메인·주소 등록 | 로컬 |
| 운영 환경 변수 이름 | `APPLE_TEAM_ID` · `APPLE_SERVICES_ID` · `APPLE_KEY_ID` · `APPLE_PRIVATE_KEY` (값은 저장소에 쓰지 않음) | 대표가 Vercel 에 |

### 서버 (클라우드)
- `src/lib/oauth.ts` 제공자에 `apple` 추가: 시작 → Apple 인증 화면, **돌아올 때 POST(form_post)**, 클라이언트 비밀 = 키로 서명한 짧은 JWT(ES256), id_token 서명 검사(Apple 공개 키), `sub` = 사용자 고유 번호.
- 이름은 **처음 로그인 한 번만** 옴 → 그때 저장. 이메일은 숨김 주소(`…@privaterelay.appleid.com`)일 수 있음 → 회사 가입·초대 연결 규칙은 지금 소셜과 같음(같은 이메일 자동 합치기 안 함, 초대 링크로 들어오면 그 계정에 연결).
- 추가형 마이그레이션: `user_identities.provider` 허용값에 `apple` 더하기.
- 계정 삭제 때 Apple 토큰 해지(App Store 5.1.1(v) 요구) — 처음 로그인 때 받은 refresh token 을 암호화 보관 → 삭제 처리 때 `revoke` 호출.
- 아이폰 앱: 지금 구조(시스템 브라우저로 로그인 → 앱으로 돌아옴 `/auth/app`) 그대로 쓰면 **앱 네이티브 코드 변경 없음**. 더 매끄럽게 하려면 네이티브 Apple 로그인 플러그인(로컬, +1일) — 1차에는 불필요.
- 아이폰에서 버튼 순서: Apple 로 로그인 → 카카오 → 네이버 → Google(Apple 버튼은 Apple 디자인 규칙대로 검정/흰색).

### 공수
클라우드 1.5일(서버·화면·시험: 가짜 Apple 서버로 시작·콜백·이름 첫 회·숨김 이메일·삭제 해지) · 로컬 0.5일(Apple 설정·TestFlight 확인) · 대표 10분(키 만들기·붙여넣기).

## 2. 아이폰 앱 안 가입 + 결제 (App Store 3.1.1 인앱 결제)

### 규칙 요점 (2026-10 기준 — 약관은 바뀔 수 있어 반영 전 다시 확인)
- 앱 안에서 디지털 구독(워크인 요금제)을 팔려면 **Apple 인앱 결제만** 가능. 웹 결제 링크·'웹이 더 싸다' 안내는 앱 안에 둘 수 없음.
- 수수료: 기본 30%, 구독 1년 넘은 회원 15%, **소규모 사업자 프로그램(연 매출 100만 달러 미만) 15%**(대표가 신청). 한국 대체 결제(외부 결제 권한)는 26% + 별도 신청·보고 — 이득이 작아 권하지 않음.
- 웹에서 산 구독은 앱에서 쓸 수 있음(3.1.3(b)) — 단 앱 안에서도 같은 상품을 인앱 결제로 살 수 있어야 함.
- 대안(가): 앱은 '웹 서비스의 무료 동반 앱'(3.1.3(f)) — 앱 안에 구매·구매 유도가 없으면 인앱 결제 의무 없음. 지금 294차가 이 방식.

### (나)를 고를 때 상품 구성 — 1인 단가 × 인원은 Apple 상품으로 그대로 못 만듦
Apple 구독은 고정 가격 상품이라 '인원 수 × 단가'를 그대로 표현할 수 없다 → **회사 단위 인원 구간 상품**으로 나눈다.

| 상품(예) | 인원 | 월 가격 | 비고 |
|---|---|---|---|
| 스탠다드 5인 | ~5명 | Apple 가격표에서 가장 가까운 값 | 한 구독 묶음(subscription group) 안에서 단계(level)로 — 올리기는 즉시(남은 기간 비례), 내리기는 다음 갱신부터 |
| 스탠다드 10인 | ~10명 | 〃 | |
| 스탠다드 20인 · 30인 · 50인 | 〃 | 〃 | 50인 넘으면 '영업 문의'(앱 안에서는 안내만, 링크 없음) |

- 1차는 **요금제 1종 × 인원 5구간 × 월 단위**(5개 상품)로 시작 권장 — 3종 × 6구간 × 월·연 = 36개는 관리 부담이 큼.
- 가격: Apple 가격표(원화 단계) 안에서 고름. 수수료를 반영해 앱 가격을 웹보다 높게 둘 수 있으나 앱 안에 '웹이 더 쌈'은 못 씀.
- 14일 무료 체험: (a) 지금처럼 회사 단위 체험(우리 서버) 뒤 인앱 구독 또는 (b) Apple '무료 체험' 첫 구독 혜택 — (b)는 Apple 계정당 1번이라 회사 단위와 안 맞음 → (a) 권장.

### 서버 (클라우드)
| 부분 | 내용 |
|---|---|
| 회사 연결 | 구매 때 `appAccountToken` = 회사 id → Apple 이 거래에 그대로 돌려줌 → 서버가 그 회사에 구독 반영 |
| 거래 검증 | App Store Server API(인앱 구입 키 .p8 — 대표가 App Store Connect 에서 만들어 붙여넣기)로 거래 조회·서명(JWS) 검사 — Apple 공식 Node 라이브러리 |
| 갱신·환불·해지 | App Store Server Notifications V2 받는 주소(`/api/billing/apple/notify`): 갱신(DID_RENEW) → 기간 연장 · 갱신 실패(DID_FAIL_TO_RENEW, 유예 기간) → 지금 미납 규칙(7일 읽기 전용·30일 중지) · 환불(REFUND)·취소(REVOKE) → 그날로 요금제 내림 · 만료(EXPIRED) |
| 이중 결제 막기 | `tenant_subscriptions` 에 결제 경로(web·apple·google) 칸 추가(추가형). 웹 구독 중인 회사는 아이폰 구매 버튼 대신 "이미 구독 중입니다" · Apple 구독 중인 회사는 웹 결제 칸 대신 "App Store 구독 — 변경·해지는 아이폰 설정 › 구독" |
| 인원 한도 | 구간 상품의 인원을 회사 사용자 한도로 — 넘으면 지금처럼 초대만 멈추고 '구간 올리기' 안내 |
| 화면 | 아이폰 앱 › 관리 › 사용량: 구간 상품 목록·현재 구독·구간 바꾸기·구매 복원 — 앱 안 가입 화면(294차에서 막은 /signup)을 아이폰에서 다시 염 |
| 정산 | 플랫폼 운영 › 정산에 Apple 매출(수수료 뺀 금액은 Apple 보고서 기준 — 자동 대조는 2차) |

### 앱 (로컬 — mobile/ios)
- StoreKit 2 로 상품 목록·구매·복원·`appAccountToken` 넣기 — Capacitor 플러그인(직접 작성 권장, 외부 유료 서비스 RevenueCat 은 매출 일정액 넘으면 1% 수수료 + 거래 정보 외부 전송이라 회사 원칙상 비권장).
- App Store Connect: 구독 묶음·상품 5개·가격·현지화 설명·심사용 스크린샷, 샌드박스 시험 계정, TestFlight.

### 대표가 할 일
1. **유료 앱 계약** 서명 — App Store Connect › 비즈니스 › 계약(법인 정보·은행 계좌·세금 서류). 이것 전에는 인앱 결제 상품을 팔 수 없음(로컬 확인: 지금 미서명).
2. 소규모 사업자 프로그램 신청(수수료 15%).
3. 구간·가격 결정.
4. 인앱 구입 키(.p8) 만들기·붙여넣기.

### 공수
클라우드 5~7일(DB·검증·알림·이중 결제 막기·화면·가짜 Apple 서버 시험) · 로컬 3~4일(플러그인·상품 등록·샌드박스·TestFlight) · 심사 1~2회(인앱 상품은 앱과 같이 심사) · 대표 계약·서류(Apple 처리 며칠).

## 4. 권고 순서
1. 294차 유지로 1.2.0 심사 통과(대표 계약 동의 → 로컬 재제출).
2. 'Apple로 로그인' 추가 → 다음 판에서 아이폰 카카오·네이버·구글 다시 켬(대표 키 준비되면 바로).
3. 안드로이드 안내 문구 중립화(작음).
4. 인앱 결제는 대표가 수수료·가격·구간을 정한 뒤 — 정하기 전까지는 웹 결제 + 앱 로그인(동반 앱 방식) 유지.
