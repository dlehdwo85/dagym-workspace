# AI 처리를 국내(서울)에서 하는 길 — 조사 (2026-11-20)

요청: 대표 11/19 밤(노트북 전달) — "AI 내용이 미국으로 나간다"는 점이 고객 신뢰 문제. 국내 지역에서 같은 AI 를 쓰는 길이 있는지, 비용·작업량·기능 제약. **조사만 — 구현은 대표 결정 뒤.**
방법: 공식 문서(Anthropic · AWS · 구글 · 마이크로소프트)를 2026-11-19 에 읽어 확인(조사 담당 하위 작업). 실제 호출 시험은 하지 않았습니다(AWS 계정 없음). 코드 쪽 두 가지(문서 엔진 파일 삭제 없음 · 처리 지역 지정 없음)는 클라우드가 직접 다시 확인했습니다.

## 한 줄 결론
**조건부 가능.** "서울 안에서만 처리"되는 길은 지금 하나뿐입니다 — 아마존 베드록(Amazon Bedrock) 서울 리전의 '리전 내 추론'. 다만 쓸 수 있는 모델이 **한 세대 전 두 가지(Claude Sonnet 5 · Opus 5)** 뿐이고, 우리가 쓰는 웹 검색과 문서 만들기(엑셀·워드·PDF 파일 생성)는 그 길로 옮길 수 없습니다. Anthropic 자체 API · 구글 · 마이크로소프트에는 한국을 고르는 기능이 없습니다.

### ①(베드록 서울)을 고르면 달라지는 것
| 우리가 쓰는 단계 | 지금 | 서울 처리 | 차이 |
|---|---|---|---|
| 기본(AI 비서) | Sonnet 5.5 | Sonnet 5 | 한 세대 전 모델 · 약 +10% |
| 가벼운 작업(분류·요약 등) | Haiku 5.5 | Sonnet 5(서울에 가벼운 모델 없음) | **단가 약 22배** |
| 깊은 분석 | Opus 5.5 | Opus 5 | 약 +37.5% |

- 가벼운 작업으로 고정된 호출이 코드에 21곳 이상이라 비용 영향이 큽니다. 실제 영향은 운영 사용량(ai_usage) 비중을 봐야 압니다 — **확인 못함**.
- **모델 수명 위험**: AWS 는 서울 리전 내 추론을 '모델 선택이 제한된' 길로 지정했습니다. 새 모델이 안 나오거나 늦을 수 있고, Sonnet 5 는 2027-06-30, Opus 5 는 2027-07-24 이전에는 끝나지 않는다고만 보장합니다.
- 옮길 수 없는 기능: **웹 검색·웹 읽기**(AI 비서) · **문서 만들기**(엑셀·워드·PPT·PDF 생성 — Anthropic 의 실행 환경을 씀). 끄거나, "이 기능은 미국에서 처리"라고 따로 알리거나, 새로 만들어야 합니다(큰 작업).
- 그 밖에 바꿀 곳: 접속 설정(src/lib/ai/provider.ts 한 파일에 모여 있음) · PDF 크기 한도 낮추기(지금 20~25MB → 베드록 20MB 요청 제한) · AI 경로의 서버 리전을 서울로(지금 기본 리전은 싱가포르) · 동의 글의 받는 곳 변경 → 모든 사람에게 다시 동의 · AWS 계정·서울 리전 모델 사용 신청(대표·로컬 작업, 비용 발생).
- Claude 를 서울로 옮겨도 받아쓰기(OpenAI — 지금 운영에는 키 없음)·영상 내레이션·영상 생성 같은 다른 바깥 AI 는 그대로 나라 밖입니다.

## "어디서 처리"와 "남는가"는 따로
- **지금(Anthropic API)**: 입력·출력은 받은 뒤 30일 안에 자동 삭제(이용정책 위반으로 표시된 것은 더 오래). 기본적으로 AI 학습에 쓰지 않습니다. '보관 0' 계약은 영업 문의로 신청하는 방식이고, 우리가 쓰는 웹 검색·문서 만들기 일부는 그 대상이 아닙니다.
- **베드록**: 처리자는 AWS. 모델 회사(Anthropic)는 프롬프트·답에 접근하지 못한다고 AWS 문서에 적혀 있습니다. 사용량 기록도 그 리전에 한정됩니다.

## 조사하다 나온 것 — 지금 구조에서 따로 볼 두 가지
1. **문서 만들기에 올린 파일이 Anthropic 에 계속 남습니다(코드 확인).** 문서 엔진(src/lib/ai/docEngine.ts 68·99줄)이 참고 자료·결과 파일을 Anthropic 파일 보관소에 올리는데, **지우는 코드가 없습니다**(저장소 전체에 삭제 호출 없음). 올린 파일은 지울 때까지 남는 방식입니다. → 작업이 끝나면 지우도록 고치는 것을 권합니다(작은 작업, 서울 이전과 무관하게 신뢰 문제에 바로 도움). **→ 11/20 고침**: 새 작업은 끝날 때 사본을 지우고, 예전 사본은 관리 › AI 사용 내역의 [지금 지우기](대표)로.
2. **동의 글의 "Anthropic(미국)" 표현.** 우리 코드는 처리 지역을 지정하지 않습니다(inference_geo 없음 — 코드 확인). Anthropic 문서의 기본값 '전 세계'는 "어느 지역에서든 처리될 수 있음"입니다. 우리 계정(작업공간)의 기본 설정이 무엇인지는 **확인 못함** — 대표가 Anthropic 콘솔에서 봐야 합니다. 기본값 그대로라면 "미국"이라고만 적은 글은 정확하지 않을 수 있습니다. 길은 둘: ㉮ 미국 고정으로 설정(1.1배) ㉯ 글을 "미국 등 Anthropic 이 운영하는 지역"으로 고침.

## 대표가 정할 것
1. **목표가 무엇인지** — "서울 안에서만 처리"가 필요한가, "미국 회사에 내 자료가 남지 않는다"는 신뢰가 필요한가. 뒤쪽이면 서울 이전 없이도 ① 올린 파일 지우기 ② 보관 0 계약 문의 ③ 글 정리로 상당 부분 풀립니다.
2. 서울 처리로 간다면 감수할 범위 — 한 세대 전 모델 · 가벼운 작업 22배 · 웹 검색·문서 만들기는 서울 처리 불가.
3. 전부 바꿀지, 원하는 고객사만 켜는 **"국내 처리 모드"**(유료 선택 사항)로 둘지.
4. 모델 수명 위험(2027년 중반 이후 서울 후속 모델을 AWS 가 보장하지 않음)을 받아들일지.
5. AWS 계정 개설·서울 리전 사용 신청(비용 발생 — 대표 승인·로컬 작업).

## 클라우드 의견(추천)
- 지금 바로: **올린 파일 지우기**(위 1번)와 **동의 글의 지역 표현 확인**(위 2번)부터. 둘 다 작고, "유출되는 느낌"에 직접 답합니다.
- 서울 처리는 **선택형 "국내 처리 모드"**로 설계만 해 두고, 실제 수요(공공기관·대기업 고객의 요구)가 생길 때 여는 쪽을 권합니다. 전부 옮기면 모델이 한 세대 내려가고 비용이 크게 늘며 웹 검색·문서 만들기를 잃습니다.

## 확인 못한 것
- 실제 호출 시험(서울에서 Sonnet 5·Opus 5 가 되는지, 할당량) — AWS 계정이 없어 못 함.
- 공식 문서끼리 어긋나는 곳: Anthropic 문서의 베드록 리전 표는 서울을 '전 세계 묶음'만으로 적고, AWS 문서·가격표는 서울 리전 내 추론을 지원한다고 적습니다(AWS 쪽 세 자료는 서로 일치).
- 우리 요청 모양(프롬프트 캐시·베타 경로)이 베드록에서 그대로 받아들여지는지.
- 우리 Anthropic 작업공간의 기본 처리 지역 설정, 운영 Vercel 의 실제 리전, 저장소 위치.
- 개인정보 국외 이전·처리 위탁의 법적 해석(조사 범위 밖 — 필요하면 전문가 확인).
