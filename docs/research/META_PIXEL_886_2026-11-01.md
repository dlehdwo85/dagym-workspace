# 워크인 메타 픽셀 설계 (#886, 2026-11-01 클라우드)

상태: **설계 문서만.** 메타 픽셀 만들기, 이벤트 관리자 설정 바꾸기, 픽셀 ID 넣기는 모두 **대표 승인 뒤 로컬**이 합니다. 메타 설정 변경이라 회사 공통 원칙상 승인이 필요합니다.
근거: 로컬 11/01 메타 일시정지 초안 결과 — "메타 픽셀이 계정에 0개라 랜딩 조회 최적화·전환 측정이 안 됨. 설계만 문서로, 개인정보 보내지 않기".

## 1. 이미 있는 것 (#449, 운영에 반영됨)

| 항목 | 지금 동작 | 위치 |
|---|---|---|
| 픽셀 ID 넣는 곳 | 플랫폼 운영 › 가입 전환 태그 › 'Meta 픽셀'(숫자). 넣으면 바로 적용, 다시 배포 없음. 비어 있으면 빌드 환경변수 `NEXT_PUBLIC_META_PIXEL_ID` | `src/lib/conversionTags.ts` · `src/components/PlatformConversionTags.tsx` |
| 보내는 이벤트 | **가입 완료(회사 생성) 순간 1번** `CompleteRegistration` | `src/components/conversion.ts` `fireSignupConversion` |
| 동의 | 가입할 때 '광고 효과 측정' 선택 동의를 한 브라우저만. 동의 안 하면 픽셀 스크립트를 아예 불러오지 않음 | 가입 화면 · 개인정보처리방침 26행 |

| 앱 화면 | **넣지 않음**(업무 내용이 광고 회사로 가지 않게) | — |
| 우리 집계 | 소개 페이지별 방문 → 가입 → 공간 선택(311차) · 출처(utm)별 주간 표. 픽셀과 따로, 개인정보 없이 | 플랫폼 운영 › 가입 흐름 |

→ 픽셀 ID만 들어가면 **가입 완료 전환 측정은 바로 됩니다.** 코드 변경이 필요 없습니다.

## 2. 지금 안 되는 것

- **랜딩 페이지 조회 최적화**(Meta 광고 세트 '랜딩 페이지 조회'): 소개 페이지에서 `PageView` 가 픽셀로 가야 합니다. 지금은 소개 페이지에 픽셀이 없어서 이 최적화를 고를 수 없습니다.
- 가입 전환이 적은 동안(주 50건 미만)은 Meta 가 '전환' 최적화를 잘 못 합니다. 그동안은 '링크 클릭' 또는 '랜딩 페이지 조회' 최적화가 현실적입니다.

## 3. 제안 — 소개 페이지 조회 이벤트 (대표 결정 뒤 구현, 약 0.5일)

| 칸 | 내용 |
|---|---|
| 어디에 | **공개 소개 화면만**: `/`(로그인 전 소개 홈), `/landing/*`, `/signup` 첫 화면. 로그인 뒤 앱 화면·`app.` 주소에는 넣지 않음(지금 원칙 그대로) |
| 이벤트 | `PageView`(모든 소개 화면) · `ViewContent`(소개 페이지, `content_name` = 페이지 이름 예 `marketing-automation` — 우리 `landing_views` 와 같은 이름) · `CompleteRegistration`(지금 그대로 가입 완료 1번) |
| 보내지 않는 것 | 이메일·전화·이름·회사 이름·사용자 id(고급 매칭 **끔**) · 업무 내용 · 앱 화면 주소. 이벤트 관리자의 '자동 고급 매칭'·'자동 이벤트 설정'도 **끔**(로컬이 설정할 때) |
| 동의 | 아래 4번 대표 결정에 따름. 동의 전에는 픽셀 스크립트를 불러오지 않음 |
| 끄기 | 픽셀 ID 칸을 비우면 전부 꺼짐(지금과 같음) |
| 코드 | `conversion.ts` 에 `firePageView(page)` 추가 → `LandingEvents` 가 이미 부르는 `landingView(page)` 옆에서 부름(동의·ID 있을 때만). 같은 페이지 하루 1번(브라우저 쪽, 311차와 같은 방식) |
| 시험 | 가짜 서버 시험: 동의 없음 = `connect.facebook.net` 요청 0건 · 동의 + ID = `PageView`/`ViewContent` 1번씩, 앱 화면 이동에서는 0건 · 요청 본문에 이메일·이름 없음. 실제 수신 확인은 로컬이 이벤트 관리자 '이벤트 테스트'로(가짜 서버 통과를 실제 연동 완료로 보고하지 않음) |

## 4. 대표 결정 필요

1. **메타 픽셀을 만들지**(이벤트 관리자에서 픽셀 1개 — 비용 없음, 메타 설정 변경). 만들면 로컬이 ID 를 플랫폼 운영 › 가입 전환 태그에 넣습니다.
2. **소개 페이지 조회 이벤트(3번)를 넣을지**, 넣는다면 동의 방식:
   - A안(권장): 소개 화면 아래 작은 띠 "광고 효과 측정(Meta·Google) 쿠키를 허용할까요? [허용] [거부]" — 허용한 브라우저만 조회 이벤트. 지금 가입 동의와 같은 '먼저 묻기' 원칙. 허용 비율만큼만 측정됨.
   - B안: 개인정보처리방침에 행태정보 수집(Meta 픽셀)을 알리고, 거부 방법(띠의 [거부]·브라우저 설정)을 두는 '알리고 거부할 수 있게' 방식 — 측정은 더 많이 되지만 지금 원칙(먼저 묻기)보다 느슨함. 개인정보처리방침 고침이 같이 필요.
3. 광고 세트 최적화: 픽셀 전 = '링크 클릭' · 3번 반영 뒤 = '랜딩 페이지 조회' · 가입이 주 50건을 넘으면 = '전환(CompleteRegistration)'.

## 5. 하지 않는 것

- 전환 API(서버에서 Meta 로 보내기): 액세스 토큰(비밀값)이 필요하고 서버가 가입 정보를 다루게 되어 지금은 하지 않음.
- 앱 안 화면·업무·메신저 이벤트, 결제 금액 이벤트.
- 다른 회사(고객사) 화면의 픽셀: 이 픽셀은 워크인 소개 사이트 전용.
