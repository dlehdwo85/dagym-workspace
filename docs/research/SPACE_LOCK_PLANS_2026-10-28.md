# 요금제별 공간 잠금 설계안 (#546 · #251)

작성: 클라우드 223차 · 2026-10-28 · **대표 확인용 — 확인 뒤 구현**
관련: #546 '요금제별로 공간 잠금(업무만 결제 → 영업·마케팅 잠금)' · #251 '요금 구조 재검토(업무 인당 + 영업 사용자 인당 + 운영실 회사당)' · #622·#624 카드 등록 체험·요금표 시안 · 근태 Pro(ATTENDANCE_PRO_SCOPE_2026-10-26.md, 같은 틀로 잠금)

## 0. 한 줄 결론(권장)
**업무는 지금처럼 1인 요금, 영업은 '영업을 쓰는 사람 수'만큼 더하기, 마케팅은 회사당 월 요금 — 결제한 공간만 열리고 나머지는 자물쇠.** 체험 14일 동안은 전부 열림, 이미 만든 자료는 잠겨도 지우지 않음.

## 1. 지금 상태(사실)
| 항목 | 지금 |
|---|---|
| 공간 켜기 | 관리자가 회사 설정에서 영업·마케팅을 **무료로** 켜고 끔(`tenants.spaces`), 직원은 배정된 공간만(`space_members`). 업무는 늘 켜짐 |
| 업무 요금제 | 베이직 2,200 · 스탠다드 4,500 · 프로 8,500원(1인 월 · VAT 별도 · 최소 3인, 연간 1,800/3,600/6,800) — 요금제마다 업무 기능 차이(결재선·자료실·감사 로그 등) |
| 영업 | 가격 없음(켜면 무료) |
| 마케팅 | 마케팅 제작 요금제(베이직·스탠다드·프로 — 주간 제작 수·크레딧) 있음, **가격은 결정 전** |
| 체험 | 14일(카드 등록 체험 — #622 대표 결정: 가입 때 카드, 14일 뒤 결제) |
| 막는 방식 | 공간 밖 사람에게는 '없는 화면'(404). 요금 때문에 막는 장치는 없음 |

## 2. 요금 구조 — 세 가지 안
| 안 | 내용 | 좋은 점 | 아쉬운 점 |
|---|---|---|---|
| **A(권장) 공간별 더하기** | 업무 1인 요금(지금 3단계) + 영업 공간 이용자 1인당 □원 + 마케팅 회사당 월 □원(=마케팅 요금제 가격) | #251 방향 그대로 · 필요한 공간만 사서 이탈 적음 · 영업팀이 2명이면 2명분만 | 화면에 '공간 추가' 단계가 하나 더 생김 |
| B 요금제에 묶기 | 베이직 = 업무만 · 스탠다드 = 업무+영업 · 프로 = 업무+영업+마케팅 | 고르기 쉬움 | 마케팅만 필요한 회사가 프로를 사야 함, 영업 1명 쓰려고 전원 스탠다드 |
| C 지금처럼 전부 포함 | 잠금 없음 | 만들 것 없음 | 영업 수집기·마케팅 제작 원가(AI·크레딧)를 업무 요금이 떠안음 |

> 단가(□)는 대표 결정. 숫자가 정해지기 전에는 화면에 '결정 전'으로 둡니다(지금 마케팅 요금제처럼).

계산 예(A안, 단가는 자리만): 직원 10명 스탠다드 + 영업 담당 3명 + 마케팅 베이직
= 4,500 × 10 + (영업 □ × 3) + (마케팅 베이직 □) → 결제 화면에 줄마다 나눠 표시.

## 3. 잠금 동작(화면·서버)
1. **열린 공간** = (체험 중이면 전부) 또는 (결제한 공간) 또는 (플랫폼 운영이 열어 준 공간). 업무는 늘 열림. 우리 회사·데모는 전부 열림.
2. **공간 바꾸기 메뉴**: 잠긴 공간은 자물쇠 표시. 누르면 안내 화면 — 이 공간에서 하는 일 3줄 + 관리자: [요금제에 추가] / 직원: [관리자에게 요청](관리자에게 알림 1건).
3. **서버**: 잠긴 공간 주소·API 는 **403 + '이 공간은 요금제에 없습니다'**(지금의 404 는 '배정 밖 사람'에게만 그대로). 고객 화면 문구에 원가·외부 서비스 이름은 쓰지 않음(#602).
4. **자료**: 잠겨도 **지우지 않음**. 다시 추가하면 그대로 열림. 보관 기간은 대표 결정(제안: 잠긴 뒤 1년, 지우기 30일 전 관리자 알림).
5. **정기 작업 멈춤**: 잠긴 공간의 수집기·당일 공고 메일·자동 제작·예약 게시·광고 성과 읽기는 멈춤(원가가 나가지 않게). 예약 게시가 걸려 있으면 잠기기 3일 전 관리자 알림.
6. **알림**: 잠긴 공간에서 생기는 알림은 보내지 않음(이미 온 알림은 보관함처럼 남김).
7. **체험 끝**: 결제한 공간만 남기고 잠금. 체험 13일째 알림에 '영업·마케팅을 계속 쓰려면 요금제에 추가' 한 줄.
8. **설계 파트너**(결정 15-30): 기간 동안 전부 열림, 끝나면 일반 규칙.

## 4. 영업 이용자 세는 법(A안)
- 영업 공간에 배정된 **활성 직원 수 + 영업을 켠 관리자**(관리자도 배정 칸에서 '영업 씀' 체크 — 안 쓰는 관리자는 세지 않음).
- 결제 인원보다 많이 배정하려 하면 배정 칸에서 '영업 이용자 n명까지(결제 기준)' 안내 + [인원 늘리기].
- 늘리기는 다음 결제일부터 반영(중간 정산 없음 — 단순하게). 줄이기도 다음 결제일부터.

## 5. 자료 구조(추가형, 구현 때)
- `tenant_subscriptions.space_plan jsonb` — `{ sales: { seats: 3 }, marketing: { plan: 'basic' } }` (결제 기준)
- `tenants.space_grants jsonb` — 플랫폼 운영이 열어 준 공간과 끝나는 날 `{ sales: '2026-12-31' }`
- 서버 한 곳 `openSpaces(tenant)` = 업무 + 체험이면 전부 + space_plan + space_grants(기간 안) → `assertSpace` 가 여기에 묶임(잠김 = 403, 배정 밖 = 404)
- 정기 작업(jobs.ts)은 회사마다 `openSpaces` 를 보고 건너뜀
- 플랫폼 운영 › 고객사 창: 공간 열어 주기(기간) · 지금 열린 공간 · 영업 결제 인원

## 6. 기존 고객사 이행
- 배포 날 이미 영업·마케팅을 켠 회사는 **다음 결제일까지 그대로 열림**(유예) + 관리자에게 '다음 결제일부터 요금제에 추가해야 계속 열림' 알림 1건. 유예 기간 동안 [요금제에 추가]를 누르면 끊김 없음.
- 우리 회사(default)·데모·설계 파트너는 영향 없음.

## 8. 대표 결정 필요
1. 구조: **A(권장)** / B / C
2. 영업 공간 1인당 월 단가 □원(연간 할인 같은 비율?)
3. 마케팅 회사당 월 단가 □원(= 마케팅 요금제 베이직·스탠다드·프로 가격)
4. 잠긴 공간 자료 보관 기간(제안 1년)
5. 영업 이용자에 관리자 포함 방식(제안: 관리자도 '영업 씀' 체크한 사람만)
