# WORKIN V21 — 문의 → 업무 → 자료 첨부 → 메일·문자 시안 확인 → 사용자가 보내기 (2026-10-15 대표 지시)

V19(견적서·문자 A)를 이 흐름에 합친다. V19 부록 A(AI 비서 입력 개선)는 별개로 먼저 진행.

## 0. 원칙
- AI·자동화는 **초안만**. 실제 발송은 사람이 시안을 본 뒤 [보내기]를 눌러야만 한다(서버에서도 "사람이 누른 요청"만 발송).
- **상업화 전제**: 다짐·하이링크 값을 코드에 박지 않는다. 회사 정보·명함·메일 계정·양식은 모두 조직 설정(DB)에 두고, 다른 고객사도 자기 값으로 쓰게 만든다.
- 비밀값(메일 앱 비밀번호)은 저장소·로그·화면에 절대 노출하지 않는다. 암호화 저장, 입력은 사용자가 직접.

## 1. 문의 → 업무
- 홈페이지 문의: 지금 연동 그대로(업무+CRM 고객 자동, V16).
- 대표번호 전화 문의: (a) 업무 화면·홈 [전화 문의 등록] — 이름·연락처·소속(아파트명 등)·내용 → 업무+CRM 고객 생성, 문의 단계(BASE_STEPS) 그대로. (b) AI 비서에 말로 등록("방금 OO아파트 위탁 문의 전화").
- 통신사·ARS 통화기록 자동 연동은 2단계(범위 밖).

## 2. 업무 안 "보낼 자료"
- 업무 상세에 "보낼 자료" 칸: [자료실에서 고르기](검색·폴더, 권한 있는 자료만, 기밀 자료는 권한자만), [견적서 작성](V19 2장 회사별 양식, 다짐 1페이지), [파일 올리기].
- AI 추천: 문의 내용·고객 종류를 보고 자료실에서 맞는 자료(회사소개서·제안서·견적서 양식) 상위 3개 추천 → 사용자가 체크.

## 3. 메일 보내기
### 3.1 시안
- [메일로] → AI 가 받는 사람(CRM 고객 이메일)·제목·본문 초안 작성. 종류별 기본 문구 양식(견적 안내·제안서 송부·공문 송부·용역비 청구·자료 송부)을 조직 설정에 두고 AI 가 고른다. 양식은 내용이 없어도 됨 — 대표 기준 "양식 = 하단 명함 카드".
- 시안 화면 = 실제 나갈 모습 그대로: 보내는 주소, 받는 사람/참조, 제목, 본문(명함 카드 포함 HTML 미리보기), 첨부 목록·용량. 편집 가능. [보내기]는 기본 대표 + 권한 받은 사람(설정 > 사용자 관리, V19 와 같은 권한).

### 3.2 명함 카드(서명) — 대표 지시
- 현재 회사 메일(보낸메일함 일부)에 쓰는 명함 카드 구성: 왼쪽 회사 로고 | 이름 + 직급 / 회사명 / 전화 / 이메일 / 웹사이트 / 하단 로고, 아래 회사 소개 한 줄, 맨 아래 비밀유지 안내문(국/영).
- 바꿀 점: **APART LINK(아파트링크) 로고·링크·문구 삭제, HI-LINK 만 사용. 주소 줄 추가 = 하이링크 주소**(조직 설정의 하이링크 사업장 주소: 경기도 화성시 동탄중심상가1길 36, 8층 801-제이12호).
- **보내는 사람에 맞춰 자동**: 이름·직급·연락처·이메일은 보내는 사용자의 프로필에서 채운다(직급은 사용자 관리의 직함 필드). 프로필에 연락처·직급이 비어 있으면 첫 발송 때 한 번 물어 프로필에 저장(학습). 대표 휴대폰 등 개인 연락처는 DB 에만, 저장소·문서에 쓰지 않는다.
- 설정 > 회사 정보 > "메일 명함" 편집기: 로고 업로드(R2), 회사명·주소·웹사이트·소개 문구·안내문, 미리보기. 회사(다짐/하이링크)별로 하나씩, 메일 시안에서 회사 선택에 따라 바뀜. 메일 HTML 은 표(table)+인라인 스타일, 이미지는 첨부 CID 또는 공개 URL(메일 클라이언트 호환). 기존 카드의 로고 원본은 로컬 세션이 설정 화면이 생기면 업로드한다.

### 3.3 발송 경로 — 회사 메일함 SMTP
- 다짐·하이링크 **모두 dagym-in@naver.com 에서 발송**(대표 결정). 보낸 메일이 네이버 보낸메일함에 남고 답장도 회사 메일로 오게.
- 조직 설정 > 메일 계정 연결: 제공자 프리셋(네이버 메일, 네이버웍스, 다음, Gmail 앱 비밀번호, Microsoft 365, 직접 입력 SMTP) — 상업화용. 계정·앱 비밀번호 입력 → [연결 시험](시험 메일 1통 자기에게) → 성공해야 저장.
- 앱 비밀번호는 서버 암호화(환경변수 마스터키로 봉투 암호화), 화면엔 "연결됨 · 마지막 성공 시각"만.
- **끊김 방지(대표: 예전 SMTP 가 자꾸 끊겼음)** — 반드시 반영:
  1. **발송 함수 지역 = 서울(icn1)**. 네이버는 해외 IP 로그인을 막거나 보안 확인을 거는 경우가 많다(Vercel 기본 미국 지역이 원인일 수 있음). 메일 발송 라우트·작업만 `preferredRegion = 'icn1'`.
  2. **보관함(outbox) 방식**: [보내기] = DB `outbox` 에 "보내는 중"으로 저장하고 바로 응답 → 백그라운드에서 발송. 화면엔 상태(보내는 중/보냄/실패) 실시간.
  3. 연결은 발송마다 새로 열고 닫기(오래 붙잡지 않음), 연결·인사·전송 단계별 타임아웃(10/10/60초).
  4. 일시 오류(연결 끊김·시간 초과·421·4xx)는 1분·5분·15분 3회 자동 재시도, 인증 실패(535)·주소 오류(5xx)는 재시도 없이 즉시 "실패 — 이유" 표시 + 메일 계정 화면 안내.
  5. **중복 발송 금지**: outbox 행마다 고정 Message-ID, 재시도 전 상태 확인, 같은 행 동시 처리 잠금.
  6. 네이버 한도 대비: 첨부 합계 10MB 넘으면 자동으로 기간 링크(14일, R2 서명 URL 대신 워크인 다운로드 페이지 — 열람 기록)로 바꿔 본문에 넣기. 받는 사람 수·하루 발송 수 제한 안내.
  7. 실패 시 대표에게 알림 + [다시 보내기].
- 네이버에서 SMTP 로 보낸 메일이 보낸메일함에 저장되는지 연결 시험 때 확인(설정 항목 있으면 안내).
- **연결 설정은 로컬 세션이 대표 화면을 직접 띄워 함께 진행**(네이버 환경설정 > POP3/SMTP 사용, 2단계 인증 앱 비밀번호 발급 → 워크인 설정에 대표가 직접 붙여넣기). 기능 배포되면 로컬에 알려 주세요.

## 4. 문자 보내기
- V19 1장 A 방식(휴대폰 문자앱으로 넘김) 그대로. 첨부는 3.3-6 의 다운로드 링크를 본문에 넣는다. 명함 대신 문자 끝에 "이름 직급 / 회사 / 대표번호" 한 줄.
- 유료 문자 서비스(B)는 상업화 때 조직별 연결로(범위 밖, 구조만 채널 추상화로 열어 둘 것).

## 5. 기록·연동
- 발송 기록: 업무 타임라인 + CRM 고객 기록 — 채널, 보낸 사람, 받는 사람, 제목, 첨부 이름, 시각, 상태, 본문 사본.
- CRM 단계 자동 체크: 제안서·자료 첨부 메일 발송 → "자료/제안서 발송", 견적서 포함 → "견적".
- 열람 기록: 다운로드 링크가 열리면 업무에 "고객이 자료를 열어봄" 표시(메일 열람 추적 픽셀은 쓰지 않음).

## 6. 상업화 고려(공통)
- 채널 인터페이스(`email:smtp`, `sms:handoff`, 추후 `sms:provider`, `kakao:alimtalk`)로 분리.
- 조직별 메일 계정·명함·양식·권한, 요금제별 한도(월 발송 수·첨부 용량), 감사 기록(누가 무엇을 보냈나).
- 다른 조직 데이터는 404(기존 원칙), 발송 로그는 조직 밖으로 안 나감.

## 시험
- 문의 업무 → 자료실 자료 2개 + 견적서 → 메일 시안: 명함에 보내는 사람 이름·직급·연락처, HI-LINK 만, 하이링크 주소, APART LINK 없음.
- 대표 외 사용자는 [보내기] 없음(서버 403).
- SMTP: 모의 서버로 연결 끊김→재시도 성공, 535→즉시 실패, 같은 행 두 번 처리해도 1통만. (실제 네이버 연결은 로컬 세션이 대표와 확인 — 가짜 서버 통과를 실제 연동 완료로 보고하지 않음.)
- 첨부 12MB → 링크로 바뀜, 링크 열람 기록.
