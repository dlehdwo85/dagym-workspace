# WORKIN V33 — 알림 바로 처리 · 공식 도메인 · 관리자 안내 · 직원 회사 메일 (2026-10-16 대표)

## 1. 알림에서 바로 처리 (카카오톡·네이버 메일 참고, 워크인에 맞게)
대표: "알림 올 때 보기·읽음(앱으로 들어가진 말기 — 내용을 터치해야만 들어가기). 검토 요청이면 승인 → 알림에서도 간단하게 업무를 볼 수 있도록."
### 1-1 앱 푸시(휴대폰 알림창)
- 알림 본문을 누르면 해당 화면으로 들어감(지금처럼). **알림 아래 버튼(액션)**: 종류별로
  - 공통: [읽음] — 앱을 열지 않고 읽음 처리(배지 감소).
  - 업무 배정·멘션·댓글: [읽음] [답글](알림창에서 바로 한 줄 답글 입력 → 댓글 등록).
  - 검토 요청: [승인] [읽음] — 승인은 확인 단계 필요 시 앱 열림(실수 방지 설정: 회사 설정 "알림에서 바로 승인 허용" 기본 켬, 반려는 사유가 필요하니 앱에서).
  - 마감 임박: [완료] [하루 연장](V32-4 연장 사유 "알림에서 연장" 자동) [읽음].
  - 메시지: [읽음] [답장](한 줄).
- 같은 업무 알림은 묶어서 표시(그룹 키), 업무 제목·담당·마감을 본문 2줄에.
- 구현: 서버 FCM 메시지에 category/actions 데이터 + 1회용 액션 토큰(알림 id·사용자·만료 24h) → 액션 API(/api/notifications/action) 가 토큰 검증 후 처리. 네이티브(로컬): Android NotificationCompat action 버튼·RemoteInput(답글), iOS UNNotificationCategory(UNTextInputNotificationAction) — Capacitor 푸시 플러그인 액션 이벤트 처리.
### 1-2 웹·앱 안 알림 화면(종 아이콘)
- 항목 줄마다 오른쪽에 작은 버튼: [읽음] / 검토 요청이면 [승인] / 마감이면 [완료]. 항목을 **길게 누르기(휴대폰)/펼치기(▾)** 로 업무 미리보기(제목·설명 3줄·담당·마감·첨부 수·최근 댓글 1개) — 들어가지 않고 확인. 미리보기 안에서 [승인] [반려] [답글] [업무 열기].
- 스와이프(휴대폰): 왼쪽 = 읽음, 오른쪽 = 보관(숨김). [모두 읽음].
- 읽음 표시: 카카오톡처럼 안 읽은 건 굵게+점, 읽으면 흐리게(전체 탭).

## 2. 공식 도메인 www.work-in.dev
- 상태: Vercel 연결·SSL 완료(work-in.dev → 308 www.work-in.dev, /api/health 200). 카카오 JS 도메인·로그인 리다이렉트에 www.work-in.dev 추가 완료(로컬).
- 클라우드 작업:
  - APP_URL 을 www.work-in.dev 로 바꾸기 전에 **OAuth 리다이렉트·쿠키를 요청 출처(req origin) 기준으로**: 앱(WebView, 지금 vercel.app 로딩)과 웹이 서로 다른 도메인에서 로그인이 깨지지 않게. 메일·문자·공유(/d/)·영수증·초대 링크는 www.work-in.dev.
  - 브라우저로 vercel.app 에 오면 www.work-in.dev 로 308(앱 WebView·/api·/.well-known·OAuth 콜백 제외).
  - .well-known(assetlinks·AASA)을 www.work-in.dev 에서도 응답.
  - 메일 발송 도메인 mail.work-in.dev(Resend) — Resend 가입·DNS 는 로컬+대표.
- 로컬 작업: 다음 앱 빌드에서 Capacitor APP_URL·allowNavigation·Android 앱 링크 host·iOS Associated Domains 를 www.work-in.dev 로(기존 vercel.app 도 유지), Naver·Google 로그인 콘솔 리다이렉트 추가.
- 순서: 클라우드 OAuth/쿠키 출처 처리 배포 → 로컬 Vercel APP_URL 변경·재배포 → 확인 → 앱 빌드 전환.

## 3. 관리 메뉴 안내 (관리자만)
- 직원 초대·연동 설정 화면과 관리 메뉴 전체에 안내: "관리 메뉴는 회사 관리자(대표·관리자 권한)만 볼 수 있습니다. 직원에게는 보이지 않습니다." — 관리 메뉴 머리 한 줄 + 초대·연동 화면 상단 배지. 직원 계정에서 관리 주소로 들어오면 "관리자만 볼 수 있는 화면입니다 — 관리자에게 요청하세요"(지금 404/빈 화면이면 교체).

## 4. 직원이 자기 회사 메일 계정으로 보내야 할 때
- 기본: 회사 기본 방식(워크인 발송 또는 회사 계정)으로 보내고 Reply-To = 직원 업무 이메일(가입 이메일).
- 직원이 **자기 회사 메일 계정(예: kim@회사도메인)** 으로 직접 보내야 하면: 설정 > 내 메일 계정 > [내 메일 계정 연결](V28 B1) — Gmail/Microsoft 365 는 OAuth(심사 후), 네이버웍스·다음·회사 메일 서버는 SMTP(주소·앱 비밀번호, 단계 안내). 연결되면 그 직원 발송은 본인 계정으로, 보낸메일함에도 남음.
- 관리자 정책(회사 설정): "직원 개인 메일 계정 연결 허용" on/off, 허용 도메인 제한(예: @회사도메인만), 연결 현황 목록(누가 어떤 주소로 연결했는지, 비밀번호는 보이지 않음).
- 가입 시: 회사 메일 주소로 가입한 직원은 그 주소가 업무 이메일·Reply-To 로 자동. 개인 메일(gmail 등)로 가입했으면 프로필에서 업무 이메일 따로 입력 안내.
