상태 변경 규칙:
- 승인: 같은 버전만, 이미 예약됨·게시됨이면 거부 (`:207-215`). 화면 버전이 옛 버전이면 “v3이 최신입니다 — 새로고침” 오류 (`:202`).
- 수정 요청: **메모 2자 이상 필수**, 예약됨·게시됨이면 거부(플랫폼 예약 먼저 취소). 대표 요청(submitRequest)으로 만들어 Claude가 가져감 (`:218-232`).
- 예약됨/게시됨 기록: Claude 세션만. 근거(evidence) 3자 이상 필수, 게시됨은 `https` 공개 주소 필수, 승인 없이 기록 불가 (`:235-249`).

### 2-2. 승인함 (`approvals`) — `route.ts:637-639`, `lib/owner-board-view.ts`

화면 순서: ① 맨 위 링크 “승인한 게시물 보기 · 게시 전 수정 요청 →”(일일 기록 화면으로) ② **승인 대기** 묶음 ③ 접힌 “Claude 처리 현황 — 운영 점검 몫 (대표 할 일 아님)”.

승인 대기 묶음 (`owner-board-view.ts:248-283`):
- 숫자 = 승인 가능한 게시물(잠금 없음) + 마감 안 지난 ‘승인 대기’ 일일 콘텐츠 (`:252-260`). 이 숫자가 메뉴 배지·홈 숫자와 같다 (`route.ts:611`).
- 게시물·일일 콘텐츠를 **게시 예정 시각순 한 목록**으로 섞는다 (2026-10-13, `:269-274`). 처음 3장만 펼치고 “N건 더 보기” (`:227-235`).
- 비었을 때: “지금 승인할 최종 시안이 없습니다.” (`:281`)
- 맨 아래 접힘: “Claude 작업 중 N건 — 시안 제작·검수·반영 (대표 할 일 아님)” = 잠긴 게시물 + **마감 지난 일일 콘텐츠**(“승인 마감 지남 — 일정 재배치 필요 (운영실)”) (`:275-278`).

### 3-2. 승인 마감 규칙
- **게시 당일 09:00 KST**까지 승인한 항목만 09시대 Claude 예약 세션이 플랫폼에 예약한다. 게시 시각이 09:00보다 이르면 그 시각이 마감 (`daily-content.ts:22-23, 96-99`).
- 화면 문구: “10/19(일) 09:00까지 승인하면 18:00 게시” (`:100-104`). 세션용 문구 `deadlineRule` = “게시 당일 09:00 KST까지 승인된 항목만 예약” (`:256`).
- 마감 지나면 `late` → 홈·승인함 숫자에서 빠지고 “Claude 작업 중”에 “승인 마감 지남 — 일정 재배치 필요 (운영실)”로 들어간다 (`owner-board-view.ts:254, 259, 277`). 일일 기록 화면에는 빨간 “마감 지남 — 다음 날로 이동 필요”로 남는다.
- 일일 제작은 노트북 Claude 앱 예약 작업이 매일 13:00에 3일 뒤 분을 만든다 (`docs/WORK_STATUS.md:137-140`).

### 3-3. 운영실 안의 알림 (종)
- 저장 `mkt:notifications:v1`, 최대 300건. 이벤트 알림(제작 완료 등)과 상태 알림(결정 대기·게시 임박 등)을 같은 키로 한 건만 유지하고, 원인이 사라지면 자동 ‘해결됨’ (`lib/marketing-execution/notifications.ts:1-11, 37-41, 61-62`).
- 종류 15개 → 탭 5개: 결정 · 요청 · 제작 · 게시 · 연결 (`:15-31`, 이름 `:185-201`).
- 숫자 = **해결 전** 대상 수(같은 대상 1번). 읽어도 해결 전이면 남는다. ‘새 N’ = 안 읽은 것 (`:74-92`; `route.ts:325-340`).
- 상태 알림은 화면을 열 때마다 계산·동기화 (`route.ts:522`, `lib/ops-status.ts:84`~).
- `POST /api/marketing/notifications` 는 **‘모두 읽음’만** 한다 (`app/api/marketing/notifications/route.ts`).
- 한계: 일일 콘텐츠 승인 대기·마감 임박은 **이 알림에 없다** (`deriveConditions`가 일일 항목을 보지 않음, `ops-status.ts:84-140`). 외부 푸시·카카오는 없다 (`notifications.ts:11`).

### 3-4. 승인 마감 알람 (예약 작업)
- 점검 스크립트 `scripts/ops/approval-deadlines.mjs` (읽기 전용, 2026-10-18 `b7e9a55`): 오늘부터 7일(`--days`)의 일일 항목 중 승인·예약됨·게시됨이 아닌 것 + ‘대표 확인 필요’·‘재승인 대기’ 요청 카드를 뽑아 “[마감 MM-DD HH:MM] 날짜 시각 브랜드 채널 — 제목 (상태·재승인)” / “[마감 지남] …”으로 출력 (`:11-32`). 조회는 `by: approval-deadline-watch`라 ‘전달’로 기록되지 않는다 (`:23-24`).
- 이 스크립트를 쓰는 알람 시각은 저장소 코드가 아니라 노트북 Claude 앱 예약 작업이다. 문서상 운영값: **13:30**(13:00 제작 직후) · **21:30**(전날 저녁 미리 알림) 2개, 대표 1명. 목표 규칙은 “제작 완료 즉시 + 마감 6시간 전, 야간(22~08) 무알림 → 직전 저녁” (`docs/marketing/COMMERCIALIZATION_READINESS_2026-10-18.md:59`). 예약 작업 설정 파일은 저장소에 없다 — 노트북 앱에서 확인 필요.

### 3-5. 대표 화면에서 빼는 상태
- `ownerEntries = allEntries.filter(e => e.status !== "실행 불가 또는 일정 재검토 필요")` (`route.ts:517`). 2026-10-16 대표 지시 “대표는 승인·수정 요청만” — 이 상태는 운영 점검·Claude 쪽에서만 다룬다 (`route.ts:557-558`, 커밋 `d4aaba6`).
- 대표 보드(홈·승인함)도 `ownerEntries`로 만든다 (`route.ts:526-528`). 운영 점검·알림 계산은 전체(`allEntries`)를 쓴다 (`route.ts:518`).
- 승인함의 막힘·질문·진행은 “Claude 처리 현황 — 대표 할 일 아님”으로 접는다 (`route.ts:638-639`).

### 3-6. 운영실 쪽 주의 (워크인이 그대로 옮기지 말 것)
- 브랜드 탭이 ‘바디랩’일 때 일일 콘텐츠가 승인함·홈에서 빠진다 — 필터가 하이링크·다짐만 처리 (`route.ts:608`).
- 일일 카드에 `credits`(제작 크레딧)가 안 보인다.
- 게시 일정·게시 결과 화면에 일일 콘텐츠가 없다 (2-4, 2-5).

## 5. 워크인 마케팅 공간 점검 체크리스트

승인함·카드
- ☐ 승인함 항목마다 브랜드 칩 (하이링크·다짐·바디랩·워크인)
- ☐ 채널 라벨 (인스타 피드+페이스북 · 네이버 블로그 · 인스타 릴스 · 유튜브 쇼츠)
- ☐ 형식 짧은 라벨 (피드 · 블로그 · 릴스 · 쇼츠)
- ☐ 제목 + 게시 날짜·시각 (“오늘 18:00 / 내일 10:00 / 10/21(화) 10:00”)
- ☐ 마감 시각 문구 “○○ 09:00까지 승인하면 HH:MM 게시”
- ☐ 마감 규칙 = 게시 당일 09:00 KST (게시가 더 이르면 게시 시각)
- ☐ ‘마감 지남’ 빨간 표시 + 승인 숫자에서 제외 + “일정 재배치(운영실)”로 이동
- ☐ 버전 `vN` 표시
- ☐ 재승인 표시 “재승인 (v2 수정 요청 → v3)”, 예전 승인이 새 버전에 이어지지 않음
- ☐ 상태 칩 5가지 (승인 대기 · 승인됨 · 예약됨 · 게시됨 · 수정 요청) + 실패, 색 규칙(주황·파랑·초록·빨강·회색)
- ☐ 이미지 전 장 넘기기 · “1 / N” · 크게 보기 · 영상은 커버 먼저
- ☐ 문안 채널별 (인스타·페이스북·블로그 제목/본문·유튜브 제목/설명) + 해시태그
- ☐ 제작 메모
- ☐ 결정 기록 한 줄 (상태 · 시각 KST · 수정 메모 · 예약 근거 · 게시물 열기 링크 · 요청 번호)
- ☐ 게시물·일일 콘텐츠를 게시 시각순 한 목록으로 섞기
- ☐ 처음 3장만 펼치고 “N건 더 보기”
- ☐ 승인 못 하는 카드는 버튼 대신 이유 (검수 중 · 시안 준비 중 · 이미지 3~5장 아님)
- ☐ 빈 상태 문구 (“지금 승인할 최종 시안이 없습니다.”)

버튼·규칙
- ☐ [승인] 한 번에 저장, 새로고침 없이 카드만 “✓ 승인됨”
- ☐ [수정 요청] 메모 필수(2자 이상) → 요청함으로 → 새 버전 → 다시 승인
- ☐ 승인한 뒤에도 예약 전까지 ‘게시 전 수정 요청’
- ☐ 예약됨·게시됨 이후 승인·수정 요청 막기
- ☐ 옛 버전 화면에서 누르면 “최신 vN — 새로고침” 거부
- ☐ 예약됨 기록엔 근거, 게시됨 기록엔 https 공개 주소 필수
- ☐ 승인 ≠ 게시 안내문 (승인 뒤 예약 세션이 올림)

홈 ‘오늘’
- ☐ 머리줄 “승인할 시안 N건” / “지금 할 일 없음 ✓” + 날짜·브랜드
- ☐ 오늘 승인 요약 (오늘 게시분 먼저, 7건 + 나머지 펼치기)
- ☐ 오늘 게시 요약 카드 (시각 · 브랜드 형식 · 제목 · 예정/승인 대기/예약됨/게시됨/실패/지연, “게시됨 N”)
- ☐ 오늘 게시가 없으면 “다음 게시: …” 한 줄
- ☐ **오늘 제작 요약 카드** (운영실에도 없음 — 제작 시각 필드를 새로 둘 것)
- ☐ 메뉴 배지 = 승인 대기 숫자 = 홈 숫자 = 승인함 숫자 (같은 계산)
- ☐ 대표 화면에서 ‘실행 불가·재검토’·기술 오류 숨기고 운영 쪽에만

일일 기록·일정·결과·자료실
- ☐ 일일 기록: 날짜별 묶음(“오늘” 표시, 건수) · “7일 안 N · 승인 대기 N · 마감 지남 N” · 다음 주 이후 건수
- ☐ 지난 날짜 항목도 볼 수 있게 (운영실은 오늘부터만 — 개선점)
- ☐ 게시 일정: 이번 주 목록(날짜·시각 · 브랜드 · 채널별 시각 · 상태) + 14일 예약된 게시
- ☐ 게시 일정에 일일 콘텐츠도 포함 (운영실은 빠져 있음 — 개선점)
- ☐ 게시 결과: 브랜드 · 채널 · 제목 · 상태 · 시각 · 공개 주소 / 실패 사유, 채널 탭·상태 필터+건수
- ☐ 게시 결과에 일일 콘텐츠 공개 주소도 (운영실은 빠져 있음 — 개선점)
- ☐ 자료실: 브랜드 탭+건수 · 여러 파일 끌어다 놓기 · 태그 · 메모 · 사용 횟수 · 큰 영상 조각 업로드 · 최신순

알림
- ☐ 알림 종: 결정·요청·제작·게시·연결 탭, 숫자 = 해결 전 대상 수, ‘새 N’ 따로, 읽어도 해결 전이면 남김
- ☐ 일일 콘텐츠 승인 대기·마감 임박 알림 (운영실 종에는 없음 — 예약 작업으로만)
- ☐ 승인 마감 알람: 제작 직후(13:30) + 전날 저녁(21:30), 22~08시 무알림
- ☐ 브랜드 필터가 바디랩 포함 모든 브랜드에서 일일 콘텐츠에 적용되는지 (운영실 버그 — `route.ts:608`)
