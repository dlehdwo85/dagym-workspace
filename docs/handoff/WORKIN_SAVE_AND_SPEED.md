# 업무 생성 저장 버튼 복원 + 화면 전환 속도 (대표 지시 2026-10-14)

> 대표: "업무 생성 시 저장 버튼 다시 살립니다. 없으니까 오히려 불편. 알맞게 세팅. 버튼 동작·페이지 전환 과정에서 속도가 느리지 않도록 주의."
> 웹 코드·설정만(앱 새 빌드 없음). 클라우드, 한 커밋으로 main.

## 1. 저장 버튼 (업무 "생성"에만 — 수정은 지금처럼 자동 저장)
- **한 줄 추가(InlineAddTask)**: 제목을 입력하기 시작하면 오른쪽에 **"저장" 버튼**(진한 파랑, 44px, 휴대폰 엄지 위치) 표시. Enter/키보드 완료도 저장. 저장 후 입력칸 비우고 커서 유지(연속 입력).
- **바깥 누르면 자동 저장(blur 저장)은 끔** — 실수로 만들어지는 업무 방지. 대신 입력값은 남겨 두고(초안 유지), 화면을 떠날 때만 "작성 중인 업무가 있습니다" 표시.
- **업무 등록 창(+ 만들기 → 업무)**: 하단 고정 "저장"·"취소", 저장 단축키 Ctrl+Enter.
- **업무 상세·일정 편집의 기존 항목 수정**: 자동 저장 유지("저장됨 ✓" 표시) — 대표 불편 신고는 "생성" 기준.
- 일정 빠른 등록 시트도 "저장" 버튼 유지(Google 과 동일).

## 2. 속도 (측정값 포함)
- 측정(로컬, 2026-10-14): `/api/health` 첫 요청 0.98s(콜드 스타트), 이후 0.21~0.22s, DB 왕복 75ms. 응답 헤더 `X-Vercel-Id: icn1::icn1` → **함수는 서울(icn1), DB(Neon)는 싱가포르(sin1)** → 쿼리 1번마다 약 75ms. 업무 목록·상세처럼 쿼리를 순서대로 5~10번 하면 0.4~0.8s 가 DB 왕복에만 씀.
- 요청:
  1. **함수 지역을 DB 와 같게**: `vercel.json` `regions: ["sin1"]`(사용자↔싱가포르 1회 왕복 ~70ms 로 바꾸는 게 쿼리마다 75ms 보다 빠름). 바꾸기 전후 주요 API(업무 목록·상세·캘린더 이벤트·홈) 서버 처리 시간 비교 기록.
  2. 서버: 순서대로 하던 독립 쿼리 `Promise.all` 로 묶기(업무 상세 `loadTaskDetail` 등), 목록 API 의 사람·조직 디렉터리 중복 조회 제거, 필요한 인덱스 확인(tasks: org_unit_id, assignee_id, due_date, deleted_at).
  3. 화면: 업무 추가·완료·순서 변경·칩 변경은 **즉시 화면 반영(낙관적 업데이트)** 후 서버 저장, 실패 시 되돌림. 저장 버튼 누름 → 0.1초 안에 목록에 새 행.
  4. 페이지 이동: 하단 탭·사이드바·업무 행은 Next `<Link prefetch>`/router.push 로(전체 새로고침 금지 — 예: 추가됨 토스트 "보기"의 `window.location.href` → router.push), 데이터는 캐시(SWR 식) 먼저 보여 주고 뒤에서 갱신, 이동 중 상단 진행 표시줄.
  5. 콜드 스타트: 정기 실행(tick)이 10분마다 깨우는지 확인, 무거운 import(FullCalendar 등)는 해당 화면에서만 동적 로드.
- 완료 기준: 휴대폰(4G)에서 탭 전환 체감 0.3초 이내, 업무 저장 후 새 행 즉시 표시, E2E 에 주요 API 응답시간 기록(TEST_REPORT).
