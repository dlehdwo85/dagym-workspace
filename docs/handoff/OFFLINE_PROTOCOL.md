# 로컬(노트북)이 끊겼을 때의 대응 체계

만든 이유(대표 11/23): "인터넷이 끊기면 노트북 덮개 설정과 무관하다 — 이에 대한 대응 체계"

## 0. 원칙
- **운영 서비스는 노트북과 상관없이 돈다.** 워크인 서버(Vercel), 데이터베이스, 정기 작업(깃허브 Actions·서버 크론), 공고 수집, 메일 발송은 노트북이 꺼져도 계속된다.
- 노트북이 끊겨 멈추는 것은 세 가지뿐이다.
  1. 대표 계정으로 하는 운영 확인
  2. 실기기 확인
  3. 클라우드와 대표 사이의 전달
- 그래서 대응은 세 가지다: **① 전달 통로를 둘로 만든다 ② 클라우드가 기다리지 않는다 ③ 복귀하면 밀린 것을 순서대로 처리한다.**

## 1. 끊김을 아는 법
- 클라우드는 로컬에 보낸 요청에 30분 안에 답(받음·결과)이 없으면 **'로컬 끊김 상태'**로 본다.
  - 로컬은 받은 요청에 짧게라도 바로 답한다.
- 클라우드에서 로컬로 보내는 메시지는 끊긴 동안 사라질 수 있다(쌓이는지 확인 못함). 그래서 같은 내용을 반드시 저장소에도 남긴다.
  - 남기는 곳: LOCAL_LOG '클라우드 → 로컬 요청' 줄, 그리고 커밋 제목의 [로컬요청]·[배포확인요청] 표시.
  - 이것이 기본 통로이고, 메시지는 보조 통로다.

## 2. 끊긴 동안 클라우드가 하는 일
- **멈추지 않는다.** 결정이 필요 없는 다음 일을 계속하고, 운영 확인이 필요한 것은 '로컬 확인 대기'로 표시만 한다.
- **대표에게 직접 묻는다.**
  - 대표는 휴대폰 Claude 앱으로 클라우드 대화를 바로 볼 수 있다. 급한 결정은 클라우드 대화 안에서 대표에게 직접 질문한다.
  - 같은 내용을 docs/handoff/CEO_DECISIONS.md '열림'에도 적는다.
- **운영 확인을 스스로 한다**(준비 중 — 아래 4번).
  - 로그인 없이 볼 수 있는 것은 지금도 한다: 운영 기본 점검, 공개 주소, 배포 상태.
- 돈·삭제·스토어 공개·설정 변경은 끊긴 동안에도 대표 승인 없이는 하지 않는다. 로컬이 대신 승인하는 일은 원래 없다.

## 3. 복귀했을 때 로컬이 하는 일(순서 고정)
1. `git fetch` 후 merge 하고, 마지막 로컬 커밋 이후의 커밋 중 [로컬요청]·[배포확인요청]을 모두 목록으로 만든다.
2. LOCAL_LOG 의 '클라우드 → 로컬 요청' 새 줄과 대표결정함(CEO_DECISIONS) '열림'을 읽는다.
3. 알림과 메시지 대기열을 읽는다(ReadNotifications 포함).
4. 밀린 운영 확인을 오래된 것부터 처리한다. 결과는 한 번에 묶어 클라우드에 보내고, 대표에게는 '끊긴 동안 있었던 일' 요약과 '대표님께 여쭙는 것'을 함께 보낸다.
5. LOCAL_LOG 에 '로컬 복귀 시각, 처리한 요청 수, 남은 것'을 한 줄 적는다.

## 4. 노트북 의존을 줄이는 일(진행)
- **검수용 시험 회사·계정으로 운영을 자동 확인**(클라우드 검토 중):
  - 운영에 다짐과 분리된 '검수용 시험 회사'를 두고, 배포 직후 깃허브 Actions 가 그 계정으로 운영 화면 시험(Playwright)을 돌린다.
  - 계정 만들기는 대표 승인이 필요하다. 비밀번호는 대표가 깃허브 비밀값에 직접 넣는다.
  - 이렇게 되면 노트북에 남는 것은 대표 계정 전용 확인과 실기기 확인뿐이다.
- **노트북 쪽**: 인터넷 대비로 휴대폰 핫스팟을 '자동 연결' 네트워크로 저장해 둔다(대표 작업, 선택).
  - 'Claude 일하는 동안 잠들지 않기'는 이미 켜져 있다.
  - 덮개 설정은 D-07(대표 선택).

## 5. 노트북 인터넷이 끊겼을 때(대표 11/23: "덮개가 아니라 인터넷 끊김이 문제")
덮개 설정(D-07)은 하지 않는다. 덮개를 열어 두어도 인터넷이 끊기면 이 대화는 똑같이 멈추기 때문이다.

**지금 노트북 상태(11/23 로컬 확인)**
- 휴대폰 핫스팟은 저장돼 있고 '자동 연결'이 켜져 있다.
- 다만 윈도는 **공유기 Wi-Fi 에 붙어 있는 채 인터넷만 끊기면**(통신사 장애·공유기 고장) 핫스팟으로 넘어가지 않는다.
  - 공유기 신호 자체가 사라질 때만 저장된 다른 네트워크로 옮긴다.
- 휴대폰 핫스팟이 꺼져 있으면 옮길 곳도 없다.

**끊긴 동안 멈추지 않는 것**: 운영 서비스, 공고 수집, 메일, 클라우드 개발. 클라우드는 휴대폰 Claude 앱으로 대표에게 직접 묻는다(2절).

**끊긴 동안 멈추는 것**: 대표 계정으로 하는 운영 확인, 실기기 확인, 대표 크롬에 화면 띄우기.
- D-08(검수용 시험 회사 + 깃허브 자동 확인)이 끝나면 운영 확인은 노트북 없이 배포마다 돈다.
- 이것이 인터넷 끊김의 근본 대책이다.

**노트북 쪽 선택지(대표 선택, 돈 없음)**
1. 휴대폰 연결 앱의 '인스턴트 핫스팟': 노트북 Wi-Fi 목록에서 휴대폰을 누르면 휴대폰을 만지지 않고 핫스팟이 켜진다. 갤럭시와 휴대폰 연결 앱이 이미 짝지어져 있다. 지원 여부는 확인 못함.
2. 인터넷 감시 작업: 1분마다 인터넷을 확인하고, 3번 연속 실패하면 저장된 휴대폰 핫스팟으로 자동 전환한다.
   - 노트북에 상시 작업을 하나 두는 일이라 대표 승인 뒤에 만든다.
   - 핫스팟이 켜져 있어야 의미가 있으므로 1번과 함께 써야 한다.

**복귀하면**: 3절 순서대로 처리한다.
