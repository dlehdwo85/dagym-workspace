# Apple 심사용 체험 계정 (대표 결정 A, 2026-10-13)

> 대표 결정: 비밀번호 없는 "체험하기"(DEMO_LOGIN) 대신 **데모 조직에 심사용 일반 계정**을 만든다.
> 목적: TestFlight 외부 테스트(공개 링크) 베타 심사 — 심사 담당자가 로그인해 기능을 볼 수 있어야 함.
> 구현: 클라우드, 바로 main. 비밀번호는 코드·저장소·로그에 남기지 않는다.

## 1. 사용자 관리 → "심사용 체험 계정" (대표만)
- 버튼 하나로: `is_demo=true` 조직 "체험 조직(심사용)" 생성(없으면) + 예시 데이터(프로젝트 1, 업무 6~8건: 담당자·지시자·마감 지남/오늘/이번 주·우선순위 섞어서, 일정 3건, 알림 몇 건) + 데모 사용자 2~3명(`is_demo=true`, 로그인 불가 이름만) 생성. 다시 누르면 예시 데이터 초기화.
- 심사용 로그인 계정 1개(`is_demo=true`, 권한 = 데모 조직 관리자, 예: `review@…` 이메일은 대표가 입력)를 **기존 초대 흐름**으로 만든다 → 초대 링크를 대표에게 보여 주고, 대표가 그 링크에서 비밀번호를 직접 정한다(서버는 해시만 저장).
- 015 격리 규칙 그대로: 데모 계정은 회사 데이터·사람을 못 보고, 대표·본사 화면에는 데모 데이터가 안 섞임. 데모 계정은 사용자 관리·운영 상태·매출·내보내기·외부 연동 불가(`denyDemo`).
- 대표 화면 사용자 목록에 데모 계정은 "심사용" 표시, 비활성화 버튼.

## 2. 완료 기준
- 운영에서 대표가 버튼 → 초대 링크 → 비밀번호 설정 → 그 계정으로 앱 로그인 시 예시 데이터만 보이고 업무 추가·완료·일정 보기 가능.
- API 시험: 데모 계정이 회사 업무/사용자 조회 시 404·403, 대표 목록에 데모 데이터 없음.

## 3. 로컬 이후 절차
1. 대표: 비밀번호 설정(첫 비밀값 입력) → App Store Connect TestFlight "테스트 정보 → 베타 앱 심사 정보"의 로그인 칸에 아이디·비밀번호 입력(로컬이 화면까지 열어 둠).
2. 로컬: 외부 그룹 "직원 공개 링크"에 최신 빌드 추가 → 공개 링크 켜기 → 베타 심사 제출 → 승인 후 링크를 대표에게 전달.
