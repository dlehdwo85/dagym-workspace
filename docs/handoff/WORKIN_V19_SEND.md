# WORKIN V19 — AI 비서 견적서·문자 작성 → 대표 확인 → 대표가 보내기 (2026-10-15 대표 지시)

## 원칙
- AI 는 **초안만** 만든다. 발송은 언제나 사람이 [보내기]를 눌러야 한다. AI 도구가 직접 보내는 경로는 만들지 않는다.
- [보내기] 권한: 기본 대표(owner)만. 설정 > 사용자 관리에서 다른 사람에게 줄 수 있게(기본 꺼짐).
- 보낸 것은 모두 기록: 업무(연결된 경우)·CRM 고객 기록에 "채널·받는 사람·보낸 사람·시각·내용 사본" 남김.

## 1. 문자 — A 방식(휴대폰 기본 문자앱으로 넘기기), 비용 없음
1. AI 비서에 "OO에게 ~ 문자 보내줘" → 새 제안 종류 `draft_sms` {to: 전화번호[], body, taskId?, leadId?}.
   - 받는 사람은 CRM 문의 고객·조직 사용자·업무 연락처에서 찾고, 못 찾으면 "번호 확인 필요"로 비워 둔다(지어내지 않음).
2. 시안 카드: 받는 사람·본문 편집 가능, 글자 수(90바이트 넘으면 "장문" 표시), [고치기] [보내기].
3. [보내기] (휴대폰 앱·휴대폰 웹):
   - `sms:` 링크로 기본 문자앱을 연다. Android `sms:010...?body=...`, iOS `sms:010...&body=...`(본문 URL 인코딩). 여러 명이면 쉼표로.
   - Capacitor 앱에서는 `App.openUrl`/`window.location` 로 열고, 앱이 다시 앞으로 오면 "문자를 보내셨나요? [보냈어요] [안 보냄]" 확인 → [보냈어요]일 때만 기록.
4. 노트북(데스크톱 웹)에서 [보내기]: 문자앱이 없으므로 "휴대폰에서 보내기" — 대표 휴대폰으로 푸시 알림을 보내고, 알림을 누르면 앱에서 같은 시안 카드가 열려 3번 진행. 화면에 QR(같은 시안 딥링크)도 함께 표시.
5. 발신 번호는 대표 휴대폰 번호임을 카드에 표시("내 휴대폰 번호로 발송됩니다").
- 문자 발송 서비스(회사 번호 1555-2564, 건당 과금) 연동은 이번 범위 아님(B 방식, 추후).

## 2. 견적서 — 회사 자체 양식
- 하이링크: 기존 자체 견적서 양식 있음. 대표가 자료실에 올린다.
- 다짐: 양식 없음. 대표가 비서에게 "하이링크 견적서를 참고해 다짐 전용 견적서 만들어줘"라고 요청한다.
  - AI 는 자료실의 하이링크 견적서를 읽어 항목 구성(품목·규격·수량·단가·공급가액·부가세·합계·유효기간·결제조건·비고)을 따라 하되, 공급자 정보는 **주식회사 다짐**(조직 설정의 다짐 본사 사업자 정보)으로 채운다. 하이링크 정보가 섞이면 안 된다.
  - **다짐 견적서는 A4 1페이지 고정.** 품목이 많으면 글자·행 높이를 줄이고, 그래도 넘치면 "1페이지 초과 — 품목을 묶어 주세요" 경고(2페이지로 자동 넘기지 않음).
  - 만든 양식은 "견적서 양식"으로 저장(회사별 1개 이상, 기본 양식 지정). 이후 "OO에 견적서" 요청 때 회사(다짐/하이링크)를 고르면 해당 양식으로 작성.
- 새 제안 종류 `draft_quote` {company: dagym|hilink, templateId, to(고객), items[], validUntil, note, taskId?, leadId?} → PDF 미리보기 + 표 편집 → [보내기].
- 견적서 [보내기] 방법(1단계):
  - (휴대폰 앱) 공유창(Capacitor Share)으로 PDF 를 넘겨 카카오톡·문자 등에서 대표가 보냄 → 돌아오면 "보내셨나요?" 확인 후 기록.
  - (메일) 고객 이메일이 있으면 Resend 로 PDF 첨부 발송(`src/lib/mail.ts` 첨부 지원 추가). 회사 도메인 발신 인증 전에는 이 버튼 숨김.
  - (링크) 만료 있는 견적서 보기 링크를 만들어 문자 시안(1번)에 넣기.
- 견적번호 자동(회사별 `Q-YYYYMMDD-001`), 금액은 원 단위·부가세 10% 계산은 서버에서, AI 가 계산한 합계는 서버가 다시 계산해 덮는다.
- 주의: 자료실 HWP 는 아직 글자를 못 읽는다(V14 #32). 하이링크 견적서가 HWP 면 PDF/엑셀로도 올려 달라고 안내하거나 #32 를 먼저 끝낼 것.

## 시험
- AI 시안 → 대표 외 사용자는 [보내기] 안 보임(서버도 403).
- `sms:` 링크 형식 Android/iOS 각각, 한글·줄바꿈·여러 명 인코딩.
- 다짐 견적서 품목 1·10·25개에서 1페이지 유지/초과 경고, 공급자란에 하이링크 정보 없음.
- 보낸 기록이 업무·CRM 에 남고, [안 보냄]이면 남지 않음.

## 부록 A. AI 비서 대화 입력 개선 (2026-10-15 대표 신고: "단락 구분, 보낸 걸 멈추거나 수정하는 게 없다")
대상: `src/app/(app)/assistant/page.tsx`, `src/components/AiDock.tsx` (두 곳 같은 동작으로)

### A1. 단락 구분(줄바꿈)
- 현재: Enter=보내기, Shift+Enter=줄바꿈 → **휴대폰 키보드엔 Shift+Enter 가 없어 줄바꿈이 불가**. textarea 도 rows=1 고정이라 줄이 늘어도 안 보임.
- 변경:
  - 휴대폰(터치 기기·앱): **Enter = 줄바꿈**, 보내기는 [보내기] 버튼만.
  - PC: Enter=보내기, Shift+Enter=줄바꿈 유지. 입력창 아래 작은 안내 "Shift+Enter 줄바꿈".
  - 입력창 자동 높이(내용에 맞춰 최대 6줄, 그 이상 스크롤).
  - 보낸 말풍선·AI 답변 모두 줄바꿈 그대로 표시(이미 pre-wrap — 유지 확인).
  - AI 답변도 읽기 쉽게: 시스템 프롬프트에 "2~3문장마다 빈 줄로 단락을 나누고, 항목은 줄머리표(-)로" 추가.

### A2. 멈추기
- 답변 기다리는 동안 [보내기] 버튼이 **[멈춤](■)** 으로 바뀐다. 누르면 요청 취소(AbortController 로 fetch 중단, 서버도 `req.signal` 을 Anthropic 호출에 넘겨 같이 끊기).
- 멈춘 대화엔 "멈춤" 표시만 남기고, 멈춘 질문으로 만들어지던 제안(업무·일정 등)은 저장하지 않는다(서버에서 abort 확인 후 제안 생성 생략). 이미 만들어진 제안이 있으면 "확정 대기"로 두고 자동 실행하지 않음(원래 원칙 그대로).
- 사용량은 실제 쓴 만큼만 기록.

### A3. 보낸 말 수정·다시 보내기
- 내가 보낸 **마지막 말풍선**에 [수정] (길게 누르기·마우스 올리면 연필): 누르면 그 내용이 입력창으로 돌아오고, 고쳐서 보내면 **그 말 이후의 AI 답변과 아직 확정 안 된 제안은 지우고** 새로 답한다. 이미 확정(실행)된 제안은 지우지 않고 "이전 요청으로 이미 처리됨" 표시.
- 답변 중이면 [수정] 누를 때 자동으로 멈춘 뒤 수정.
- 모든 말풍선에 [복사] 추가(길게 누르기 메뉴).
- AI 답변에 [다시 답하기](↻) — 같은 질문으로 다시 생성.

### 시험
- 휴대폰 폭(390px)에서 Enter 로 3줄 입력 → 말풍선에 3줄 그대로, 버튼으로만 보내짐. PC 에서 Enter 보내기·Shift+Enter 줄바꿈.
- 답변 대기 중 [멈춤] → 로딩 사라지고 "멈춤" 표시, 제안 생성 안 됨, 바로 다음 질문 가능.
- 마지막 질문 [수정] → 이후 답변 교체, 확정 안 된 제안 사라짐, 확정된 업무는 그대로.
