# WORKIN V22 — AI 비서 문서·엑셀 결과물 품질 (2026-10-15 대표 신고)

## 신고
"하이링크 견적서를 참고해 다짐 견적서(엑셀)를 만들어 달라" → 글자만 옮겨지고, 1페이지에 안 들어가고, 디자인이 없음. "그냥 Claude 로 작업한 결과물 수준이면 좋겠다. 단, 사용량을 고려."

## 원인 (코드·운영 데이터 확인)
1. **참고 파일을 글자로만 읽음** — `src/lib/textExtract.ts` 의 xlsx 읽기는 셀 값만 뽑는다. 병합·테두리·색·글꼴·열 너비·로고 이미지·인쇄 설정(1페이지 맞춤)은 AI 에게 전달되지 않는다. PDF·이미지는 아예 본문이 없다.
2. **만드는 도구가 표 글자만 받음** — `propose_xlsx_report` 입력은 `sheets[].rows`(2차원 글자 배열)뿐이라 AI 가 디자인을 지시할 방법이 없다.
3. **엑셀 작성기가 최소 기능** — `src/lib/xlsx.ts` 는 첫 줄 굵게 + 열 너비 추정만 한다. 병합·테두리·채우기·숫자 서식·인쇄 영역·한 페이지 맞춤·이미지 없음.
4. 운영 확인: 자료실 "하이링크 견적서 양식" 29KB(서식·로고 포함) → AI 결과 "다짐 견적서 (위탁운영 · 1페이지)" 4KB(글자만).
- Claude 앱에서 잘 나오는 이유: 그쪽은 코드 실행 환경에서 엑셀 라이브러리로 서식까지 직접 만들고, 결과를 렌더링해 확인한다. 워크인 AI 는 그 능력이 없다.

## 개선 — 두 단계(사용량 고려)
### A. 기본: "양식 복제 + 칸 채우기" (추가 비용 거의 없음, 디자인 100% 유지)
- 참고할 원본 양식(xlsx/docx)이 있으면 **원본 파일을 그대로 복사**하고 AI 는 바꿀 칸만 지시한다. 디자인·로고 위치·병합·인쇄 설정이 그대로 남는다.
- 새 읽기 도구 `read_template_layout(fileId)`: 시트별 사용 범위, 칸 주소별 값(빈 칸 제외), 병합 범위, 머리글/합계로 보이는 칸, 인쇄 설정(용지·방향·한 페이지 맞춤), 이미지 위치 — **요약 지도**로 돌려준다(원문 XML 아님 → 토큰 적음).
- 새 제안 도구 `propose_fill_template({ sourceFileId, title, folder, edits: [{ sheet, cell, value }], rows?: { sheet, startRow, items: [[...]] , keepStyleFromRow }, replaceImage?: { from: 'source-logo', to: 'company-logo:dagym' }, fitOnePage?: true })`.
  - 서버가 xlsx 의 sheet XML·sharedStrings 를 **수술식으로 수정**(셀 스타일 s= 유지, 값만 교체). 품목 줄 추가는 지정 행의 스타일을 복사해 삽입하고 합계 수식 범위를 늘린다. 수식 셀은 값으로 덮지 않는다.
  - `fitOnePage`: pageSetup fitToWidth=1, fitToHeight=1, A4, 인쇄 영역 = 사용 범위. 품목이 너무 많아 글자가 지나치게 작아질 정도면(예: 축소 60% 미만 추정) "1페이지 초과 — 품목 묶기" 경고.
  - `replaceImage`: 원본의 로고 이미지(xl/media)를 조직 설정의 회사 로고로 교체(크기·위치 유지).
  - 공급자 정보 칸은 AI 가 쓰지 않고 조직 설정(회사별 상호·사업자번호·대표·주소·연락처)에서 서버가 채운다 — 섞임 방지.
- 같은 방식을 docx 에도(`propose_fill_template` 가 docx 면 본문 단락·표 셀 치환).
- 만든 결과를 "양식"으로 저장(V19 견적서 양식) → 다음부터는 이 양식에 칸만 채움 = 가장 싸고 빠름.

### B. 선택: "고급 생성(새 디자인)" — Claude 앱 수준, 필요할 때만
- 참고 양식이 없거나 "새로 디자인해 줘"일 때만. Claude API 의 **Agent Skills(xlsx/docx/pptx/pdf) + 코드 실행** 사용:
  `client.beta.messages.create({ model: AI_MODEL, container: { skills: [{ type: 'anthropic', skill_id: 'xlsx', version: 'latest' }] }, tools: [{ type: 'code_execution_20260521', name: 'code_execution' }], betas: ['code-execution-2025-08-25'], ... })` → 응답의 file_id 를 `client.beta.files.download` 로 받아 R2 자료실에 저장. 참고 파일은 Files API 로 올려 `container_upload` 로 전달. `pause_turn` 처리.
- 코드 실행 컨테이너: 조직당 월 1,550시간 무료, 이후 시간당 $0.05 — 사실상 비용은 토큰. 한 건이 여러 번 왕복하므로 일반 대화보다 토큰이 많다(추정 건당 수백 원).
- 사용량 통제: 화면에 "고급 생성" 버튼(자동 사용 금지), 실행 전 "예상 비용 약 OOO원" 표시, 조직 월 한도에 합산, 관리자 설정에서 끄기 가능, 기본 모델 Sonnet(effort medium). 결과는 다시 A 방식 양식으로 저장해 이후엔 싸게 재사용.
- 상업화: 요금제별 고급 생성 월 횟수.

### C. 공통
- PDF·이미지 참고 자료: 지금은 본문이 없음 → 참고로 지정되면 Claude 에 PDF document / image 블록으로 직접 넘겨 보게 한다(그 요청에서만, 페이지 수 제한).
- 시스템 프롬프트: 견적서·공문 등 "양식이 있는 문서"는 A 를 먼저 쓰고, 글자만 표로 옮기는 propose_xlsx_report 는 데이터 표(업무 목록·매출 집계)에만 쓰도록 명시.
- 결과 미리보기: 제안 카드에 첫 페이지 미리보기(서버에서 간단 HTML 렌더) + "1페이지 / 2페이지" 표시.

## 시험
- 하이링크 견적서 양식 → "다짐 견적서" A 방식: 원본과 같은 서식·병합·로고 자리(다짐 로고), 공급자 = 다짐 정보, 하이링크 정보 없음, 인쇄 미리보기 1페이지.
- 품목 3→15개: 행 스타일 유지, 합계 수식 범위 확장, 1페이지 유지 또는 경고.
- B 는 버튼으로만 실행, 예상 비용·월 한도 반영, 결과 파일 다운로드·자료실 저장.
- 토큰 사용량 비교 기록: 기존 방식 vs A vs B (관리 > 사용량에 문서 생성 건별 표시).

## 부록 (2026-10-15 대표 추가 지시): "디자인을 발전시키고 새로 개선할 줄 알아야 한다. 일반 생성형 AI 도구의 기본 기능은 할 수 있게"
→ **B(Agent Skills + 코드 실행)를 '고급 버튼'이 아니라 문서·디자인 작업의 기본 경로로 바꾼다.** A(양식 칸 채우기)는 "같은 양식에 값만 바꾸기"일 때만 쓰는 빠른 길로 남긴다. 사용량은 아래 통제로 관리.

### 1. 갖춰야 할 기본 기능 (일반 생성형 AI 수준)
| 기능 | 방법 |
|---|---|
| 엑셀·워드·PPT·PDF 새로 만들기/디자인 | Agent Skills `xlsx`·`docx`·`pptx`·`pdf` + `code_execution_20260521` (betas `code-execution-2025-08-25`) |
| **디자인 발전시키기(반복 수정)** | 같은 대화에서 "더 세련되게/색 바꿔/표 정리" → 같은 컨테이너 재사용(`container: <id>`)으로 직전 파일을 이어서 고침. 자료실에 **버전**(v1, v2…)으로 저장, 이전 버전으로 되돌리기 |
| 결과 미리보기 | 컨테이너 안에서 첫 페이지(또는 슬라이드)를 PNG 로 렌더 → 채팅에 이미지로 보여 주고, AI 도 그 이미지를 보고 스스로 점검(1페이지 넘침·글자 잘림·정렬) 후 고친 뒤 제출 |
| 참고 자료 반영 | 참고 xlsx/docx/pdf/이미지를 Files API 로 올려 `container_upload` — 원본 서식·로고까지 보고 따라 하거나 개선 |
| 차트·그래프 | 코드 실행(matplotlib)으로 이미지 또는 엑셀 차트 |
| 데이터 분석 | 올린 엑셀/CSV 를 코드로 계산(합계·피벗·추세) — 숫자를 지어내지 않고 계산 결과로 답 |
| 웹 검색·페이지 읽기 | `web_search_20260209`·`web_fetch_20260209` (출처 링크 표시). 조직 설정에서 끌 수 있게 |
| 글쓰기·요약·번역·교정 | 지금처럼 대화로. 긴 결과는 문서로 저장 제안 |
| 이미지 이해 | 지금 기능 유지(사진·스캔 읽기) |
- 이미지 "생성"(그림 그리기)은 Claude 가 하지 않는다 → 범위 밖. 대신 도형·도표·아이콘은 SVG/PPT 도형으로.

### 2. 흐름
- AI 비서가 문서·디자인 요청을 알아보면(도구 `create_or_edit_file` 호출) 서버가 Skills+코드 실행 요청을 별도로 돌려 결과 파일·미리보기를 받는다. 대화 화면엔 "만드는 중… (미리보기 생성)" 진행 표시, `pause_turn` 이어받기.
- 결과 카드: 미리보기 이미지 + [자료실에 저장] [업무에 첨부] [더 다듬기] [버전 보기]. 데이터를 바꾸는 저장·첨부는 지금처럼 사용자 확인.
- 회사 디자인 기준(브랜드 색 #0F766E 계열, 로고, 글꼴, 회사 정보)은 조직 설정에서 읽어 매번 프롬프트에 넣는다(상업화: 조직별).

### 3. 사용량 통제
- 일반 대화는 지금 모델(Sonnet)·낮은 effort 유지, 파일 작업만 코드 실행 경로(effort medium).
- 시스템 프롬프트·도구·회사 디자인 기준은 고정 순서로 두고 **프롬프트 캐싱**.
- 컨테이너는 대화 단위로 재사용(파일을 매번 다시 올리지 않음). 코드 실행 시간은 조직당 월 1,550시간 무료, 이후 시간당 $0.05.
- 파일 작업 1건 비용을 기록해 관리 > 사용량에 "문서 작업 n건 · $x" 로 따로 표시, 월 한도(기존 limitUsd)에 합산, 80% 도달 시 대표 알림.
- 한 요청의 반복 수정 횟수 상한(예: 자동 점검 2회), 요청당 토큰 상한(task budget) 설정.
- 같은 양식에 값만 바꾸는 반복 업무는 A 경로(토큰 적음)로 자동 선택.

### 4. 시험
- "하이링크 견적서 참고해서 다짐 견적서를 더 깔끔하게 1페이지로" → 서식 있는 xlsx, 미리보기 1페이지, 다짐 로고·정보.
- "색을 청록으로, 표 테두리 얇게" → v2 생성, v1 되돌리기 가능.
- "이 엑셀 매출 월별 합계와 차트" → 계산값이 원본과 일치.
- "OO 최근 기사 찾아 요약" → 출처 링크 포함(웹 검색 켜짐일 때만).
- 사용량 화면에 문서 작업 비용 따로 표시, 한도 초과 시 차단 안내.

## 부록 2 (2026-10-15 대표): "문서를 만들면 비용이 너무 많이 든다 — 다른 방안"
### 실측(작업 53c8cb47, 다짐 견적서 새로 만들기)
- 문서 엔진 $0.403 + AI 비서 대화 $0.077 = 약 $0.48(약 670원).
- 문서 엔진 1회 호출 안에서 코드 실행 8번(server_tool_use 8) — 출력 5,389 토큰($0.05)뿐이고 **나머지 약 $0.35 는 입력**(약 17만 토큰): 단계마다 스킬 설명·코드 결과·미리보기 이미지를 다시 읽기 때문. 모델 Sonnet 5.5($2/$10).
### 줄이는 방법 (효과 큰 순)
1. **양식 재사용 경로(V22-A) 실제 구현**: 한 번 만든 문서는 [양식으로 저장] → 다음부터 "값만 채우기" = 코드 실행 없이 서버가 셀 값만 교체, AI 는 값 목록만 출력(Haiku, 수천 토큰) → **건당 수 원**. 견적서·공문·월 보고 같은 반복 문서는 전부 이 길로. 첫 화면에서 기본 제안.
2. **문서 엔진 기본 모델 = Haiku 5.5**($0.10/$0.50, Sonnet 대비 1/20): 고치기·값 바꾸기·단순 문서는 Haiku, "새로 디자인"·Haiku 실패 시에만 Sonnet. 환경변수 AI_MODEL_DOC(기본 haiku) / AI_MODEL_DOC_DEEP(sonnet). 품질은 로컬이 같은 요청으로 Haiku vs Sonnet 비교 시험.
3. **단계 줄이기**: 미리보기 PNG 를 AI 가 "열어 보고" 고치는 자기 점검을 기본 끔(이미지 입력·추가 단계가 큼) → 변환 후 쪽수만 코드로 확인(pdfinfo), 1쪽 넘으면 그때만 1회 수정. 미리보기 이미지는 만들되 AI 가 보지 않음. effort low.
4. **프롬프트 캐싱**: system·도구·회사 정보 블록에 cache_control(1h) — 같은 날 연속 작업 입력비 절감. usage 의 cache_read/cache_creation 을 ai_usage 에 그대로 기록(지금 0 으로 넣음).
5. **AI 비서 대화 쪽**: 문서 요청으로 판단되면 긴 도구 목록·대화 기록 없이 짧게 run_file_task 만 호출(분류는 Haiku).
6. 화면: 문서 카드에 "이번 작업 약 OO원" 표시(관리자), 사용량 화면 문서 작업 건당 평균.
### 목표
- 반복 문서(양식 채우기): **10원 이하**. 새 문서(Haiku): **50원 이하**. 새 디자인(Sonnet, 단계 축소): **200원 이하**.
- 로컬 검증: 같은 "다짐 견적서" 요청으로 ① Haiku 새로 만들기 ② 양식 채우기 ③ Sonnet 새 디자인 비용·품질 비교 후 보고.
