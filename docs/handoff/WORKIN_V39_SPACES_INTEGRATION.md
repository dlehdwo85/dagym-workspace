## 결론(권장안) — "워크인 한 곳으로 옮겨 짓기"
- **영업 → 워크인 저장소·DB 로 흡수(다시 짓기)**: 화면·기능은 영업관리 것을 그대로 옮기되 워크인 디자인으로. 업무·일정·파일·사람은 워크인 것을 같이 씀(중복 제거). Supabase 27 테이블 → Neon 에 tenant 칸 포함 새 테이블(추가형 마이그레이션) + 데이터 이전 스크립트(다짐 데이터 1회).
- **마케팅 → 1단계는 링크+통합 로그인, 2단계에 흡수**: 지금 구조(HTML 문자열·KV·공용 비밀번호)는 다른 회사에 팔 수 없음. 1단계: 워크인 로그인으로 들어가게(SSO), 워크인 공간 전환에서 마케팅으로 이동. 2단계: 승인·캘린더·광고 성과·채널 연결을 워크인 안 React 화면 + Neon 테이블로 다시 짓고, SNS·광고 연결을 회사별 설정(암호화 저장)으로.
- 이유: 저장소 3개·DB 3종·로그인 3종으로 파는 건 보안·유지보수·결제(요금제별 공간 제공) 모두 어렵고, 고객 회사마다 데이터 분리(테넌트)가 워크인에만 있음.

## 예상 문제점과 대응
1. **로그인 통합**: 서로 다른 *.vercel.app 은 쿠키 공유 불가 → 흡수하면 해결. 마케팅 1단계는 워크인을 로그인 제공자(짧은 서명 토큰)로, 장기적으로 app.work-in.dev 한 도메인.
2. **데이터 이전**: 영업 데이터(Supabase) → Neon 이전 중 누락 위험 → 이전 전 백업·건수 대조·읽기 전용 기간.
3. **공용 비밀번호·환경변수 계정**(마케팅): 상업화 불가 → 회사별 채널 연결(OAuth) + 암호화 저장.
4. **업종 전용 기능**: K-APT 아파트 관리업체 수집·입찰 공고는 다짐 업종 전용 → "업종 확장 기능"으로 켜고 끄기(시설 운영 업종 고객에게 판매 포인트).
5. **요금제**: 공간별로 판매(업무 기본, 영업·마케팅 추가 요금) → V27 요금표에 "공간 추가" 항목.
6. **마케팅 Preview 가 운영 KV 공유**: 통합 시험 중 운영 데이터 오염 위험 → 시험 전 분리.
7. **배포 운영**: 이전 기간 동안 기존 두 사이트는 그대로 운영(중단 없음), 공간이 완성되면 기존 사이트는 읽기 전용 → 종료.
8. **사람 한 명이 여러 회사·공간**: 지금은 users.tenant 하나 → 멤버십 테이블(사람×회사×공간 권한) 필요.

## 단계(대표 시안 확정 후)
1. 공간 틀: AppShell 공간 전환(휴대폰 시트·PC 메뉴), 공간별 강조색, 멤버십·공간 권한, 요금제 연동.
2. 영업 공간 1차: 리드·파이프라인·제안/견적·계약·고객 + 데이터 이전.
3. 마케팅 1단계: 워크인 로그인으로 진입·공간 전환 링크.
4. 영업 2차(입찰·건물 모니터링·지역) / 마케팅 2단계(흡수).

### C. 상업화 때문에 바꿔야 하는 것
1. **수집 데이터는 회사 공용, 진행 기록은 회사별**: 입찰공고·준공시설·신규단지·협력사 목록은 공개 데이터라 전체 1벌(global 테이블)로 두고, opportunity_work·연락 상태·메모·전환은 tenant 칸으로 회사마다 따로. 다른 회사가 다짐의 검토 메모를 보면 안 됨.
2. **검색어·업종이 다짐 전용**: matchFit(헬스·피트니스·커뮤니티 등 18개 검색어, 다짐/하이링크 적합)과 사업 카테고리를 **회사 설정**(업종 템플릿 + 직접 추가)으로. 기본 템플릿 "시설 운영(피트니스·커뮤니티)"으로 다짐 값 그대로 제공.
3. **입찰 모니터링은 업종 확장 기능**(요금제 '공간 추가'·업종 팩): 켜진 회사만 수집 결과 열람.
4. **비밀값**: DATA_GO_KR_SERVICE_KEY·KAPT_SERVICE_KEY·KAKAO_REST_API_KEY 는 워크인 Vercel 에 대표가 직접 입력(우리 회사 키로 전체 수집, 고객 회사 키 불필요).
5. 사용자 2명 중 role=admin 0명(원본 확인 필요 항목) → 이전 때 대표 계정을 관리자로 지정.
