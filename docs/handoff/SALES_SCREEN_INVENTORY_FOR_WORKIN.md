## 2. 화면별 상세

### 2-1. 홈 /dashboard

제목은 "홈", 설명은 "{이름} 님, 오늘 할 일부터 위에서 차례로 처리하세요."

**① 오늘 할 일 카드 (남색)**

- 날짜, "N건", [순서대로 시작] 버튼이 있다.
- 막대 그래프로 "지연 n / 오늘 n / 새로 확인 n" 을 보여 준다.
- 12건까지 펼쳐 보이고, 나머지는 "나머지 N건 더 보기" 로 접힌다.
- 각 줄: 종류 배지 · 제목 · 부제 · 시점 · [전화]
- 정렬: 지연 → 오늘 → 새로 확인

종류 배지별 원천은 다음과 같다.

| 종류 배지 | 원천·조건 |
|---|---|
| 연락 지연 / 오늘 연락 | leads.next_contact_date |
| 지난 일정 / 일정 HH:MM | 미완료 일정 |
| 입찰 후속 / 신규단지 후속 | opportunity_work.next_date ≤ 오늘. 단 진행영업 전환·대상아님·미참여는 제외 |
| 준공시설 연락 | next_action_date ≤ 오늘, 미연락·연락중 |
| 협력사 등록 | next_date ≤ 오늘. 단 등록 완료·대상 아님은 제외 |
| 입찰 오늘 마감 / 내일 마감 | 즉시 검토 또는 검토중·연락중 |
| 그 밖에 오늘·내일 마감 관련 공고 N건 | 위에 들지 않은 마감 공고 |
| 새 입찰 N건 | 오늘 first_seen_at, related, 협력사 모집 아님 |
| 협력사 모집 N건 | 오늘 first_seen_at, 협력사 모집 |

**② 숫자 카드 4개**

| 라벨 | 값 | 보조 표시 |
|---|---|---|
| 진행 영업 | 진행 영업 수 | "연락 지연 N건" |
| 입찰 마감 7일 내 | 마감 7일 이내 관련 공고 수 | "진행 공고 N건" |
| 지금 영업기회 | '지금 영업' 건수 | "입찰·만료·신축·준공" |
| 이번 달 계약 | contracts.start_date 가 이번 달인 수 | "종료 90일 내 N건" |

**③ 아래 카드 2개**

- "다가오는 연락 · 지연 일정": 지연 / 3일 이내 / 7일 이내 로 나눈다.
- "지금 영업할 곳": 상위 5건과 [전체 →]

**④ 접힘 영역 "성과·분석 더 보기"**

- 영업 단계 분포 (6그룹)
- 자동수집 최근 실행 (관리자만)
- "30일 이상 활동 없는 진행 리드"
- 최근 상담 8건
- 한 줄 요약: 제안·협상 / 계약 검토 / 이번 달 계약 완료 / 이번 달 신규 리드 N / 전체 N / 예상 매출 / 가중 forecast(단계 가중치) / 운영중 계약
- 최근 6개월 매출 트렌드 (예상 대 계약)

### 2-2. 영업기회 요약 /opportunities

제목은 "영업기회", 설명은 "공고 전 선행영업 · 입찰공고 · 계약만료 재입찰 · 신규단지를 한곳에서 보고 '지금 움직일 곳'부터 처리합니다."

**타일 6개**

| 타일 | 큰 숫자 | 보조 줄 | 계산 |
|---|---|---|---|
| 지금 영업할 곳 | N곳 | "입찰 n · 계약만료 n" / "신규 n · 운영시설 n" | '지금 영업' 목록 건수 |
| 입찰 | N건 진행 | "즉시 검토 n" / "7일 안에 마감 n" | 관련 공고 중 마감·취소·낙찰이 아니고 KST 마감일 ≥ 오늘. 대상아님·미참여는 제외 |
| 계약만료 | N건 / 12개월 | "지금 영업 단계 n" / "가장 빠른 종료 {날짜}" | 종료일이 오늘부터 365일 안 |
| 신규단지 | N건 | "지금 영업 n" / "후속조사 n" | — |
| 준공·입주 시설 | N곳 | "연락중 n · 진행영업 n" / "미연락 n" | — |
| 협력사 등록 | N곳 | "모집 공고 n건" / "시공사·시행사·관리주체" | — |

**"목록별 진행 현황" 표**

- 열: 목록 | 전체 | 미검토 | 검토중 | 연락중 | 보류 | 미참여 | 대상아님 | 진행영업 전환
- 행 4개: 입찰 (진행중 관련) / 계약만료 (12개월 내) / 신규단지 · 신규건축 / 준공·입주 시설
  - 준공·입주 시설 행은 contact_status 를 위 열에 맞춰 넣고, 옆에 "영업완료 n" 을 붙인다.
- 휴대폰에서는 목록별 카드에 상태 칩으로 보여 준다.

**"지금 영업할 곳" 상위 40건**

- 각 줄: 출처 배지 · 제목 · 부제 · 날짜 · D-day
- 출처 배지는 선행영업 / 입찰 / 계약만료 / 신규건축 / 운영시설 이다.

**"선행영업 · 거래처 연결" 표**

- 열: 영업 적기 | 시설 | 현재 운영사 | 계약 종료 | 영업 시작 | 예상 공고 | 발주 단계 | 근거(확정/추정) | 링크

### 2-3. 오늘 등록 /opportunities/today

제목은 "오늘 등록", 설명은 "그날 새로 들어온 DB 만 모아 봅니다. 기준은 영업관리에 처음 저장된 날(한국 시간)입니다." 판단 방식은 4장에 있다.

**날짜 이동**

- 버튼: ← 전날 / 날짜 칩 / 다음날 → / 오늘 / 날짜 직접 입력 + [보기]
- 미래 날짜는 오늘로 바꾼다.

**요약 카드 4개** (누르면 아래 섹션으로 이동): 입찰 (관련) · 협력사 모집 · 신규단지 · 준공·입주 시설

**섹션 4개 (모두 카드형)**

1. **입찰 (다짐·하이링크 관련)**
   - 카드 항목: 사업 배지 · 분류 · 마감일 · 단지/기관명 · 공고명 · 지역 · 첨부 수
   - 마감 지난 건은 흐리게 보인다.
   - 누르면 입찰 상세로 간다.
2. **협력사 모집**: [모집 공지 ↗] [협력사 등록 화면]
3. **신규단지**: 단지명 · "유형 · 지역 · n세대"
4. **준공·입주 시설**
   - 세대수 큰 순으로 30곳까지 보인다.
   - 카드 항목: 이름 · "유형 · 지역 · n세대 · 관리사무소 전화"

- 이 화면은 읽기만 한다. 행 버튼이 없다.

### 2-4. 지금 영업할 곳 /opportunities/now

설명: "오늘({날짜}) 기준으로 바로 움직여야 하는 {n}건을 선행영업·입찰·계약만료·신규건축·운영시설 5그룹으로 묶었습니다."

| 그룹 | 포함 조건 | 날짜 라벨 |
|---|---|---|
| 선행영업 | 적기가 공고중·공고 임박·지금 접촉 | 공고 예상 / 영업 시작 |
| 입찰 공고 | 진행 중 관련 공고 중 분류가 '즉시 검토'·'협력사 필요' | 입찰 마감 (7일 이내가 위로) |
| 계약만료 · 재입찰 | 12개월 안 종료, 단계가 재입찰 임박·본격 제안·지금 영업 | 계약 종료 |
| 신규단지 · 신규건축 | 영업시작일 ≤ 오늘 | 제안 시작 / 영업 시작 |
| 준공·입주 완료 시설 · 위탁 잠재수요 | 아래 참고 | — |

- 준공·입주 시설 그룹에 들어가는 경우:
  - 계약종료·입주·준공이 6개월 안
  - 최근 18개월 안에 준공
  - 다음 연락일 ≤ 오늘
  - 가능성 상·중의 위탁검토 후보
  - 이 그룹은 상위 30건만 보여 준다.
- 정렬: 급한 순위 → 날짜 → 가능성 점수
- 각 줄: 출처 배지 · 제목 · 부제 · "다음 조치 …" · 전화 · 날짜 또는 "후속조사 필요" · D-day ('신규 준공 단지'는 "n일 경과")
- 대상아님·미참여·영업완료는 뺀다.
- 필터는 없다.

### 2-5. 입찰 DB /opportunities/monitoring (가장 기능이 많은 화면)

설명: "수집한 입찰공고 전체 목록입니다. 기본은 다짐·하이링크 관련 · 마감 전 공고를 마감 빠른 순으로 보여 줍니다." 한 쪽에 50건씩 보인다.

**탭**

- **진행 중** (기본)
  - 조건: 관련 공고, 마감 시각 ≥ 지금 또는 마감일 없음, 상태가 취소·낙찰·예정이 아님
  - 미참여·대상아님은 제외한다.
- **완료**
  - 조건: 마감 지남 또는 취소·낙찰, 또는 미참여·대상아님으로 정리한 공고
  - 마감 **월별 칩**으로 나눠 본다.
    - 칩 라벨은 "2026년 10월 n" 형식이다. 마감일이 없으면 "마감일 없음" 칩에 들어간다.
    - 기본은 이번 달이다. 이번 달에 공고가 없으면 가장 최근 달을 보여 준다.
    - 월 안에서는 마감 늦은 순이다.
  - 탭 안내 문구: "미참여·대상아님으로 정리한 공고와 마감이 지난 공고입니다. 마감 월별로 봅니다."

정렬: 다음 연락일 빠른 순 → 최근 수정 순

### 2-12. 칸반 /pipeline

- 열: 영업 단계 11개, 각 열에 건수가 붙는다.
- 카드: 거래처명 · 시설·지역 · 예상매출
- 드래그해서 단계를 바꾼다. 실패·보류로 옮길 때는 사유를 꼭 입력해야 한다.

### 2-13. 거래처 /leads

**영업비용 입력**

- 월 · 사업(공통/다짐/하이링크) · 항목(광고/인건비/영업활동비/입찰·제안/기타) · 금액 · 메모

## 4. '오늘 새로 들어온 공고·DB' 판단 방식

- **기준 칸은 `first_seen_at` 하나다.** 영업관리에 처음 저장된 시각이다.
  - created_at, posted_date(공고일)는 쓰지 않는다.
  - 수집기가 같은 건을 다시 봐도 first_seen_at 은 바뀌지 않는다. 다시 본 시각은 last_seen_at / last_seen_date 에 기록한다.
- **범위는 한국 시간 그날 00:00 이상, 다음날 00:00 미만**이다.
  - 쿼리: `.gte(first_seen_at, {날짜}T00:00:00+09:00).lt(…다음날)`

**'오늘 등록' 화면이 합치는 4개 원천**

| 원천 | 조건 | 정리 방식 |
|---|---|---|
| 입찰 | procurement_notices, related=true, 협력사 모집 제외 | 중복 정리 후 마감 빠른 순, 300건까지 |
| 협력사 모집 | 공고 유형 '협력사 모집' | — |
| 신규단지 | building_sales_pipeline | 세대수 큰 순, 100건까지 |
| 준공·입주 시설 | operating_facility_prospects | 세대수 큰 순 30곳 표시, 전체 수는 따로 셈 |

**다른 화면에서 쓰는 곳**

| 화면 | 쓰는 방식 |
|---|---|
| 입찰 요약 '오늘 등록 (관련)' 카드 | 같은 기준 |
| 입찰 목록 카드 | 'DB 등록 {날짜}' + 「오늘 등록」 배지 |
| 입찰 '최근 등록 순' 정렬 | first_seen_at 최근 순 |
| 준공·입주 시설 목록 | 'DB 등록' + 「오늘 등록」 배지 |
| 홈 '새 입찰 N건 · 협력사 모집 N건' | 같은 기준 |

- **주의**: '오늘 등록' 화면은 진행 상태를 보지 않는다. 그래서 대상아님·미참여로 정리한 공고도 그날 목록에 그대로 나온다.

**메뉴·화면**

- 입찰 탭 전체와 상세
- 계약만료 화면 전체 — 데이터가 입찰 공고의 계약 종료일에서 나오기 때문

| 화면 | 입찰 요소 |
|---|---|

## 부록: 코드에서 확인된 주의점

워크인에서 그대로 따라 할지 정해야 하는 것들이다.

**입찰**

- 중복 공고 합치기는 **한 쪽(50건) 안에서만** 적용된다. 쪽이 다르면 합쳐지지 않는다.
- '최근 등록 순' 으로 볼 때도 목록 위 안내 문구는 "최근 마감 순" 으로 나온다. 실제 정렬은 최근 등록 순이다.
- 요약 화면 '입찰' 숫자와 입찰 '진행 중' 숫자는 다를 수 있다.
  - 요약은 KST 마감일 기준이고 사전규격을 포함한다.
  - 입찰 화면은 현재 시각 기준이고 사전규격을 뺀다.

**신규단지**

- 신규단지 화면만 미참여를 숨기지 않는다. 다만 신규단지에는 미참여 버튼이 없다.

**홈**

- '다가오는 연락 · 지연 일정' 카드의 '지연' 구역은 항상 비어 있다. 코드가 빈 목록을 넘긴다.

**거래처**

- 목록 쿼리가 전화번호·메모를 읽지 않는다. 그래서 휴대폰 카드에 전화 버튼이 안 나오고, 📝 메모 빠른 수정 창이 빈 채로 열린다.
- 연락 지연 수를 서버 시간대로 계산한다 (KST 아님). 업무 화면의 오늘·지연 판정도 같다.
- CSV 내보내기는 보기(계약 고객 등)를 반영하지 않는다.

**일정**

- 종류를 건드리지 않고 저장하면 옛 값 '미팅' 으로 저장된다. 기본값이 옛 값으로 남아 있다.

**진행 영업**

- 관리자에게만 보이는 하단 설명이 "1차연락완료부터 계약검토까지" 로 되어 있다. 실제로는 신규리드·보류도 포함된다.
