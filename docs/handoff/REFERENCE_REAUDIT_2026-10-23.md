     - ② 계약 방법: 내 서명만 / 비대면 / 대면
     - ③ 참여자: 순서, 참조자 탭, 만료일, 개별 메시지, 첨부 요청, 전달 방법(문자 자동·메일)

     - 놓은 칸은 서명자 색으로 칠하고 크기 조절·필수 지정이 된다.
     - 되돌리기·확대를 지원한다.
     - 서명자마다 서명·도장 칸이 1개 이상 없으면 '다음'을 막는다.
  4. 서명자 화면: 내 칸만 강조, [다음 칸] 이동, 칸 종류별 입력 창, 첨부 올리기, 휴대폰 우선(375px).
  5. 완료본
     - 원본 PDF 좌표에 값을 합성하고 감사 추적 쪽(열람·서명 시각·IP·기기·원본/완료본 SHA-256)을 붙인다.
     - 자료실에 보관하고, 거래처·업무 타임라인에 기록한다.
  6. 직원이 아닌 상대(거래처)와 계약할 수 있게 한다.
     - 리드·거래처 상세와 영업 '제안·계약'에 [전자계약 보내기]를 둔다.
  7. 칸을 놓은 서식을 저장할 수 있게 한다. 대량 전송·링크 계약은 3차로 미룬다.
     - 데이터: contract_fields·contract_ccs·contract_attachments_req 추가형(문서 5절)

## 5. 기록·검수 과정의 빈틈과 권고

### 1. 대표 메시지 원문 누락
- ceo-msgs.txt·user-msgs.txt를 만든 추출 스크립트(extract-user.cjs)는 `type:"user"`만 읽었다.
- 대표가 작업 중에 입력한 메시지는 대화 기록에 `type:"attachment"`(attachment.type=`queued_command`)로 남는데, 이것을 읽지 않았다.
- 그래서 **135건**(중복 제거, 10/13~10/22)이 빠졌다. 10/23 01:10 '전체 검수(357건→689건)'도 이 원문을 대조하지 않았다.
- 매트릭스에는 LOCAL_LOG 요약을 거쳐 일부만 들어가 있다.
- 권고: 대기열 메시지를 포함해 다시 추출(이미지 첨부 수 포함)하고 전체 검수를 다시 돌린다.

### 2. 레퍼런스를 실물 대신 문서로 조사
- 글로싸인: 10/20 대표가 "체험이 필요하면 사이트를 열어서 회원가입 혹은 로그인 요청"이라고 했다. 그런데 그날 설계는 검색 AI 요약으로 했다(대화 기록 10/20 15:02 KST).
- 폴시아: 도움말만 봤다.
- 카카오워크: 앱·관리 화면을 보지 않았다.
- 권고
  - 레퍼런스 요청이 오면 첫 단계에서 실제 제품을 캡처한다. 로그인이 필요하면 그때 대표를 호출한다.
  - 캡처 → 비교표 → 개발 지시 순서로 진행한다.

### 3. '있으면 ✅' 판정
- 매트릭스·감사가 '기능 존재'를 기준으로 ✅를 줬다. 대표 기준은 '레퍼런스처럼 보이고 동작하는가'다.
- 권고
  - 레퍼런스 항목은 나란히 캡처한 비교표와 대표 확인이 있어야 ✅로 한다.
  - 상태 칸에 '레퍼런스 일치'를 따로 둔다.

### 4. 네이티브 묶음 정체
- 앱 빌드가 필요한 레퍼런스 4건이 '클라우드는 API, 로컬은 네이티브'로 나뉜 뒤 네이티브가 착수되지 않았다.
  - R02 알림창 버튼
  - R03 전체화면 알람
  - R04 알림창 묶음
  - R15 위젯
- 권고: 한 번의 앱 빌드(1.1.3)에 묶어 일정을 정하고 내부 테스트로 배포한다.

### 5. 배포했지만 확인 안 한 것
- R05 영상 v2(오늘)
- R17 투어
- R37 휴대폰 순서 끌기
- R26·R27 휴대폰 캘린더
- R45 견적서
- 로컬이 운영·실기기 확인을 먼저 하고 대표에게 보고한다.

### 6. 기준 코드 차이
- 로컬 main이 origin/main보다 3커밋 뒤다(e8467fab·04367b83·1d6d535a).
- 다음 작업 전에 fetch → merge가 필요하다(이번 감사는 읽기 전용이라 merge하지 않음).
