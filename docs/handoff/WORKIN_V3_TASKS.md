# 워크인 업무 화면 3차 — 서로 배정 · 지시자 · 마감/우선순위/순서 (대표 지시 2026-10-13)

## 0. 버그 — 업무 0건인 사람은 담당자 묶음이 안 생김
- 위치: `src/components/TaskViews.tsx` GroupedTasks, `group === 'assignee'` — `ensure(user.id)` + 업무가 있는 담당자만 묶음 생성.
- 결과: 운영에서 칩에는 김민수가 보이는데 목록엔 "이동재" 묶음만 있고 "김민수님에게 업무 추가" 줄이 없음.
- 수정: 상단 사람 칩과 같은 목록(본사 소속 활성 사용자 = `people`)을 **업무가 0건이어도 모두 묶음으로** 만든다(빈 묶음은 "업무 없음" + 추가 줄). 순서: 나 → 나머지 이름순 → 담당자 없음.

## 1. 서로에게 배정
- 본사 사람끼리 누구나 서로에게 업무를 배정(담당자 선택 목록 = 본사 활성 사용자 전체). 서버 `validateRefs` 는 활성 사용자만 검사하므로 유지하되, 배정받은 사람이 그 업무를 볼 수 있는지(담당자 열람 허용) 시험 추가.
- 본사 3명이 서로 전체 업무를 보려면 권한이 **대표 또는 본사 관리자**여야 함 → 사용자 관리 화면에서 "직원" 권한으로 본사 소속이면 "본사 사람끼리 전체 열람" 안내(또는 본사 조직 소속 직원도 본사 업무 전체 열람으로 규칙 조정 — 클라우드 판단, 다른 조직 404 원칙은 유지).

## 2. "지시자(업무를 부여한 사람)" 칸
- 새 필드 `requested_by`(추가형 마이그레이션, 기본값 = 만든 사람). 업무 등록 창·인라인 추가·상세 패널에서 **선택 가능**(본사 사람 목록).
- 목록 행에 "○○ → ○○"(지시자 → 담당자) 작은 표시, 필터·묶기에 "지시자별" 추가, "내가 지시한 업무" 칩(Asana 홈의 "내가 배정한 작업").
- 알림: 담당자가 완료·검토 요청하면 지시자에게 알림. 변경 이력에 지시자 변경 기록.

## 3. 마감일·우선순위·순서 (Asana 목록 수준)
- 목록 행에서 바로 편집: **마감일 칩**(오늘·내일·이번 주 금·다음 주 월·날짜), **우선순위 칩**(긴급·높음·보통·낮음 색 표시), 담당자 칩, 지시자 칩.
- **직접 순서 정하기**: 행 왼쪽 손잡이로 끌어 묶음 안 순서 변경(기존 `sort_order` 사용, 저장 즉시 반영, 다른 사람 화면에도 같은 순서). 묶음 사이로 끌면 담당자/마감 묶음 값 변경.
- 정렬 선택: **직접 순서(기본) · 마감일순 · 우선순위순 · 최근 생성순**. 선택은 사용자별로 기억.
- 열 머리(PC): 업무 이름 | 담당자 | 지시자 | 마감일 | 우선순위 | 상태 — 열 머리 클릭 정렬.

## 4. 완료 기준
- 운영에서 "전체" 보기에 본사 3명 묶음이 모두 보이고 각 묶음 끝 "○○님에게 업무 추가"로 바로 배정
- 지시자 선택·표시·"내가 지시한 업무" 칩 동작, 완료 시 지시자 알림

## 5. 추가 (대표 운영 화면 재확인 2026-10-13 14:45) — 아직 미반영, 최우선
- **여전히 "전체"에 이동재 묶음만 보임**(0번 버그 그대로). 칩에는 김민수·김소담·이동재가 있음.
- **상단 직원 이름 칩 = 필터**: "전체"는 본사 3명 묶음을 모두 펼쳐 보이고, 이름 칩을 누르면 그 사람 업무만(그 사람 묶음 + "○○님에게 업무 추가"). 다시 누르면 해제(전체로).
- **"업무 하나 만든 뒤 추가로 만들 수 없음"** — 운영(대표 계정, PC Chrome·한글 입력)에서 발생. 로컬 최신 빌드(fixture 데이터)에서는 상단 "+ 업무 추가"·묶음 끝 줄 모두 연속 2건 저장됨(재현 안 됨). 확인 요청:
  1. 한글 IME: Chrome 에서 조합 중 Enter 는 `isComposing=true` 로 무시되고 두 번째 keydown 이 오지 않음 → 사용자는 "Enter 눌러도 안 됨"으로 느낌. `compositionend` 직후 Enter 처리(예: `onKeyUp`/플래그) 또는 저장 버튼(↵ 아이콘) 추가.
  2. 화면 캡처상 이동재 묶음이 **0건** — 만든 업무가 목록에 안 보이는 것일 수 있음. 운영 DB 에서 오늘 이동재 계정이 만든 tasks(created_by·assignee_id·org/brand·status) 확인하고, 다른 사람에게 배정되면 0번 버그로 묶음이 없어 사라져 보이는지 확인.
  3. 저장 실패 시 오류 토스트가 확실히 보이게(입력값 유지).
- E2E: 한글 조합 입력 후 Enter 로 2건 연속 등록, 다른 사람 배정 후 "전체"에 그 사람 묶음에 표시.

## 6. 대표 앱(Android) 재확인 2026-10-13 15:12 — c7f35a1 반영 후 (`local-screens/51-app-tasks-v3-add-other.jpg`)
본사 3명 묶음·내가 지시한 업무·정렬(직접 순서)은 보임. 남은 문제:
1. **다른 사람 묶음에서 업무 추가가 안 됨** — 캡처: 김민수 묶음 끝 줄에 "두정점 원판 수량 파악"·오늘·민수 칩까지 입력된 채 저장 안 됨. 내 묶음만 추가됨.
   - 서버(`validateRefs`)는 다른 사람 배정 허용 → 화면 쪽 의심. 휴대폰 키보드(삼성·Gboard)는 Enter 가 `key: 'Unidentified'`/keyCode 229 로 오거나 조합 끝 이벤트 순서가 달라 `onKeyDown` Enter 가 안 잡힐 수 있음.
   - 요청: 입력을 `<form onSubmit>` 으로 감싸 키보드 "완료/이동" 버튼이 확실히 저장되게(`enterKeyHint="done"`), **입력 중에는 오른쪽에 "저장" 버튼**(44px) 표시. 저장 실패는 오류 문구로 표시하고 입력값 유지.
2. **업무를 만들었는데 갑자기 사라짐** — 의심: (a) `queueOffline` 으로 들어가 "대기열" 안내 후 입력만 지워짐(앱 WebView 에서 요청 실패 시), (b) 목록 새로고침 때 정렬/묶음 이동으로 접힌 묶음(김소담 접힘 상태)으로 들어감, (c) 담당자 칩만 바꾼 뒤 저장되어 다른 묶음으로 이동. 저장 직후 **"○○님에게 추가됨 · 보기" 토스트**와 새 행 강조(2초) 필요. 운영 DB 에서 오늘 이동재 계정 created 업무·activity 확인 부탁.
3. **업무 순서 정하기** — 휴대폰에서 손잡이 끌기가 안 보이거나 안 됨. 휴대폰: 행 길게 누르기 → 끌기, 또는 행 메뉴 "위로/아래로/맨 위로". 묶음 사이 이동도.
