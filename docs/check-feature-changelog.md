# 「점검」 기능 — 단계별 변경 기록

설계: [check-feature-design.md](check-feature-design.md) · 원문: [reference/prompt-b-check-feature.md](reference/prompt-b-check-feature.md)

## 1단계 — 점검 가이드 (2026-11-20)

### 들어가는 길
- 메뉴 **점검**(PC 사이드바 '공통' 묶음의 공지 아래 · 휴대폰은 프로필(오른쪽 위 얼굴) › 메뉴 목록). 주소 `/check`.
- 누가 무엇을 보나(메뉴 권한 '점검 가이드' — 관리 › 권한에서 바꿈)
  | 권한 | 기본값 | 보이는 것 |
  |---|---|---|
  | 편집 | 대표·관리자 | 점검 가이드 · 직원 공유 양호 기준 · 분야·공간(템플릿) |
  | 보기 | 부서장·현장 관리자 | 점검 가이드(읽기) · 직원 공유 양호 기준 |
  | 없음 | 직원 | 직원 공유 양호 기준만(관리자가 공유를 켠 항목) |

### 처음 쓰는 순서
1. **점검**을 엽니다. 처음 열면 공통 기본 템플릿(분야 8개 · 공간 유형 6개 · 항목 20개)이 들어 있습니다. 가입 때 업종을 고른 회사는 그 업종 템플릿도 함께 들어 있습니다.
2. 항목을 눌러 우리 회사에 맞게 고칩니다: 양호 기준, 놓치기 쉬운 곳, 보완 시 조치, 권장 주기. 고친 까닭을 적으면 개정 이력에 남습니다.
3. **[사진 추가]** 로 기준 사진(양호한 모습)을 올립니다. 항목마다 6장까지.
4. 직원이 알아야 할 항목은 **[직원에게 공유]** 를 켭니다. 직원은 양호 기준·놓치기 쉬운 곳·기준 사진만 봅니다(조치·근거 메모는 안 보임).
5. **[직원 공유 양호 기준]** 탭에서 **[글자로 복사]**(메신저·문자에 붙이기) 또는 **[인쇄·PDF 저장]**.
6. 필요하면 **[분야·공간]** 탭에서 분야·공간 유형을 더하고, 곳별 실제 공간 이름(예: 2층 화장실)을 적고, 다른 업종 템플릿을 더 넣습니다.

### 만든 것
- 표(마이그레이션 262, 새 표만): 분야 · 공간 유형 · 곳별 공간 · 점검 항목 · 개정 이력 · 사진 · 템플릿 설치 기록. 모두 회사 칸으로 나뉨.
- 권한 키 3개: 점검 가이드(없음/보기/편집) · 점검하기(2단계에서 씀) · 점검 리포트(4단계에서 씀).
- 템플릿(코드에 든 자료): 공통 기본 + 업종 3종(운동시설 · 아파트·건물 공용 시설 · 카페·음료). 가입 업종과 잇기: 운동·피트니스 → 운동시설, 시설관리·용역/건설·시설관리 → 아파트·건물 공용 시설, 외식·카페 → 카페·음료.
  한 번 설치한 템플릿은 다시 넣지 않습니다(안 쓰게 하거나 없앤 항목이 되살아나지 않음).
- 기준 사진: 올리기 전에 휴대폰에서 줄이고(긴 변 1600px), 회사 저장공간 한도에 함께 셉니다.
- 직원 공유용 양호 기준 내보내기: 글자로 복사 · 인쇄(PDF 저장).
- 화면 글은 `src/lib/check/copy.ts` 한곳. 업종 낱말은 템플릿 자료에만 있습니다.

### 시험
- API: `check-guide`(권한·회사 분리·개정 이력·직원 공유) · `check-templates`(가입 때 설치·처음 열 때 설치·업종 더 넣기·기준 사진·저장공간)
- 화면: 375px 에서 가이드·항목 작성·사진·직원 공유·템플릿 넣기, 직원 화면
- 금칙어 검사: 통과(기준 그대로 — 업종 템플릿 이름도 범용 낱말로)

### 남은 것 · 알아 둘 것
- 기본 회사 전용 설정(원문 부록 4 — 코스, 현장 체크 항목, 업체 이름)은 넣지 않았습니다. 코드에 넣지 않고 그 회사 자료로 넣는 것이 원칙이라, 2단계(점검 코스)가 생긴 뒤 화면에서 넣거나 대표가 내용을 정해 주시면 자료로 넣습니다.
- 사진을 지우면 기록만 지워지고 저장소의 파일은 남습니다(정리 작업은 사진 보관 기간 규칙과 함께 2단계에서).
- '이미지로 내보내기'는 따로 만들지 않았습니다(인쇄 화면을 PDF 로 저장하거나 화면을 찍어 쓰는 것으로 대신).
- 공간(곳별 실제 공간)은 등록·보기만 됩니다. 이름 고치기·순서 바꾸기는 2단계 점검 코스를 만들 때 함께.

### 다음(2단계) 제안
- 점검하기(코스를 따라 양호/보완 필요/해당 없음 + 사진 + 메모), 수시 점검
- 보완 요청 = 업무로 만들고, 보완 확인은 점검 쪽 상태(확인 대기 → [양호 확인]/[다시 보완])로 — 업무의 검토 기능에 기대지 않음(대표 11/18 원칙)
- 같은 항목 3회 연속 보완 필요 → 개선 과제, 외부 연락 기록과 회신 기한 알림

## 2단계 — 점검하기 · 보완 흐름 (2026-11-20, 만드는 중 — 1단계 운영 확인 뒤 올림)

### 들어가는 길
- 메뉴 **점검** › **[점검하기]** 탭(메뉴 권한 '점검하기·보완 확인'이 있는 사람 — 기본: 대표·관리자·부서장·현장 관리자). 이 권한이 있으면 점검을 열 때 이 탭이 먼저 보입니다.

### 쓰는 순서
1. 곳(지점)과 **점검 코스**를 고르고 **[점검 시작]**. 처음에는 '기본 매장 점검'(출입구·로비 → 고객 이용 공간 → 화장실 → 직원 공간 → 창고) 코스가 들어 있습니다.
2. 항목마다 **[양호] [보완 필요] [해당 없음]** 을 누릅니다. 항목을 누르면 확인 방법·놓치기 쉬운 곳·기준 사진이 펼쳐집니다. 메모와 사진을 붙일 수 있습니다.
3. **[점검 끝내기]** 에서 보완 필요 항목마다 담당자와 기한을 정합니다 → 담당자에게 **보완 요청 업무**가 갑니다(사진 1장 필수, "무엇을·어디를·언제까지" 요청형 글).
4. 담당자는 평소 업무 화면에서 조치 사진을 올리고 **[완료]** 합니다(검토 요청은 필요 없음).
5. 점검자에게 '보완 확인 요청' 알림 → 점검하기 탭의 **보완 요청** 목록에서 사진을 보고 **[양호 확인]** 또는 **[다시 보완]**.
   - [다시 보완]은 까닭을 적어야 하고, 같은 담당자에게 새 업무(2차)가 갑니다. 앞 업무는 완료 그대로 남습니다.
6. 코스 없이 본 것만 적으려면 **[수시 점검]**.

### 만든 것
- 표(마이그레이션 264, 새 표만): 점검 코스 · 점검 1회 · 항목별 결과 · 보완 요청 · 외부 연락 · 개선 과제.
- 보완 확인은 업무의 검토 기능에 기대지 않습니다(대표 11/18 "검토는 완료의 조건이 아니다"). 업무가 완료되면 보완 요청이 '확인 대기'로 보이고, 확인은 점검 화면에서 합니다.
- 같은 항목·같은 곳이 **3회 연속** 보완 필요면 **개선 과제** 업무 1건(기준 보완 · 다시 안내 · 장비 교체 · 주기 변경 가운데 정하기). 열린 과제가 있으면 또 만들지 않습니다.
- 외부 업체·건물 관리처 연락: 끝내기에서 대상과 회신 기한을 적으면 기록되고, 기한이 지나면 알림. 결과를 적으면 닫힙니다.
- 점검 코스 관리: 점검 › [분야·공간] 탭에서 돌 순서대로 공간 유형을 눌러 만듭니다(곳 전용 코스 가능).
- 결과에는 그때의 항목 이름·양호 기준·판 번호를 함께 남겨, 나중에 가이드를 고쳐도 기록은 그대로입니다.

### 시험
- API `check-rounds`: 권한·코스 · 점검 기록 · 끝내기 · 보완 확인(다시 보완 → 양호 확인) · 개선 과제 · 외부 연락 · 수시 점검 · 회사 분리
- 화면(375px): 점검 → 보완 요청 → 조치 → 다시 보완 → 양호 확인 → 수시 점검 → 코스 만들기

### 남은 것 · 알아 둘 것
- ~~홈의 '오늘 점검' 카드, 업무 목록의 '점검 보완' 거름 단추는 아직 없습니다~~ → 11/20 넣음(아래 '홈 카드 · 업무 목록 거름').
- 점검 사진 1년 뒤 자동 삭제는 넣지 않았습니다(삭제는 대표 확인 뒤).
- '확인 대기' 알림은 정기 실행 간격(15~30분)만큼 늦을 수 있습니다.
- 표본 점검(정기와 따로 세는 점검)은 자료 칸만 있고 화면에는 아직 없습니다.

## 홈 카드 · 업무 목록 거름 (2026-11-20)

### 홈의 '점검' 카드
- 보이는 사람: 메뉴 권한 '점검하기·보완 확인'이 있는 사람. 점검을 한 번도 하지 않은 회사의 홈에는 나오지 않습니다(점검을 쓰기 시작하면 나옴).
- 보이는 것: **이어서**(내가 하다 만 점검 — 누르면 그 점검으로) · **확인 대기 n**(담당자가 조치를 끝낸 보완 — 누르면 점검 화면) · **조치 중 n** · 열린 것이 없으면 **마지막 점검** 날짜와 곳 · 오른쪽 **[점검하기]**.
- 휴대폰에서 점검으로 들어가는 길이기도 합니다(하단 탭은 그대로 — 설계 6절 대표 결정 2).
- 수는 점검 화면의 '보완 요청' 머리줄과 같은 셈입니다(내가 볼 수 있는 곳 기준).

### 업무 목록 '점검 보완만'
- 업무 › [필터] › **점검 보완만**: 점검에서 만든 보완 요청 업무(꼬리표 '점검 보완')만 봅니다. 점검하기 권한이 있는 사람에게 보입니다.
- 점검 화면 '보완 요청' 머리줄의 **[업무 목록에서 보기]** 로도 갑니다(주소 `/tasks?tag=점검 보완` — 이 주소로 들어오면 권한이 없어도 거름이 걸리지만, 볼 수 있는 업무만 나옵니다).

### 시험
- API `check-home-1120`: 권한 없는 직원·점검을 안 한 회사는 카드 없음 · 이어서 · 조치 중 → 확인 대기 → 0 · 점검 화면과 같은 셈 · 꼬리표 거름(정확히 같은 꼬리표만, 권한 규칙 그대로) · 회사 분리
- 화면(375px): 홈 카드(조치 중 1 · 마지막 점검) → [점검하기] → [업무 목록에서 보기] → '점검 보완만' 표시와 그 업무 한 줄

## 4단계 가운데 점검 리포트 — 숫자·표 (2026-11-20)

원문 범위 4번("지점·분야·항목별 양호율, 반복 항목, 보완 처리 기간")을 AI 없이 숫자와 표로 만들었습니다. 설계는 docs/check-feature-design.md 12절.

### 들어가는 길
- 메뉴 **점검** › **[리포트]** 탭. 메뉴 권한 '점검 리포트'가 있는 사람에게만 보입니다(기본: 대표·관리자).

### 보는 것
- 위에서 기간(**이번 달 · 지난달 · 최근 90일 · 직접 고르기**)과 곳을 고릅니다. **[엑셀]** 로 내려받습니다(요약 · 곳별 · 분야별 · 항목별 · 보완 요청 시트).
- 요약 4칸: 끝낸 점검 n회 · **양호율**(지난 기간과 견줌) · 보완 요청 n건(열린 것) · 평균 처리 기간.
- 표: **곳별**(점검 횟수·양호율·보완 필요·열린 보완) · **분야별** · **보완이 잦은 항목**(위에서 10개) · **반복 항목**(같은 곳에서 보완 필요 2번 이상 — 지금 몇 번 연속인지, 개선 과제가 열려 있는지) · **보완 처리 기간**(닫힘·확인 대기·조치 중·기한을 넘긴 것·다시 보완·평균·가장 긴 것, 닫히기까지 며칠).

### 셈 규칙(화면 아래에도 적혀 있음)
- 고른 기간 안에 **끝낸** 점검만 셉니다(서울 날짜). 하다 만 점검은 "진행 중 n회는 빼고 셈"으로만 보입니다.
- 양호율 = 양호 ÷ (양호 + 보완 필요). '해당 없음'은 뺍니다.
- 처리 기간 = 보완 요청을 보낸 날 → [양호 확인]으로 닫힌 날. 같은 날이면 '당일'.
- 볼 수 있는 곳만 셉니다. **사람별 순위는 만들지 않습니다**(직원 평가표가 아니라 기준이 지켜지는지 보는 표).

### 넣지 않은 것
- AI 요약 · 고객사 보고용 문장(비용이 드는 일 — 대표 결정 뒤).
- "직원 체크는 완료인데 점검은 보완 필요" 목록(외부 체크 앱 연동 뒤).
- 달마다 리포트를 메일·알림으로 보내기(원문에 없음 — 필요하면).

### 시험
- API `check-report` 4묶음: 권한(직원·점검하기만 있는 사람 404) · 셈(양호율·분야·항목·반복·진행 중 제외) · 처리 기간·기한 넘김·다시 보완·지난 기간·서울 날짜 경계 · 곳 범위·회사 분리·엑셀
- 화면(375px): [리포트] 탭 → 숫자 → 지난달(빈 화면) → 이번 달

### 담당자별 보완 처리 표 (2026-11-20 추가 — 대표 결정)
