# 휴대폰 화면 전체 공유 — 앱 작업 규격 (로컬 담당: mobile/android · mobile/ios)

작성 2026-11-20 · 클라우드 · 대표 11/19 "영상회의 화면에서 핸드폰이나 컴퓨터 화면 공유하면서 회의할 수 있도록"

## 1. 왜 앱 작업이 필요한가
- 컴퓨터 브라우저: 화면 공유가 됩니다(브라우저 기능 `getDisplayMedia`).
- **휴대폰 브라우저와 앱의 웹 화면(WebView)**: 이 기능이 없습니다(안드로이드·아이폰 공통, 운영체제 제약). 대표가 휴대폰에서 [화면 공유]를 눌렀을 때 실패한 까닭입니다.
- 그래서 **앱(네이티브)이 기기 화면을 잡아** 영상 서버에 그 사람의 **두 번째 접속**(화면만 보내는 접속)으로 보내는 방식으로 갑니다. 웹 화면의 회의(카메라·마이크·채팅)는 그대로 두고, 화면만 앱이 따로 보냅니다.
- 그사이 휴대폰에서 되는 것(웹만으로, 11/20 반영): 사진·PDF 보여 주기 · 앞뒤 카메라 전환(실물 비추기).

## 2. 클라우드가 끝낸 것(서버·웹)
### 서버 — 화면 전용 입장권
- 직원: `POST /api/meetings/:id/screen-ticket` (로그인 쿠키)
- 손님: `POST /api/meet/:code/guest/:pid/screen-ticket` (헤더 `x-guest-secret`)
- 답: `{ engine, url, token, identity, expiresIn }`
  - `url` = 영상 서버 주소(wss://…) · `token` = 입장권(JWT, 10분 안에 접속에 써야 함) · `identity` = `<참가자 id>~screen`
  - 입장권 권한: **화면(screen_share)·화면 소리(screen_share_audio)만 보낼 수 있음.** 받기·채팅·방 관리 불가. 이름은 "○○ 화면".
- 조건: 회의에 들어와 있는 사람 + 화면 공유가 허락된 사람(회의 규칙 '주최자만'이면 참가자·손님은 403). 끝난 회의 410.
- 본 참가자가 **나가거나 내보내지면** 서버가 화면 접속도 끊습니다(영상 서버에 내보내기 요청). 엔진 알림에 화면 접속이 와도 회의 기록·인원에는 세지 않습니다.

### 웹 — 앱 기능을 부르는 자리 (`src/components/native.ts`)
플러그인 이름 **`WorkinScreenShare`**. 웹은 `Capacitor.isPluginAvailable('WorkinScreenShare')` 이고 `isSupported()` 가 true 일 때만 공유 창에 **[휴대폰 화면 공유]** 단추를 보입니다(플러그인이 없는 예전 앱·브라우저에는 단추가 없음 — 웹을 다시 배포할 필요 없음).

| 부르는 것 | 모양 | 뜻 |
|---|---|---|
| `isSupported()` | `→ { supported: boolean }` | 이 기기·OS 판에서 되는지 |
| `start({ url, token, title? })` | `→ { started: boolean }` | 권한 창 → 허용하면 영상 서버에 접속해 화면 보내기 시작. 거절·실패면 `started: false`(또는 오류) |
| `stop()` | `→ void` | 공유 멈추고 접속 끊기 |
| 이벤트 `stopped` | `addListener('stopped', fn)` | 기기 쪽에서 끝났을 때(알림의 [중지] · 방송 종료 · 연결 끊김 · 서버가 내보냄) |

- 회의 화면은 이름표가 `~screen` 으로 끝나는 접속을 **사람 칸·인원에 세지 않고 공유 화면으로만** 보여 줍니다. 본인 휴대폰에는 화면 대신 "내 휴대폰 화면을 공유하고 있습니다" 안내와 [공유 멈추기]가 뜹니다.
- 웹은 회의 화면을 떠날 때 `stop()` 을 부릅니다.

## 3. 로컬이 할 것(앱)
### 안드로이드 (먼저 — 대표 기기)
1. 영상 서버용 안드로이드 SDK(LiveKit Android)를 앱에 넣고, 플러그인 `WorkinScreenShare` 를 만듭니다.
2. `start`: 화면 녹화 권한 창(MediaProjection) → **포그라운드 서비스(종류 mediaProjection)** 를 띄운 뒤 → `url`·`token` 으로 방에 접속 → 화면 공유 켜기. 알림에 "화면 공유 중 · [중지]".
3. 안드로이드 14 이상: 권한 `FOREGROUND_SERVICE_MEDIA_PROJECTION` 과 매니페스트의 서비스 종류 선언이 필요하고, 권한 결과는 한 번만 쓸 수 있습니다(서비스를 먼저 띄운 뒤 화면 잡기).
4. `stopped` 이벤트: 알림 [중지] · 시스템이 캡처를 끝냄 · 방 연결이 끊김(서버가 내보냄 포함).
5. 확인할 것: 다른 앱으로 넘어가도 **회의의 마이크 소리가 유지되는지**(웹 화면이 뒤로 가면 카메라는 꺼지는 것이 정상, 마이크는 서비스 종류에 microphone 을 더해야 할 수 있음).
6. 스토어: Play Console 에 포그라운드 서비스(mediaProjection) 사용 선언이 필요합니다(심사 항목). 민감 정보 안내 — 화면에 알림 내용이 비칠 수 있음(웹 단추 설명에 "방해 금지를 켜 두세요"라고 적어 둠).

### 아이폰·아이패드 (그다음 — 난도 높음)
1. 기기 화면 전체는 **방송 확장(Broadcast Upload Extension)** 이 있어야 합니다(새 타깃 + 앱 그룹). 앱 안 화면만 잡는 방식은 다른 앱을 보여 줄 수 없어 목적에 맞지 않습니다.
2. 다른 앱으로 넘어가 있는 동안 회의(웹 화면)의 소리가 유지되는지가 함께 풀려야 합니다(백그라운드 오디오).
3. 심사: 새 확장·권한 설명 글이 필요합니다. iOS 재제출(지금 진행 중인 것)과 **섞지 말고 다음 판으로** 가는 것을 권합니다.

### 작업량(추정 — 해 보기 전 값)
안드로이드 2~4일 · 아이폰 4~7일. SDK 의 정확한 호출 이름·설정은 공식 문서로 확인해 주세요(여기에는 방식만 적었습니다).
