# iOS 1.2.0 반려(11/15 심사) — 원인과 고칠 안

작성 2026-11-19 · 클라우드. 반려 사유 원문은 로컬이 App Store Connect 해결 센터에서 읽어 전달한 것(5건). **아직 고치지 않았습니다 — 아래는 제안이고, 대표 결정 뒤 구현합니다.**

## 1. 한 장 요약

| 사유 | 원인(코드·운영에서 본 것) | 고칠 안 | 새 빌드 |
|---|---|---|---|
| 1. 로그인 화면에 요금 주소(`/#pricing`) | 앱 화면 자체에는 요금·가입 길이 없음(아래 2절 확인). 남는 길은 **소셜 로그인 때 뜨는 시스템 브라우저 창** — 그 창은 일반 사파리로 보여 서버가 앱인지 모르고 웹 화면(소개·요금·체험 신청)을 그대로 보여 줌 | 아이폰·아이패드 앱은 **이메일 로그인만**(소셜 로그인 단추 전부 뺌) → 브라우저 창이 안 뜸 | 필요 없음(웹만) |
| 2. 사업자·단체 가입 기능 | 위와 같은 창에서 웹 가입 화면에 닿음 | 위와 같음 + 앱에서 시작한 브라우저 창에는 '앱에서 옴' 표시를 심어 웹 화면도 앱 모양(가입·요금 없음)으로 | 필요 없음 |
| 3. 연령 등급 | 스토어 설정 | 로컬이 ASC 설문에서 'Messaging and Chat = Yes'(대표 승인 뒤) | — |
| 4. 외부 AI 로 보내는 데이터 동의 | 가입 때 'AI 동의' 칸은 **선택이고, 체크 여부를 어디서도 확인하지 않음**. 초대로 들어온 직원은 묻지도 않음. 자료실에 파일을 올리면 **묻지 않고** 자동 정리용으로 AI 에 보냄. 안내 글에는 받는 곳이 2곳만 적혀 있음 | 사람마다 **AI 사용 동의 화면**(보내는 것·받는 곳·동의/거부) + 서버에서 동의 없으면 AI 로 안 보냄 + 처리방침·AI 안내 글 고침 | 필요 없음(권한 문구까지 고치려면 필요) |
| 5. Apple 로그인 실패 | 고장이 아니라 **일부러 막은 것**: 아이폰 앱에서 처음 보는 Apple 계정이면 "연결된 워크인 계정이 없습니다" 안내를 띄움(`src/lib/oauth.ts` — 앱에 가입이 없으므로). 심사자는 새 Apple 계정으로 눌러서 이 안내를 '오류'로 봄 | 1번 안대로 아이폰 앱에서 Apple 로그인 단추를 빼면 사라짐 | 필요 없음 |

- 1·2·5 는 한 가지로 풀립니다: **아이폰·아이패드 앱 = 이미 있는 회사 계정으로 이메일 로그인만.** 소셜 로그인이 없으면 Apple 로그인을 넣을 의무(4.8)도 없습니다(회사 계정 전용 업무 앱).
- 4 는 사용자 화면이 바뀌는 일(다짐 직원 포함 모든 사용자에게 동의 화면이 한 번 뜸)이라 대표 결정이 필요합니다.
- 모두 웹 쪽 변경이라 **앱을 새로 빌드하지 않아도 됩니다.** 다만 같은 빌드로 다시 내면 심사자가 '빌드가 그대로'라고 볼 수 있으니, 해결 센터 답글에 "서버 쪽에서 고쳤다"와 확인 순서를 적어야 합니다(5절).

## 2. 확인한 것과 확인 못한 것

- 운영(www.work-in.dev)을 아이패드 앱과 같은 표시(맥 표시 + `WorkInApp`)로 돌아봄: 로그인 화면의 링크는 소셜 로그인 단추·이용약관·개인정보 처리방침·계정 삭제·AI 이용 안내뿐. `/`·`/welcome`·`/signup` 은 모두 로그인으로 돌아감. 약관류 화면의 '워크인' 로고도 로그인으로 돌아감 → **앱 화면 안에서는 요금·가입에 닿지 않음.**
- `https://www.work-in.dev/#pricing` 이라는 주소 모양은 **첫 화면(/)이 소개 화면으로 보일 때만** 나옴(소개 화면 머리줄 [요금]). 첫 화면이 소개로 보이는 것은 앱 표시가 없는 브라우저뿐 → 소셜 로그인용 시스템 브라우저 창이 유력.
- Apple 로그인 시작 주소는 정상: 서비스 ID `dev.work-in.signin`, 돌아오는 주소 `https://www.work-in.dev/api/auth/oauth/apple/callback`, 303 으로 Apple 화면까지 감. 주소 분리(www/app)는 운영에서 꺼져 있어 원인이 아님.
- **확인 못함**: 심사자가 실제로 누른 순서(재현은 못 함 — Apple 계정 로그인이 필요), 11/15 15시(UTC) 전후 서버 기록(운영 DB 를 볼 수 없음. 다만 '연결된 계정 없음'은 오류로 기록하지 않는 정상 응답이라 오류 목록에 없을 것).
- 로컬이 볼 것: Apple Developer › Identifiers › Services ID `dev.work-in.signin` 의 Return URLs 에 위 주소가 있는지(있어야 정상 — 지금도 Apple 화면까지는 가므로 맞을 것).

## 3. 고칠 안 — 로그인(사유 1·2·5)

1. **아이폰·아이패드 앱 로그인 화면**: Apple·구글·카카오·네이버 단추를 모두 숨김. 이메일·비밀번호만. 안내 한 줄 "계정은 회사 관리자의 초대로 만들어집니다"(지금 있는 글).
2. **설정 › 계정의 소셜 계정 연결**도 아이폰 앱에서는 숨김(같은 브라우저 길을 타지 않게).
3. **방어 한 겹**(안드로이드 앱은 소셜 로그인 유지): 앱에서 시작한 로그인 브라우저 창에는 15분짜리 표시를 심어, 그 창에서 열리는 우리 화면은 모두 앱 모양(소개·요금·가입 없음, 첫 화면은 로그인)으로.
4. 심사용 **체험 계정**(로컬이 이미 쓰는 심사용 계정)은 그대로 — 심사 메모에 아이디·비밀번호를 적으면 됩니다. 로그인 화면에 '체험하기' 단추를 새로 두는 것은 권하지 않습니다(가입·체험 문구로 다시 읽힐 수 있음).
5. 이미 Apple 계정으로만 로그인하던 아이폰 사용자가 있으면: 웹에서 비밀번호를 정하거나 관리자가 재설정 링크를 보내야 함. **로컬 확인 요청**: 운영에 Apple 로 연결된 계정이 몇 개인지(플랫폼 운영에서 보이면).

작업량: 반나절(화면 3곳 + 시험).

## 4. 고칠 안 — 외부 AI 동의(사유 4)

### 4-1. 지금 실제로 외부로 나가는 것(코드 기준)

| 받는 곳 | 무엇을 보냄 | 언제 |
|---|---|---|
| **Anthropic(Claude, 미국)** | AI 비서에 쓴 글·붙인 파일(사진·PDF)·답에 필요한 업무·일정·자료 내용 / 업무 등록 창의 말·글과 동료 이름·직함 / 업무 도우미(업무 제목·설명·댓글·첨부 글) / 메신저 글 → 업무 / 메일·문자 초안 / 회의 녹음을 글로 바꾼 것 / 영상 요약의 장면·글 | 대부분 단추를 누를 때 |
| | **자료실에 올린 파일**(사진·PDF·글) — 자동 정리·분류용 | **올릴 때마다 자동** |
| | 웹 문의·전화 문의 한 줄 요약 | 문의가 들어올 때 자동 |
| **OpenAI(미국)** | 회의 녹음·영상의 **소리**(글로 바꾸기) | 회의록·영상 요약 단추 |
| 음성 합성 업체(OpenAI·ElevenLabs·Google·네이버 중 운영자가 고른 1곳) | 마케팅 영상 내레이션 글 | 마케팅 영상 만들 때(지금 운영은 키 없음 — 로컬 11/15 확인) |
| Higgsfield | 마케팅 이미지·영상 지시문, 참고 사진 | 마케팅 제작(기본 회사만, 지금 멈춤) |

휴대폰의 말하기(음성으로 업무 등록)는 기기 안 음성 인식을 써서 **소리는 서버로 안 옵니다**(글만 옴).

**로컬 확인 요청**: 운영 환경 변수에 `OPENAI_API_KEY` 가 있는지(있다/없다만). 없으면 회의록·영상 요약은 꺼져 있고 받는 곳에서 OpenAI 를 '쓸 때만'으로 적습니다.

### 4-2. 화면(안)

- **처음 AI 기능을 쓰려 할 때** 한 번 뜨는 창(그리고 설정 › 개인정보·AI 에서 언제든 다시):
  - 제목: "AI 기능을 쓰려면 동의가 필요합니다"
  - 보내는 것: 내가 AI 에게 쓴 글과 말, 붙인 파일·사진, 답에 필요한 업무·일정·자료 내용, (회의록을 쓸 때) 회의 녹음
  - 받는 곳: Anthropic PBC(미국) — Claude AI / OpenAI(미국) — 녹음을 글로 바꿀 때만
  - 쓰는 목적: 답 만들기·정리·요약. 받는 곳의 AI 학습에는 쓰이지 않는 방식(API)으로 보냅니다
  - 보관: 받는 곳은 처리 뒤 일정 기간 안에 지웁니다(각 회사 정책) · 워크인 안의 대화 기록은 회사 설정대로
  - 단추: [동의하고 사용] [동의하지 않음]
- **동의하지 않으면** AI 단추를 눌렀을 때 같은 창이 다시 뜨고, 아무것도 보내지 않습니다. 나머지 기능은 그대로.
- **자료실 자동 정리**: 올린 사람이 동의한 경우에만 AI 로 보냄(동의 안 했으면 파일 이름·종류로만 정리).
- **회사 단위 자동 작업**(문의 한 줄 요약, 영업·마케팅 자동 작업): 회사 관리자가 켜고 끄는 **'회사 자료 AI 처리' 스위치**를 관리 › 회사 정보에 둠. 새 회사는 꺼짐에서 시작, 관리자가 같은 안내를 읽고 켬. **다짐은 지금 쓰는 그대로 켜진 상태로 옮김**(대표 확인 필요).
- 동의·철회 기록은 사람·시각·안내 글 판 번호로 남김.

### 4-3. 서버

- 동의 확인을 AI 호출 한곳(요청 수 확인 함수가 이미 20곳에서 불림)과 따로 부르는 3곳(문서 엔진·소리 → 글·내레이션)에 넣음. 동의 없으면 403 `ai_consent` → 화면이 동의 창을 띄움.
- 가입 화면의 'AI 동의' 칸은 지금처럼 선택으로 두되, 체크하면 그 사람의 동의로 기록.

### 4-4. 글 고치기(초안 방향)

- 개인정보 처리방침: 수집 항목에 "AI 기능 이용 시: 입력한 글·음성, 첨부 파일·사진, 답에 필요한 업무·일정 내용" / 처리 위탁·국외 이전 표에 받는 곳별 줄(업체·나라·보내는 항목·목적·보관) / "AI 기능은 동의한 사람만, 설정에서 언제든 철회".
- AI 이용 안내(/ai-notice): "AI 기능을 쓰지 않으면 아무것도 전송되지 않습니다"는 **지금 사실과 다름**(자료실 자동 정리) → 동의 방식으로 바꾼 뒤 사실이 되게 하고, 받는 곳 목록을 4-1 대로.
- 마이크 권한 문구(앱 안 고정 글)는 회의 녹음을 말하지 않음 → 고치려면 새 빌드가 필요(로컬 몫, 이번 반려 사유는 아님).

작업량: 2~3일(동의 저장·창·서버 확인·자료실 갈래·회사 스위치·글 2곳·시험). **다짐 직원에게도 동의 창이 한 번 뜹니다.**

## 5. 다시 낼 때

- 새 빌드 없이 다시 낼 수 있음(모두 서버 쪽). 해결 센터 답글에 적을 것:
  1. iOS 앱은 기존 회사 계정 전용 — 가입·요금·외부 링크·소셜 로그인 없음(서버 쪽 변경, 앱을 다시 열면 보임)
  2. AI: 처음 쓸 때 동의 창(보내는 것·받는 곳·동의), 거부하면 전송 없음. 처리방침 주소
  3. 연령 등급 설문 고침
  4. Sign in with Apple 은 앱에서 뺐음(회사 계정 전용 앱)
  5. 심사용 계정 아이디·비밀번호와 확인 순서
- 다시 내는 일은 대표 승인 뒤 로컬이 합니다.

## 6. 대표가 정할 것

1. 아이폰·아이패드 앱에서 **소셜 로그인(Apple 포함)을 모두 빼고 이메일 로그인만** 두어도 되는지(추천).
2. **AI 동의 창**을 모든 사용자에게 한 번 띄워도 되는지, 다짐의 '회사 자료 AI 처리'는 켜진 채 옮겨도 되는지.
3. 받는 곳 표기에 넣을 업체(운영에 실제로 연결된 곳만 적습니다 — 로컬 확인 뒤 확정).
