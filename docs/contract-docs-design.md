# 계약서 보관·만료일 관리 — 설계 메모

작성 2026-11-19 · 클라우드. 대표 11/19 "계약서를 업로드하고 만료일자에 따른 계약서 관리 기능을 구현하고자 한다". **아직 구현하지 않았습니다 — 순서·범위를 대표가 정한 뒤 시작합니다(지금 순서: 점검 먼저).**

## 1. 한 장 요약

- 지금 있는 '전자계약'(/contracts)은 **서명 받는 도구**입니다. 거기의 '만료'는 서명 기한이지 계약 기간이 아닙니다. 거래처·고객과 맺은 계약서를 보관하고 **계약 만료일로 챙기는 기능은 없습니다.**
- 새 표 2개 + 메뉴 권한 1개 + 화면 1개(목록·등록·상세) + 정기 알림 1개로 얹을 수 있습니다. **기존 표는 바꾸지 않습니다**(다짐 화면·자료 영향 없음).
- 파일은 자료실의 기밀 폴더에 넣습니다 → 회사별 분리, 기밀 열람 기록, 저장공간 한도 계산, 글자 찾기가 이미 됩니다.
- 알림은 지금 있는 '날짜 n일 전 한 번 알림' 틀을 그대로 씁니다.
- 작업량: 1단계 2~3일, 2단계(선택) 1~2일.

## 2. 이름 — 겹치지 않게

이미 쓰는 이름: 표 `contracts`·`contract_*`(전자계약), 주소 `/contracts`·`/api/contracts`, 영업의 `/s/sales/contracts`(계약만료·재입찰 화면)와 영업 계약 기록(`kind='contracts'`).

| 무엇 | 새 이름(안) |
|---|---|
| 메뉴 | **계약 관리** (관리 묶음, '전자계약' 바로 아래) |
| 주소 | `/agreements` · API `/api/agreements` |
| 표 | `agreements`(계약 한 건) · `agreement_terms`(기간 이력 — 갱신할 때마다 한 줄) |
| 권한 키 | `agreements` (없음 / 보기 / 편집) |
| 알림 종류 | `agreement_expiry` |
| 자료실 폴더 | `계약서`(기밀) · 출처 표시 `agreement` |

화면 글은 범용 낱말만 씁니다(상대방·계약 종류·담당자 — 다짐 전용 낱말 없음, 금칙어 검사 대상).

## 3. 자료 구조

**agreements** — 회사(tenant) 칸 필수, 다른 회사 것은 404
- 계약명 · 상대방(글자 + 선택: 연락처/영업 거래처 연결) · 계약 종류(용역·임대·구매·유지보수·기타 — 회사가 고침) · 금액(선택) · 담당자 · 소속(선택) · 메모
- 지금 기간: 시작일 · 만료일 · 자동 연장 여부 · 해지 통보 기한(만료 n일 전, 선택)
- 상태: 진행 중 / 만료 임박 / 만료 / 종료(해지) — 진행 중·임박·만료는 날짜로 계산, 종료만 사람이 정함
- 지금 계약서 파일(자료실 파일 연결) · 알림 보낸 단계 기록 · 만든 사람·시각

**agreement_terms** — 갱신 이력
- 계약 · 차수 · 시작일 · 만료일 · 금액 · 계약서 파일 · 메모 · 등록한 사람·시각

## 4. 기능

1. **등록**: 파일(PDF·사진, 50MB 까지) 올리기 + 위 칸 입력. 파일 없이도 등록 가능(나중에 붙임).
2. **목록**: 만료 임박순 기본. 상태·상대방·종류·담당자 거름, 찾기. 맨 위에 "30일 안 만료 n건 · 90일 안 n건". 엑셀 내려받기.
3. **알림**: 만료 **90·60·30·7일 전**(회사가 날짜 수를 고침) 담당자 + 회사 대표에게 알림함·푸시. 같은 단계는 한 번만, 만료일을 고치면 다시 셈. 늦게 등록해도 가장 가까운 단계 하나만.
   - 선택(기본 켬): 첫 단계에 '[계약 갱신 검토] ○○' 업무 1건을 담당자에게 만듦.
   - 자동 연장 계약은 문구가 달라짐: "자동 연장 예정 — 해지하려면 ○월 ○일까지 통보".
4. **갱신**: [갱신 등록] → 새 기간·새 파일을 잇고 이전 기간은 이력으로. [종료(해지)]는 사유와 함께.
5. **홈 카드**: 권한 있는 사람에게 "만료 임박 계약 n건".
6. **권한**: 기본값 — 대표·관리자: 편집 / 현장 관리자: 없음 / 직원: 없음(대표가 권한 표에서 바꿈). 파일은 이 권한이 있는 사람만 열고, 열람은 기밀 열람 기록에 남음.

## 5. 지금 있는 기능과 잇기

| 있는 것 | 이번(1단계) | 나중(2단계) |
|---|---|---|
| 전자계약(서명) | 잇지 않음 | 서명이 끝난 계약서에 [계약 관리에 등록] — 파일을 그대로 가져옴 |
| 영업 › 제안·계약의 계약 기록(시작·종료일, 종료 120일 전 '재계약 준비' 업무) | 잇지 않음. **영업 계약은 '우리가 따낸 계약', 계약 관리는 '보관하는 모든 계약서'**로 따로 둠 | 영업 계약에서 [계약서 올리기] → 같은 건으로 연결하고, 연결된 건은 알림을 한쪽에서만 보냄(중복 방지) |
| 올린 PDF 에서 만료일·상대방 읽기(AI) | 없음 | [AI 로 채우기] 단추 — 회사 AI 한도 사용, **AI 동의(iOS 반려 4번 대응)가 먼저 들어가야 함** |

## 6. 단계와 작업량

| 단계 | 내용 | 작업량 |
|---|---|---|
| 1 | 표 2개(마이그레이션 추가형) · 등록·목록·상세·갱신·종료 · 자료실 기밀 폴더 저장 · 권한 키 · 만료 알림(+갱신 검토 업무) · 홈 카드 · 엑셀 · 시험(다른 회사 404, 알림 단계·중복 없음, 권한) | 2~3일 |
| 2(선택) | AI 로 채우기 · 전자계약 완료본 가져오기 · 영업 계약 연결 | 1~2일 |

완료 기준: 권한·회사 분리 시험, 금칙어 검사 통과, 휴대폰 폭 확인, 운영 반영 뒤 로컬 확인.

## 7. 대표가 정할 것

1. **메뉴 위치**: 관리 묶음에 '계약 관리'를 따로 둠(추천) / '전자계약' 화면 안의 탭.
2. **알림 받는 사람**: 담당자 + 대표(추천) / 담당자만.
3. **알림 날짜 기본값**: 90·60·30·7일 전(추천).
4. **자동 연장 계약**: 표시와 문구만 다르게(추천 — 기간은 사람이 [갱신 등록]) / 만료일이 지나면 같은 길이로 자동으로 늘림.
5. **영업 계약과 잇기**: 2단계로 미룸(추천) / 1단계에 같이.
6. **순서**: 점검 다음(지금 결정) — iOS 반려 대응은 그보다 먼저 필요.
